# 2.1 进程与线程

## 2.1.1进程的概念

我们知道，程序主要是存放在磁盘中的指令和数据，为了执行程序，需要将程序的指令和数据放入内存，并为它分配CPU和堆栈等资源支持它运行。

所谓<span style="color: #e03e3e;">进程</span>，就是一个正在运行的程序某一时刻的<span style="color: #e03e3e;">**所有状态**</span><span style="color: #e03e3e;">信息</span>，它包括了

> 💡 

> - 内存空间:<span style="color: #0b6e99;">程序代码</span>，<span style="color: #0b6e99;">程序处理的数据</span>（包括全局变量）和<span style="color: #0b6e99;">栈</span>（包括临时数据，如函数参数、返回地址和局部变量）、<span style="color: #0b6e99;">堆</span>(进程运行时动态分配的内存)等
>
> - CPU内部状态信息:<span style="color: #e03e3e;">一组通用寄存器的当前值</span>，程序计数器PC，SP（堆栈指针）
>
> - 进程占用的其他系统资源:打开文件、已分配内存、设备等
>
> 进程与程序的联系

> - 进程是操作系统处于执行状态程序的抽象
>   - 程序 = 文件（静态的可执行文件）
>   - 进程 = 执行中的程序 = 程序 + 执行状态
>
> - 同一个程序的多次执行和过程对应为不同的进程（例如同一用户可以调用 web 浏览器的多个副本，但是每个都是单独进程，虽然文本段相同，都是数据、堆及堆栈段却不同。进程在运行时也经常会生成许多进程。）
>
为了使参与并发执行的每个程序都能独立地运行，必须为之配置一个专门的数据结构，即**进程控制块(** Process  Control  Block, <span style="color: #6940a5;">PCB</span> **)**，系统利用<span style="color: #6940a5;">PCB</span>来描述进程的基本情况和运行状况，从而控制和管理进程。

<span style="color: #6940a5;">**进程实体**</span>(进程映像):由**程序段**、**相关数据段**和<span style="color: #6940a5;">**PCB**</span>三部分构成。创建进程实质上是创建<span style="color: #6940a5;">PCB</span>，而撤销进程实质上是撤销进程的<span style="color: #6940a5;">PCB</span>。

引入<span style="color: #6940a5;">进程实体</span>的概念后，我们可以把进程定义为:**进程是**<span style="color: #6940a5;">**进程实体**</span>**的运行过程，是系统进行**<span style="color: #0f7b6c;">**资源分配和调度的一个独立单位**</span>**。**

## 2.1.2 进程的组织

1.**进程控制块**<span style="color: #6940a5;">**PCB**</span>**（最核心的）**

- **PCB是进程存在的**<span style="color: #0f7b6c;">**唯一标志**</span>，进程创建后该结构**常驻内存**，并在进程结束时删除,操作系统通过<span style="color: #6940a5;">PCB</span>来管理和控制进程,因此**管理和控制所需的参数一定是放在**<span style="color: #6940a5;">**PCB**</span>**中**的。
- 包含的内容
PCB还包括程序计数器PC（一般放在里面的context上下文信息结构体之中）、CPU调度信息(包括进程优先级、调度队列的指针和其他调度参数)、**内存管理信息(可以包括基地址和界限寄存器的值)等等**。

> 进程标识符是对进程的唯一标识，类似于进程的编号，每个进程在创建时，都会产生对应的 pid 并装入其 PCB。
pid 是由操作系统分配的有限资源，即可分配的 pid 个数往往是固定的，该个数对应了系统中允许同时存在的最大进程数。若进程创建无法申请到 pid，则该进程的创建会失败。

  ```c
//进程状态枚举
enum procstate {
  UNUSED,     // 进程槽位未使用（初始状态）
  USED,       // 进程已分配，但未初始化完成（过渡状态）
  SLEEPING,   // 进程在休眠（等待事件或资源）
  RUNNABLE,   // 进程可运行（在就绪队列中等待调度）
  RUNNING,    // 进程正在运行（占用 CPU）
  ZOMBIE      // 进程已终止，等待父进程回收（僵尸状态）
};
//内核态下进程上下文
struct context {
  uint64 ra;   // 返回地址（指令指针），即PC程序计数器
  uint64 sp;   // 栈指针
  uint64 s0;   // callee-saved 寄存器 s0-s11
  uint64 s1;
  ...
};
// xv6 源码片段（RISC-V 版本）:
struct proc {
    struct spinlock lock;       // 进程锁（用于同步）
    enum procstate state;       // 进程状态（UNUSED, SLEEPING, RUNNABLE 等）
    int pid;                    // 进程 ID
    struct proc *parent;        // 父进程指针
    void *chan;                 // 休眠等待的通道（用于同步）
    int killed;                 // 是否被终止
    uint64 kstack;             // 内核栈地址
    uint64 sz;                 // 进程内存大小，和下面的页表指针一起可以找到页表，这就是该进程的地址空间
    pagetable_t pagetable;     // 页表指针（RISC-V 页表）
    struct trapframe *trapframe; // 陷阱帧（保存用户态寄存器状态,用于从内核态返回到用户态）
    struct context context;     // 内核态上下文（用于进程上下文切换）
    struct file *ofile[NOFILE]; // 打开的文件表
    // ... 其他字段（当前目录、进程名等）
};
  ```

1. **程序段**:存放二进制代码、常量、全局赋值变量，<span style="color: #e03e3e;">可被多进程共享</span>，即多个进程可以运行同一个程序。
1. **数据段**:对应进程原始数据或处理的中间数据或最终结果；
  - 存放堆:动态分配存储区 malloc 
  - 栈:临时使用的变量(函数调用的参数、函数的局部变量)
  - 程序是通过堆栈的基地址和偏移量来访问其中的数据

<details><summary>虚拟地址空间</summary>

- <span style="color: #d9730d;">**保留区**</span>:位于虚拟地址空间的最底部，未赋予物理地址。任何对它的引用都是非法的，程序中的<span style="color: #e03e3e;">空指针（NULL）</span>指向的就是这块内存地址。
- <span style="color: #d9730d;">**.text段**</span>:<span style="color: #d9730d;">代码段</span>也称正文段或文本段，用于<span style="color: #0b6e99;">存放程序的执行代码</span>（即 CPU 执行的机器指令）。代码段通常是<span style="color: #e03e3e;">只读</span>的，这是对执行代码的一种保护机制。
- <span style="color: #d9730d;">**.data段**</span>:<span style="color: #d9730d;">数据段</span>用于<span style="color: #0b6e99;">存放</span>程序中<span style="color: #e03e3e;">已初始化且初值不为 0</span> 的<span style="color: #d9730d;">全局变量和静态变量</span>。数据段属于<span style="color: #0b6e99;">静态内存分配</span>（静态存储区），可读可写。
- <span style="color: #d9730d;">**.bss段**</span>:<span style="color: #0b6e99;">存放</span><span style="color: #e03e3e;">未初始化以及初始为 0</span> 的<span style="color: #d9730d;">全局变量和静态变量</span>，操作系统会将这些未初始化的变量<span style="color: #0b6e99;">初始化为 0</span>。
- <span style="color: #d9730d;">**堆（heap）**</span>:用于<span style="color: #0b6e99;">存放进程运行时动态分配的内存</span>。
  - 堆中内容是<span style="color: #e03e3e;">匿名</span>的，不能按名字直接访问，只能通过<span style="color: #e03e3e;">指针</span>间接访问。
  - 堆<span style="color: #0b6e99;">向高地址扩展</span>（即"向上生长"），是<span style="color: #e03e3e;">不连续</span>的内存区域。这是由于系统用<span style="color: #d9730d;">链表</span>来<span style="color: #0b6e99;">存储空闲内存地址</span>，自然不连续，而链表从低地址向高地址遍历。
- <span style="color: #d9730d;">**内存映射区（mmap）**</span>:作为内存映射区<span style="color: #0b6e99;">加载磁盘文件</span>，或者<span style="color: #0b6e99;">加载</span>程序运作过程中需要调用的<span style="color: #d9730d;">动态库</span>。
- <span style="color: #d9730d;">**栈（stack）**</span>:<span style="color: #0b6e99;">存储</span>函数内部声明的<span style="color: #d9730d;">非静态局部变量</span>、<span style="color: #e03e3e;">函数参数</span>、<span style="color: #e03e3e;">函数返回地址</span>等信息，栈内存由编译器自动分配释放。栈和堆相反，地址<span style="color: #0b6e99;">向下生长</span>，分配的内存是<span style="color: #e03e3e;">连续</span>的。
- <span style="color: #d9730d;">**命令行参数**</span>:<span style="color: #0b6e99;">存储</span>进程执行时传递给 `main()` 函数的参数，`argc`、`argv[]`、`env[]`。
- <span style="color: #d9730d;">**环境变量**</span>:<span style="color: #0b6e99;">存储</span>与进程相关的环境变量，比如:<span style="color: #e03e3e;">工作路径</span>、<span style="color: #e03e3e;">进程所有者</span>等信息。

PCB组织形式:（为了方便进程的调度和管理，将各进程的PCB用适当的方法组织起来）

1. **线性表:**将系统中的所有PCB都组织在一张线性表中，将这张表的起始地址存放在内存的特定位置或存放在专用寄存器里。
1. **链表队列**:进程的不同状态对应着PCB挂在不同的队列(阻塞队列、就绪队列)
1. **索引表:**<span style="color: #e03e3e;">进程的不同状态对应着PCB挂在不同的索引表内(阻塞索引表、就绪索引表)。</span>
进程的封闭性: 进程的执行结果只取决于进程的本身，而不受外界(推进速度)影响，无论该进程是一鼓作气执行完，还是走走停停，都不影响执行的结果，<span style="color: #e03e3e;">若进程失去了封闭性，那么它的推进速度（是否被阻塞）便会影响它的执行结果。</span>

## 2.1.3 进程的状态

1. <span style="color: #6940a5;">**运行态 (running)**</span>:在单处理机下只有<span style="color: #0f7b6c;">一个</span>进程处于执行态；多处理机下可有<span style="color: #0f7b6c;">多个</span>进程同时处于执行态。
1. <span style="color: #6940a5;">**就绪态 (ready)**</span>:已获得除处理机外的<span style="color: #0f7b6c;">全部</span>所需资源，一旦获得 CPU 即可立刻执行。
1. <span style="color: #6940a5;">**阻塞态 / 等待态 (waiting)**</span>:等待<span style="color: #6940a5;">非处理机资源</span>或 I/O 完成；即便 CPU 空闲也<span style="color: #e03e3e;">不能</span>运行。
  > 说明:就绪态的唯一原因是<span style="color: #0f7b6c;">尚未分配 CPU</span>；阻塞态原因<span style="color: #6940a5;">多样</span>，因此按原因分别挂到<span style="color: #6940a5;">不同的等待队列</span>；就绪队列通常<span style="color: #0f7b6c;">只有一个</span>。

1. <span style="color: #6940a5;">**创建态**</span>:已分配 PCB，正在分配除 CPU 外的其他资源。
  > <span style="color: #e03e3e;">除了第一个进程，操作系统中的进程均是由另一个进程创建的</span>，创建进程的进程和被创建的进程互为<span style="color: #e03e3e;">父进程和子进程</span>。父进程在创建子进程的过程中会为子进程申请 pid 和 PCB，并申请其它子进程所需要的资源，创建过程中的进程处于创建态。

1. <span style="color: #6940a5;">**退出态**</span>:进程运行终止，OS 正在回收其占用的资源与<span style="color: #6940a5;">PCB</span>。
![](https://cos.izumichan16.cn/408note/OS/TKE3DZHvgVA3Y5Vo/1745499930114-a1dee34c-0859-410e-8e3e-f6f1c3f9ba23-363294.png)

<span style="color: #6940a5;">【状态转换要点】</span>

- <span style="color: #6940a5;">运行 → 阻塞</span>:进程的<span style="color: #0f7b6c;">主动</span>行为（系统调用等待事件/资源）。
- <span style="color: #6940a5;">阻塞 → 就绪</span>:等待的事件到来或资源就绪，属<span style="color: #0f7b6c;">被动</span>行为。
- <span style="color: #e03e3e;">重要限制</span>:<span style="color: #0f7b6c;">**不能**</span>由<span style="color: #6940a5;">阻塞态</span>直接转<span style="color: #6940a5;">运行态</span>，也<span style="color: #0f7b6c;">**不能**</span>由<span style="color: #6940a5;">就绪态</span>直接转<span style="color: #6940a5;">阻塞态</span>。
  - 理由:进入阻塞态是<span style="color: #0f7b6c;">主动</span>请求，必须在<span style="color: #6940a5;">运行</span>时发起；离开阻塞必须先<span style="color: #6940a5;">就绪</span>再由调度获得 CPU。
> <span style="color: #6940a5;">就绪 vs 阻塞为何必须区分？</span>

> - 分时系统中时间片很短，进程频繁<span style="color: #e03e3e;">运行↔就绪</span>；而 I/O 事件/外设分配较慢，<span style="color: #6940a5;">阻塞</span>次数/时间分布特性不同。
>
> - 这两种状态在生命周期中语义完全不同，故需分开管理以提升<span style="color: #0f7b6c;">调度效率</span>与<span style="color: #0f7b6c;">资源利用率</span>。
>
<span style="color: #6940a5;">【扩展:挂起态】</span>

当内存紧张时，OS 可能将短期内不运行的进程换出到外存，称为<span style="color: #6940a5;">挂起</span>；重新调入称为<span style="color: #6940a5;">激活</span>。

- <span style="color: #6940a5;">阻塞挂起</span>:在外存且等待事件。
- <span style="color: #6940a5;">就绪挂起</span>:在外存，只要调入内存即可运行。
![](https://cos.izumichan16.cn/408note/OS/TKE3DZHvgVA3Y5Vo/1745499539037-9111e874-42a1-4a7d-b398-6120bf4c99d1-691973.png)

<span style="color: #6940a5;">【挂起相关转换】</span>

- <span style="color: #6940a5;">运行 → 就绪挂起</span>:例如用户手动挂起前台程序。
- <span style="color: #6940a5;">阻塞 → 阻塞挂起</span>:内存紧张，优先换出当前<span style="color: #6940a5;">阻塞</span>进程。
- <span style="color: #6940a5;">阻塞挂起 → 就绪挂起</span>:<span style="color: #e03e3e;">等待事件已到达，但仍在外存。</span>
- <span style="color: #6940a5;">就绪挂起 → 就绪</span>:被调入内存，等待 CPU 调度。
- <span style="color: #6940a5;">就绪 → 就绪挂起</span>:必要时为高优先级或更紧迫的进程腾挪内存。
> 💡 <span style="color: #6940a5;">小结</span>

> - <span style="color: #0f7b6c;">就绪</span>:差 CPU，<span style="color: #e03e3e;">时间片到期</span>
>
> - <span style="color: #0f7b6c;">阻塞</span>:差事件/资源
>
> - <span style="color: #0f7b6c;">就绪挂起/阻塞挂起</span>:在外存，需先调入内存
>
> - <span style="color: #e03e3e;">禁止的直接转换</span>:阻塞→运行，就绪→阻塞
>

## 2.1.4 进程控制

主要功能:对系统中的所有进程实现有效的管理,具有创建新进程、撤销已有进程、实现进程状态切换等功能．

### 2.1.4.1 进程的创建

<span style="color: #6940a5;">【任务与触发】</span>

- 触发来源:<span style="color: #6940a5;">终端登录</span>、<span style="color: #6940a5;">作业调度</span>、<span style="color: #6940a5;">系统服务</span>、<span style="color: #6940a5;">用户程序请求</span>
<span style="color: #6940a5;">【创建流程】</span>

1. 分配<span style="color: #6940a5;">PID</span>并申请<span style="color: #6940a5;">空白 PCB</span>（<span style="color: #0f7b6c;">PCB 是有限资源，失败则创建失败或进入创建态等待</span>）。
1. 分配运行所需资源:<span style="color: #6940a5;">内存</span>、<span style="color: #6940a5;">文件</span>、<span style="color: #6940a5;">I/O 设备</span>、<span style="color: #6940a5;">CPU 时间</span>（<span style="color: #0f7b6c;">体现在 PCB 字段</span>）。
  - 若资源不足（如内存），进程处于<span style="color: #6940a5;">创建态</span>等待；<span style="color: #e03e3e;">父进程可能被阻塞</span>。
1. 初始化<span style="color: #6940a5;">PCB</span>:标志信息、处理机状态信息、控制信息、<span style="color: #6940a5;">优先级</span>等。
1. 插入<span style="color: #6940a5;">就绪队列</span>，等待调度。
> 💡 <span style="color: #6940a5;">结论速记</span>

> - <span style="color: #0f7b6c;">创建=PID+PCB+资源+入队</span>
>
> - <span style="color: #6940a5;">PCB</span>是进程的<span style="color: #0f7b6c;">唯一标志</span>；<span style="color: #e03e3e;">PCB 数量有限</span>
>
<span style="color: #6940a5;">【代码视角:Linux】</span>

- 入口:<span style="color: #6940a5;">`kernel_clone()`</span>` → `<span style="color: #6940a5;">`copy_process()`</span>` → `<span style="color: #6940a5;">`wake_up_new_task()`</span>
- 关键:
  - <span style="color: #6940a5;">`copy_mm()`</span> 使用 <span style="color: #6940a5;">COW</span>（写时复制）共享父子地址空间的物理页，写入时复制。
  - <span style="color: #6940a5;">`wake_up_new_task()`</span> 将新任务放入就绪结构，并<span style="color: #0f7b6c;">必要时触发抢占</span>。
<span style="color: #6940a5;">【代码视角:xv6】</span>

- 入口:<span style="color: #6940a5;">`sys_fork() → fork()`</span>
- 关键:
  - <span style="color: #6940a5;">`allocproc()`</span> 分配<span style="color: #6940a5;">PCB</span>与内核栈，设置<span style="color: #6940a5;">陷阱帧</span>与<span style="color: #6940a5;">上下文</span>。
  - <span style="color: #6940a5;">`uvmcopy()`</span> 直接复制父进程用户空间（无 COW），<span style="color: #e03e3e;">开销更大</span>。
<span style="color: #6940a5;">【易考点】</span>

- 必做项:<span style="color: #0f7b6c;">申请空白 PCB、初始化 PCB</span>；<span style="color: #e03e3e;">不必</span>设置为<span style="color: #6940a5;">执行态</span>（先入就绪）。
- <span style="color: #6940a5;">父子</span>互为创建关系；<span style="color: #6940a5;">PID</span> 唯一标识进程。
### 2.1.4.2 进程的终止

引起进程终止的事件主要有:

① <span style="color: #0f7b6c;">正常结束</span>，表示进程的任务已完成并准备退出运行。

② <span style="color: #dfab01;">异常结束</span>，表示进程在运行时，发生了某种异常事件，使程序无法继续运行，如<span style="color: #e03e3e;">存储区越界</span>、<span style="color: #e03e3e;">保护错</span>、<span style="color: #e03e3e;">非法指令</span>、<span style="color: #e03e3e;">特权指令错</span>、<span style="color: #e03e3e;">运行超时</span>、<span style="color: #e03e3e;">算术运算错</span>、<span style="color: #e03e3e;">I/O 故障</span>等。

③ <span style="color: #0b6e99;">外界干预</span>，指进程因外界的请求而终止运行，如<span style="color: #6940a5;">操作员或操作系统干预</span>、<span style="color: #6940a5;">父进程请求</span>和<span style="color: #6940a5;">父进程终止</span>。

操作系统终止进程的过程如下:

1. 根据被终止进程的<span style="color: #0b6e99;">标识符</span>，检索出该进程的 <span style="color: #6940a5;">PCB</span>，从中读出该进程的状态。
1. 若被终止进程处于<span style="color: #0f7b6c;">运行状态</span>，立即终止该进程的执行，将<span style="color: #0b6e99;">处理机资源</span>分配给其他进程。
1. 将该进程所拥有的<span style="color: #0b6e99;">全部资源</span>，或归还给其<span style="color: #6940a5;">父进程</span>，或归还给<span style="color: #6940a5;">操作系统</span>。
1. 将该 <span style="color: #6940a5;">PCB</span> 从所在<span style="color: #0b6e99;">队列(链表)</span>中删除。
注意，不同操作系统的实现对进程终止的处理不完全相同，以上操作属于各OS共有的操作；（例如<span style="color: #0b6e99;">windows操作系统</span>在进程终止时会终止其所有子进程，而<span style="color: #0b6e99;">类unix操作系统</span>则不会）

<details><summary>**Linux 进程终止的核心源码**</summary>

Linux 进程终止通过 `**exit()**` 系统调用触发，最终由内核函数 `**do_exit()**` 处理。以下是关键源码和步骤:

(1) 入口函数:`**do_exit()**`

```c
// kernel/exit.c
void __noreturn do_exit(long code) {
    struct task_struct *tsk = current;

    // 1. 标记进程为僵尸状态（EXIT_ZOMBIE）
    tsk->exit_state = EXIT_ZOMBIE;

    // 2. 释放资源
    exit_mm(tsk);        // 释放内存管理结构（mm_struct）
    exit_files(tsk);     // 关闭打开的文件描述符
    exit_fs(tsk);        // 释放文件系统资源
    exit_thread(tsk);    // 清理线程上下文
    //驱动层负责设备资源释放

    // 3. 通知父进程（通过信号 SIGCHLD）
    exit_notify(tsk);

    // 4. 调度到其他进程（永不返回）
    schedule();
    panic("do_exit returned");
}
```

(2) **父进程通知与僵尸进程处理**

`**exit_notify()**`通知父进程子进程已终止，若父进程已退出，则交由 `**init**` 进程（PID 1）接管:（由此可见父进程终止，不一定会终止所有的子进程）

```c
// kernel/exit.c
static void exit_notify(struct task_struct *tsk) {
    struct task_struct*parent = tsk->real_parent;
    if (thread_group_empty(tsk)) {
        // 父进程未等待子进程，则子进程成为僵尸进程
        tsk->exit_signal = SIGCHLD;
        list_add_tail(&tsk->ptrace_entry, &parent->ptraced);
    } else {
        // 父进程已终止，子进程由 init 接管
        reparent_to_init(tsk);
    }
}
```

</details>

<details><summary>**xv6 进程终止的核心源码**</summary>

xv6 的进程终止通过 `**exit()**` 系统调用触发，核心逻辑在 `**exit()**` 函数中实现。

(1) 入口函数:`exit()`

```c
void exit(int status) {
    struct proc *p = myproc();

    // 1. 关闭所有打开的文件
    for (int fd = 0; fd < NOFILE; fd++) {
        if (p->ofile[fd]) {
            fileclose(p->ofile[fd]);
            p->ofile[fd] = 0;
        }
    }

    // 2. 释放用户内存（页表和物理页）
    uvmunmap(p->pagetable, 0, p->sz / PGSIZE, 1);
    p->sz = 0;

    // 3. 通知父进程
    acquire(&p->parent->lock);
    if (p->parent->state == SLEEPING && p->parent->chan == p) {
        wakeup(p->parent); // 唤醒等待的父进程
    }
    release(&p->parent->lock);

    // 4. 标记进程为僵尸状态（ZOMBIE）
    acquire(&p->lock);
    p->state = ZOMBIE;
    p->exit_status = status;
    release(&p->lock);

    // 5. 调度到其他进程（永不返回）
    sched();
    panic("exit returned");
}
```

(2) **关键资源释放逻辑**

**释放内存（**`**uvmunmap**`**）**遍历进程页表，释放所有用户态物理页:

```c
// kernel/vm.c
void uvmunmap(pagetable_t pagetable, uint64 va, uint64 size, int free_pages) {
    for (uint64 a = va; a < va + size; a += PGSIZE) {
        pte_t *pte = walk(pagetable, a, 0);
        if (pte && (*pte & PTE_V)) {
            uint64 pa = PTE2PA(*pte);
            kfree((void*)pa); // 释放物理页
        }
    }
}
```

**父进程唤醒**

若父进程正在等待子进程退出（如调用 `**wait()**`），通过 `**wakeup()**` 唤醒父进程:

```c
// kernel/proc.c
int wait(uint64 addr) {
    for (;;) {
        // 查找僵尸子进程
        for (struct proc *np = proc; np < &proc[NPROC]; np++) {
            if (np->parent == p && np->state == ZOMBIE) {
                // 复制子进程退出状态到用户空间
                copyout(p->pagetable, addr, (char*)&np->exit_status, sizeof(int));
                freeproc(np); // 释放子进程资源
                return np->pid;
            }
        }
        sleep(p, &p->lock); // 等待子进程退出
    }
}
```

(3) 僵尸进程的最终清理

父进程调用 `**wait()**` 时，回收僵尸进程的资源（如 `**freeproc()**`）:

```c
// kernel/proc.c
static void freeproc(struct proc *p) {
    if (p->trapframe) kfree((void*)p->trapframe); // 释放陷阱帧
    p->trapframe = 0;
    if (p->pagetable) proc_freepagetable(p->pagetable, p->sz); // 释放页表
    p->state = UNUSED; // 标记进程槽位为空闲
}
```

<details><summary>**僵尸进程和孤儿进程(扩展了解)**</summary>

1. <span style="color: #0b6e99;">**僵尸进程**</span>（Zombie Process）
  - 定义:僵尸进程是指**已经终止运行但尚未被父进程回收资源的进程**。其<span style="color: #6940a5;">进程描述符（PCB）</span>仍保留在系统进程表中，以便父进程查询其终止状态。
  - 产生原因:父进程创建子进程后，子进程执行完毕并通过<span style="color: #d9730d;">`exit()`</span>终止。父进程未调用<span style="color: #d9730d;">`wait()`</span>或<span style="color: #d9730d;">`waitpid()`</span>来获取子进程的终止状态。
  - 特点
    - 占用进程表资源:僵尸进程的<span style="color: #0f7b6c;">PID</span>和退出状态信息仍占用系统进程表。
    - 无法被终止:僵尸进程已经死亡，无法通过信号（如<span style="color: #d9730d;">`SIGKILL`</span>）杀死。
    - 长期存在:如果父进程一直不回收，僵尸进程会持续存在，可能导致进程表耗尽。
  - 解决方法
    - 父进程调用<span style="color: #d9730d;">`wait()`</span>或<span style="color: #d9730d;">`waitpid()`</span>:主动回收子进程资源。
    - 忽略<span style="color: #d9730d;">`SIGCHLD`</span>信号:通过<span style="color: #d9730d;">`signal(SIGCHLD, SIG_IGN)`</span>通知内核无需保留子进程状态。
    - 父进程终止:当父进程终止时，僵尸进程会被<span style="color: #d9730d;">`init`</span>进程接管并清理。
1. <span style="color: #0b6e99;">**孤儿进程**</span>（Orphan Process）
  - 定义:孤儿进程是指<span style="color: #6940a5;">父进程提前终止</span>，导致子进程被<span style="color: #d9730d;">`init`</span>进程（PID为1）接管。操作系统自动处理孤儿进程的资源回收。
  - 产生原因:父进程在子进程终止前意外退出（如崩溃或被终止）。
  - 特点:由<span style="color: #d9730d;">`init`</span>进程接管:操作系统将孤儿进程的父进程设为<span style="color: #d9730d;">`init`</span>。自动回收:当孤儿进程终止时，<span style="color: #d9730d;">`init`</span>进程会调用<span style="color: #d9730d;">`wait()`</span>回收其资源。无资源泄漏:不会长期占用进程表。
  - 处理机制:操作系统自动将孤儿进程的父进程设置为<span style="color: #d9730d;">`init`</span>。<span style="color: #d9730d;">`init`</span>进程周期性调用<span style="color: #d9730d;">`wait()`</span>回收终止的子进程。
总结:

僵尸进程可能导致<span style="color: #6940a5;">进程表资源耗尽</span>，需及时处理。孤儿进程由系统<span style="color: #6940a5;">自动管理</span>，无需干预。

僵尸进程:父进程未及时回收的子进程残留，需<span style="color: #6940a5;">手动处理</span>。

孤儿进程:父进程意外终止后的子进程，由<span style="color: #d9730d;">`init`</span>自动接管。

</details>

### 父进程与子进程

由上面学习的进程创建我们可知，若P1进程创建了P2进程，则P1是P2的父进程，P2是P1的子进程。

> 💡 父进程和子进程共享部分全局资源

> 某些操作系统全局资源是存在父子继承的，例如后面会学到的文件、管道、设备等，对这些特定的全局资源来说，**子进程通常会继承父进程对它们的访问权限。**
>
>
但是注意<span style="color: #e03e3e;">**父子进程是两个不同的进程，因此其pid和PCB都不同，也不会共享地址空间**</span>，我们知道进程具有独立性，是一个能独立运行、独立获得资源和独立接受调度的基本单位，要是可以共享地址空间，父进程进程执行的过程中发生了中断，但是在它由于中断而被暂停执行的过程中，其子进程还在执行，并且更改了内存里的部分信息，这就破坏了父进程的现场，因此二者不会共享地址空间。


从进程创建的源码中我们可以看到:

1. 在<span style="color: #0b6e99;">Linux操作系统</span>中，当父进程创建子进程时，使用<span style="color: #d9730d;">fork()</span>函数，子进程会复制父进程的<span style="color: #6940a5;">地址空间</span>，即虚拟地址空间的副本，包括代码段、数据段、堆栈等完全相同（之后可通过执行`exec()`改变）。通常会采用<span style="color: #e03e3e;">**写时复制（Copy-On-Write，COW）技术**</span>，即<span style="color: #0b6e99;">fork之后，父子进程的虚拟地址空间映射到相同的物理内存页</span>，但一旦任一进程试图修改某页，就会触发复制，生成该页的副本，使它们不再共享同一物理页。从虚拟地址空间角度看，初始时它们的地址空间内容相同，但各自独立，非共享。共享意味着一个进程修改数据后另一进程能看到变化，而fork后的子进程修改数据时会有自己的副本，因此虚拟地址空间实际上是独立的。
  ![](https://cos.izumichan16.cn/408note/OS/TKE3DZHvgVA3Y5Vo/1745422630974-52fe309c-d96b-4f61-819f-633dbe1e5305-760102.png)

1. 在<span style="color: #0b6e99;">xv6操作系统</span>中，父进程创建子进程时，将父进程的<span style="color: #6940a5;">虚拟地址空间</span>完整复制到子进程的地址空间中，包括:<span style="color: #d9730d;">代码段（Text）</span>、<span style="color: #d9730d;">数据段（Data）</span>、<span style="color: #d9730d;">堆（Heap）</span>和<span style="color: #d9730d;">栈（Stack）</span>。每个虚拟页对应的物理页会被<span style="color: #e03e3e;">逐页复制</span>（非共享），确保父子进程内存完全独立。
![](https://cos.izumichan16.cn/408note/OS/TKE3DZHvgVA3Y5Vo/1745423385820-88f1afce-2267-44d9-8366-eb5af6179b4d-882911.png)

> 💡 由以上两种操作系统创建进程的过程可知，父子进程在创建之初具有**相同且**<span style="color: #e03e3e;">**独立的地址空间**</span>。父进程和子进程可以共享相同的代码和数据，但又能保持各自的独立性，使得进程间的<span style="color: #0b6e99;">数据隔离</span>和<span style="color: #0b6e99;">安全性</span>得以保证。

### 2.1.4.3 进程的阻塞与唤醒

> 💡 正在执行的进程，由于期待的某些事件未发生，如请求<span style="color: #0b6e99;">系统资源</span>失败、等待某种操作的完成、新数据尚未到达或无新任务可做等，进程便通过调用<span style="color: #e03e3e;">阻塞原语(Block)</span>，使自己由<span style="color: #d9730d;">运行态</span>变为<span style="color: #d9730d;">阻塞态</span>。可见，<span style="color: #e03e3e;">阻塞是进程自身的一种主动行为</span>，也因此只有处于<span style="color: #d9730d;">运行态</span>的进程(获得CPU)，才可能将其转为<span style="color: #d9730d;">阻塞态</span>。阻塞原语的执行过程如下:

> 当被阻塞进程所期待的事件出现时，如它所期待的<span style="color: #0b6e99;">I/O操作已完成</span>或其所期待的数据已到达，由有关进程(比如，释放该I/O设备的进程，或提供数据的进程)调用<span style="color: #e03e3e;">唤醒原语(Wakeup)</span>，将等待该事件的进程唤醒。唤醒原语的执行过程如下:
>
> 1. 在该事件的<span style="color: #e03e3e;">等待队列</span>中找到相应进程的<span style="color: #6940a5;">PCB</span>。
> 1. 将其从<span style="color: #e03e3e;">等待队列</span>中移出，并置其状态为<span style="color: #d9730d;">就绪态</span>。
> 1. 把该<span style="color: #6940a5;">PCB</span>插入<span style="color: #e03e3e;">就绪队列</span>，等待<span style="color: #0b6e99;">调度程序</span>调度。
>
> **注意:**<span style="color: #e03e3e;">**阻塞操作**</span>**通常会与**<span style="color: #0b6e99;">**进程的调度和切换**</span>**操作成对出现**，进程如果在<span style="color: #0f7b6c;">用户态</span>下触发阻塞条件，也会经历类似于进程切换中的"<span style="color: #0f7b6c;">用户态-内核态-内核态-用户态</span>"的过程变化。
>
>
<details><summary>**Linux 进程阻塞与唤醒的核心源码**</summary>

Linux 通过 **等待队列（Wait Queue）** 和 **调度器状态切换** 实现进程的阻塞与唤醒。以下是关键源码和机制:

**(1) 阻塞进程**

当进程需要等待某个条件（如 I/O 完成、信号量释放）时，会**主动调用阻塞函数**。核心函数:`wait_event`（定义在 ）

```c
// kernel/sched/wait.c
void __sched wait_event(wait_queue_head_t wq, condition) {
    DEFINE_WAIT(__wait); // 定义等待队列条目
    for (;;) {
        prepare_to_wait(&wq, &__wait, TASK_UNINTERRUPTIBLE); // 标记进程为不可中断睡眠
        if (condition) // 检查条件是否满足
            break;
        schedule(); // 主动让出 CPU，触发调度
    }
    finish_wait(&wq, &__wait); // 从等待队列移除
}
```

关键步骤:

- **标记阻塞态**:将进程状态设为 `TASK_UNINTERRUPTIBLE`（不可中断睡眠）或 `TASK_INTERRUPTIBLE`（可中断睡眠）。
首先，**这两种状态均属于阻塞态**。

TASK_INTERRUPTIBLE（可中断睡眠）:进程等待事件时，可以响应信号（如`SIGKILL`、`SIGTERM`）。

若接收到信号，进程会被唤醒并处理信号（如终止或执行信号处理函数）。

- 典型场景:用户空间的系统调用（如`read()`等待输入、`sleep()`等待超时）。
TASK_UNINTERRUPTIBLE（不可中断睡眠）:进程等待事件时，不响应任何信号（包括强制终止信号`SIGKILL`）。

内核强制确保关键操作完成后再处理信号（保证操作的原子性），避免系统状态不一致。

- 典型场景:内核必须完成的关键操作（如磁盘I/O、硬件交互）。
- **加入等待队列**:通过 `prepare_to_wait` 将进程加入指定的等待队列。（**不同事件有不同的等待队列**）
- **调度切换**:调用 `schedule()` 触发调度器，切换到其他进程。
---

**(2) 唤醒进程**

当条件满足（如数据到达、资源可用）时，唤醒等待队列中的进程。核心函数:`wake_up`（定义在 ）

```c
// kernel/sched/wait.c
void wake_up(wait_queue_head_t *wq) {
    struct wait_queue_entry *curr, *next;
    list_for_each_entry_safe(curr, next, &wq->head, entry) {
        // 遍历等待队列，唤醒每个进程
        curr->func(curr, TASK_NORMAL, 0, NULL); // 调用默认唤醒函数
    }
}
```

关键步骤:

- 遍历等待队列:找到所有需要唤醒的进程。
- 修改进程状态:将进程状态设为 `TASK_RUNNING`（就绪态）
- 加入就绪队列:通过 `enqueue_task` 将进程加入调度队列，等待被调度。
### **Linux 中的等待队列使用**

```c
// 驱动中等待数据到达的示例
DECLARE_WAIT_QUEUE_HEAD(data_ready_queue); // 定义等待队列

// 阻塞:等待数据
wait_event(data_ready_queue, data_available);

// 唤醒:数据到达后
wake_up(&data_ready_queue);
```

> 一次完整的切换过程示例:进程 P0 响应时钟中断从用户态进入了内核态，其用户态上下文保存在了内核堆栈中。时钟中断会检查并更新当前进程 P0 的时间片，当发现该时间片用完时， 操作系统会将 P0 从运行态变更为就绪态，并通过进程调度从就绪队列中选择出就绪进程 P1 的 PCB，随后，操作系统将当前进程 P0 的上下文保存在 PCB0 中，并从 PCB1 中取出记录的 P1 上下文放入各寄存器中（包括地址空间和堆栈地址等），此时 P1 处于什么状态 呢？我们可以想象到，P1 在 PCB 中存入的上下文内容也类似于 P0 存入的内容，PCB1 中保存的上下文一定对应于 P1 上次刚刚发生切换时的状态，即处于某一次中断处理的内核态中。 此后，P1 会继续执行，处理完各种中断异常后从 P1 的内核堆栈中取出 P1 的用户态上下文， 中断返回 P1 的用户态，这便是从 P0 用户态切换到 P1 用户态的完整过程。

> 💡 **中断响应与进程切换的上下文切换区别**

> 1. 中断响应保存和恢复上下文是<span style="color: #0b6e99;">分开进行</span>的，分别位于<span style="color: #e03e3e;">中断响应</span>和<span style="color: #e03e3e;">中断返回</span>的过程中；而进程切换的上下文保存与恢复是<span style="color: #0b6e99;">连续进行</span>的（两个不同进程之间）。
>
> 1. 中断响应保存的上下文是<span style="color: #e03e3e;">中断前进程</span>执行的上下文，进程切换保存的是<span style="color: #e03e3e;">中断服务程序</span>正在执行过程中的上下文。进一步说，中断响应维护的上下文可能是<span style="color: #0b6e99;">用户上下文</span>（因为多重中断的存在），而进程切换维护的一定是<span style="color: #0b6e99;">内核态下的上下文</span>。
>
> 1. 中断响应<span style="color: #e03e3e;">不涉及地址空间切换</span>（仅切换了内核态以及由用户堆栈切换到内核堆栈，中断前后仍属于同一地址空间），**进程切换涉及**<span style="color: #e03e3e;">**地址空间切换**</span>**。**
>
> 1. 中断响应可能发生<span style="color: #0b6e99;">特权级切换</span>，进程切换全程在<span style="color: #0b6e99;">内核态</span>下进行。
>
> **注意区分CPU模式切换和进程切换**
>
>
> - 进程切换与模式切换都涉及到上下文的保存与恢复，但它们有本质的不同。
>
> - 模式切换发生在<span style="color: #e03e3e;">用户态响应中断或异常</span>（用户态→核心态）和<span style="color: #e03e3e;">处理完中断异常返回用户态</span>（核心态→用户态）这两种情况下，本质工作是处理中断异常和中断异常返回。
>
> - 模式切换是<span style="color: #0b6e99;">同一进程</span>在自身用户态和内核态下的切换，二者<span style="color: #0b6e99;">共用地址空间</span>，涉及到特权级的切换以及用户栈与内核栈的切换，只需要保存和恢复<span style="color: #e03e3e;">**用户态的上下文**</span>**（主要是通用寄存器，PC、PSW和SP等，即断点和现场信息）**而不需要保存和恢复内核态的上下文。而进程切换发生在<span style="color: #0b6e99;">内核态</span>，以上图P0切换到P1为例。在进程切换发生之前，一定存在某些事件使P0进程离开运行态，而这一处理本来就是在内核态下完成的，因此进程切换P0保存在PCB中的是P0处于内核态的上下文，同样的道理，从P1的PCB中获取的上下文一定也是P1位于内核态下时存放的上下文。所以，<span style="color: #e03e3e;">进程的调度和切换均发生在内核态下</span>，是从一个进程的内核态切换到另一个进程的内核态。
>
> 💡 典型错误认知

> - 错误理解: 认为进程切换是<span style="color: #e03e3e;">直接在用户态间切换</span>，或PCB中保存的是<span style="color: #e03e3e;">用户态上下文</span>
>
> - 正确认知:
>   - 切换永远发生在<span style="color: #0b6e99;">两个进程的内核态之间</span>
>   - PCB保存的是进程在<span style="color: #0b6e99;">内核态被切换时</span>的完整状态
>   - 用户态恢复依赖<span style="color: #0b6e99;">中断返回机制</span>，不是进程切换的直接结果
>
<details><summary>**进程调度和切换的一些Linux相关源码（帮助理解）**</summary>

1. **调度入口:**`**__schedule**`
```c
// kernel/sched/core.c
static void __sched notrace __schedule(bool preempt) {
    struct task_struct *prev, *next;
    // 1. 获取当前进程和下一个待运行进程
    prev = rq->curr;
    next = pick_next_task(rq, prev, &rf); // 通过调度类（如 CFS）选择下一个进程

    // 2. 执行进程切换，如果调度程序选择的下一个进程仍然是该进程，就不用切换了
    if (prev != next) {
        rq->curr = next;
        // 上下文切换
        context_switch(rq, prev, next, &rf);
    }
}
```

1. **上下文切换:**`**context_switch**`
```c
// kernel/sched/core.c
static __always_inline struct rq *
context_switch(struct rq*rq, struct task_struct *prev,
               struct task_struct*next, struct rq_flags *rf) {
    // 1. 切换地址空间（MMU 页表），中断处理就不用切换地址空间，
    //而进程切换需要，因此我们说中断处理程序的执行不算进程切换
    struct mm_struct*mm = next->mm;
    if (mm != prev->active_mm) {
        switch_mm_irqs_off(prev->active_mm, mm, next);
    }

    // 2. 切换寄存器上下文（CPU 状态）
    switch_to(prev, next, prev);
    return rq;
}
```

```c

    struct vm_area_struct *mmap;        // 指向虚拟内存区域（VMA）链表的头节点
    struct rb_root mm_rb;               // VMA 红黑树根节点（用于快速查找内存区域）
    pgd_t*pgd;                         // 页全局目录（Page Global Directory）指针（页表根）
    atomic_t mm_users;                  // 使用该地址空间的进程数（如线程共享时计数）
    atomic_t mm_count;                  // mm_struct 的引用计数（生命周期管理）
    struct rw_semaphore mmap_sem;       // 读写信号量（保护 VMA 操作的并发访问）

    unsigned long start_code, end_code; // 代码段起始和结束地址
    unsigned long start_data, end_data; // 数据段起始和结束地址
    unsigned long start_brk, brk;       // 堆的起始地址和当前堆顶
    unsigned long start_stack;          // 栈的起始地址（栈向下增长）
    unsigned long arg_start, arg_end;   // 命令行参数的起始和结束地址
    unsigned long env_start, env_end;   // 环境变量的起始和结束地址

    // ... 其他字段（如内存策略、反向映射、内存统计等）
};
```

1. 在 Linux 操作系统中，`**__schedule()**` 是内核调度器的核心函数，负责实际的进程切换操作。触发 `**__schedule()**` 的情况可以分为 **主动调度** 和 **被动调度** 两类。以下是详细的触发场景及对应的源码分析
- **主动调度**:**进程主动让出 CPU，通常发生在需要等待资源（如 I/O、锁、信号量）时。**
例如在执行P操作后，发现信号量≤ 0 时，会触发调度（阻塞自己）

```c

    // 1. 检查信号量状态
    if (sem->count <= 0) {
        // 2. 将进程状态设为阻塞，并加入等待队列
        current->state = TASK_INTERRUPTIBLE;
        add_wait_queue(&sem->wait_queue, &wait);
        // 3. 主动触发调度
        schedule(); // 调用调度程序
    }
    // 4. 信号量可用时恢复执行

    return 0;
}
```

```c
    if (curr->sched_class == &fair_sched_class) {

}
```

## 2.1.5 进程间通信

> 💡 考纲原话:进程间通信（<span style="color: #6940a5;">共享内存</span>，<span style="color: #6940a5;">消息传递</span>，<span style="color: #6940a5;">管道</span>，<span style="color: #6940a5;">信号</span>）

由于每个进程的<span style="color: #0b6e99;">用户空间</span>都是<span style="color: #6940a5;">独立的</span>，不能相互访问，因此需要借助<span style="color: #0b6e99;">内核空间</span>来实现进程间通信，原因很简单，每个进程都<span style="color: #6940a5;">共享一个内核空间</span>。

Linux内核提供了多种进程间通信方式，其中最简单的是<mark style="background-color: #ddebf1;">管道</mark>。<span style="color: #0b6e99;">匿名管道</span>是只存在于内存的特殊文件，不存在于文件系统中，shell命令中的「|」竖线就是匿名管道。管道通信的特点是:数据为<span style="color: #6940a5;">无格式的流</span>且大小受限，通信方式是<span style="color: #6940a5;">单向的</span>，数据只能在一个方向上流动，双向通信需要创建两个管道。此外，匿名管道只能用于<span style="color: #6940a5;">父子关系</span>的进程间通信，生命周期与进程创建和终止同步。进程写入的数据<span style="color: #6940a5;">缓存在内核中</span>，另一进程从内核中读取，数据遵循<span style="color: #6940a5;">先进先出原则</span>，不支持lseek等文件定位操作。

<mark style="background-color: #ddebf1;">消息队列</mark>克服了管道通信数据是无格式字节流的问题。消息队列实际上是保存在内核的「<span style="color: #0b6e99;">消息链表</span>」，其消息体可以是<span style="color: #0b6e99;">用户自定义的数据类型</span>，发送时被分成独立的消息体，接收时需与发送方的消息体数据类型保持一致，确保读取的数据正确性。消息队列通信速度不是最及时的，因为每次数据的读写都需要经过<span style="color: #6940a5;">用户态与内核态之间的拷贝</span>过程。

<mark style="background-color: #ddebf1;">共享内存</mark>可以解决消息队列通信中数据拷贝带来的开销，它直接分配一个<span style="color: #0b6e99;">共享空间</span>，每个进程都可以<span style="color: #0b6e99;">直接访问</span>，如同访问自己的空间一样快捷，<span style="color: #6940a5;">无需陷入内核态或系统调用</span>，大大提高了通信速度，是<span style="color: #6940a5;">最快的进程间通信方式</span>。然而，高效的共享内存通信也带来新问题:<span style="color: #e03e3e;">多进程竞争共享资源会造成数据错乱</span>。

因此，需要<mark style="background-color: #ddebf1;">信号量</mark>来保护共享资源，确保任何时刻只有一个进程访问共享资源，实现<span style="color: #0b6e99;">互斥访问</span>。信号量不仅可以实现互斥，还能实现进程间的<span style="color: #0b6e99;">同步</span>。信号量本质是一个<span style="color: #6940a5;">计数器</span>，表示资源个数，其值通过两个<span style="color: #0b6e99;">原子操作</span>控制，分别是<span style="color: #6940a5;">P操作</span>和<span style="color: #6940a5;">V操作</span>。

与信号量名称相似但功能完全不同的是<mark style="background-color: #ddebf1;">信号</mark>。信号是<span style="color: #0b6e99;">异步通信机制</span>，可在应用进程和内核之间直接交互，内核利用信号通知用户空间进程发生的系统事件。信号事件来源主要有<span style="color: #0b6e99;">硬件来源</span>（如键盘Ctrl+C）和<span style="color: #0b6e99;">软件来源</span>（如kill命令）。信号发生时，进程有三种响应方式:1.<span style="color: #0b6e99;">执行默认操作</span>、2.<span style="color: #0b6e99;">捕捉信号</span>、3.<span style="color: #0b6e99;">忽略信号</span>。有两个信号（<span style="color: #6940a5;">SIGKILL</span>和<span style="color: #6940a5;">SIGSTOP</span>）应用进程无法捕捉和忽略，这确保我们能在任何时候结束或停止进程。

前述通信机制都工作于同一台主机，若需与不同主机的进程通信，则需要<span style="color: #6940a5;">Socket通信</span>。Socket不仅用于不同主机进程间通信，也可用于本地主机进程间通信。根据Socket类型，常见的通信方式有:基于<span style="color: #0b6e99;">TCP协议</span>的通信方式、基于<span style="color: #0b6e99;">UDP协议</span>的通信方式，以及<span style="color: #0b6e99;">本地进程间</span>通信方式。

以上就是进程间通信的主要机制。那么，<span style="color: #e03e3e;">线程间的通信方式又如何呢</span>？

同一进程下的线程共享进程资源，<span style="color: #6940a5;">共享变量</span>（如全局变量）都可实现线程间通信。因此，线程间关注的不是通信方式，而是<span style="color: #0b6e99;">多线程竞争共享资源</span>的问题。信号量同样可在线程间实现互斥与同步:

- <span style="color: #0b6e99;">互斥方式</span>，确保任意时刻只有一个线程访问共享资源；
- <span style="color: #0b6e99;">同步方式</span>，确保线程A在线程B之前执行；

<span style="color: #6940a5;">概念</span>:不同进程把各自的虚拟地址区间映射到<span style="color: #0f7b6c;">同一物理内存</span>，读写像本地内存，<span style="color: #0f7b6c;">无需反复陷入内核</span>。

<span style="color: #6940a5;">**共享内存通信工作过程**</span>

**1** 创建共享内存

- 系统调用:进程通过调用<span style="color: #0b6e99;">`shmget`</span>（System V）或 <span style="color: #0b6e99;">`shm_open`</span>（POSIX）创建共享内存。
- 内核在<span style="color: #0f7b6c;">物理内存</span>中分配一块连续区域，指定共享内存的<span style="color: #6940a5;">访问权限</span>（如读写权限）和<span style="color: #6940a5;">大小</span>。
**2** 附加共享内存到进程地址空间

- 系统调用:进程调用 <span style="color: #0b6e99;">`shmat`</span>（System V）或 <span style="color: #0b6e99;">`mmap`</span>（POSIX）将共享内存映射到自己的虚拟地址空间。
- 页表映射:内核修改进程的<span style="color: #6940a5;">页表</span>，将指定的虚拟地址范围映射到共享内存的物理页框。多个进程的虚拟地址可以不同，但最终指向<span style="color: #0f7b6c;">同一物理内存</span>。
- 进程获得共享内存的虚拟地址，一般来说，共享内存位于进程的<span style="color: #0f7b6c;">用户地址空间</span>，可直接通过虚拟地址访问。
**3** 读写共享内存

- <span style="color: #6940a5;">直接访问</span>:进程像操作普通内存一样读写共享内存区域，无需系统调用，实现<span style="color: #0f7b6c;">零拷贝高效通信</span>。
- 数据可见性:一个进程的写入操作会立即对其他附加到该共享内存的进程可见（无缓存一致性协议时需手动同步）。
**4** 同步机制

- 必要性:共享内存（属于<span style="color: #e03e3e;">临界资源</span>）本身不提供同步，需结合<span style="color: #0b6e99;">信号量</span>、<span style="color: #0b6e99;">互斥锁</span>等机制避免竞态条件。
- 示例:进程A写入数据前获取信号量锁，进程B在读取前等待同一信号量锁释放，确保<span style="color: #6940a5;">数据一致性</span>。
**5** 分离共享内存

- 系统调用:进程调用 <span style="color: #0b6e99;">`shmdt`</span>（System V）或 <span style="color: #0b6e99;">`munmap`</span>（POSIX）解除虚拟地址与共享内存的映射。
- 页表更新:内核移除该进程页表中对应的映射关系，但共享内存的物理内存仍保留。
**6** 销毁共享内存段

- 系统调用:通过 <span style="color: #0b6e99;">`shmctl`</span>（System V）或 <span style="color: #0b6e99;">`shm_unlink`</span>（POSIX）标记共享内存为待删除。
- 内核回收:当所有附加进程分离且无引用时，内核释放物理内存。
> 💡 

> - 共享区在用户空间；建立/撤销映射需内核态
>
> - <span style="color: #dfab01;">并发控制是必需的</span>
>
<span style="color: #e03e3e;">**基于内核空间的共享内存**</span>:各进程的内核空间映射到同一物理内存，代码与全局数据共享；但每个进程有独立的<span style="color: #6940a5;">内核栈</span>（指针在 PCB）。

### 2.1.5.3 管道通信（匿名管道为主）

<span style="color: #6940a5;">核心</span>:内核中的<span style="color: #6940a5;">环形缓冲区</span>，以文件描述符读写，<span style="color: #dfab01;">单向、字节流、容量有限</span>。

自测判断题:

1. 管道位于进程用户空间，可直接用户态读写。→ <span style="color: #e03e3e;">错</span>
1. 管道与共享内存都自带同步互斥。→ <span style="color: #e03e3e;">错</span>
1. 管道是存放在磁盘中的“特殊文件”。→ <span style="color: #e03e3e;">错</span>
1. 管道支持定位读写。→ <span style="color: #e03e3e;">错</span>
1. 管道包含互斥锁、等待队列、读/写指针等。→ <span style="color: #0f7b6c;">对</span>
1. 读需要互斥，写不需要。→ <span style="color: #e03e3e;">错</span>
1. 可用 open/write/read/close 等文件接口操作。→ <span style="color: #0f7b6c;">对</span>
1. 所有端关闭后数据持久化到磁盘。→ <span style="color: #e03e3e;">错</span>
1. 支持单向数据传输。→ <span style="color: #0f7b6c;">对</span>
1. 常用于有亲缘关系进程。→ <span style="color: #0f7b6c;">对</span>
1. 父进程被撤销即销毁子进程管道。→ <span style="color: #e03e3e;">错</span>
1. 以消息为单位进行读写。→ <span style="color: #e03e3e;">错</span>
---

<span style="color: #6940a5;">管道</span>有两种类型:<span style="color: #0f7b6c;">匿名管道</span>与<span style="color: #0f7b6c;">有名管道</span>，这里我们着重介绍匿名管道，了解原理后记住相应特点即可。

匿名管道是Linux系统中一种基于<span style="color: #dfab01;">内核缓冲区</span>的进程间通信（IPC）机制，主要用于具有<span style="color: #0f7b6c;">亲缘关系</span>的进程（如父子进程、兄弟进程）之间的<span style="color: #dfab01;">单向数据流</span>通信。其核心原理是通过共享的内核缓冲区和文件描述符继承实现数据传输。具体工作流程及原理如下:

1. **创建管道**
  系统调用:通过`pipe(int pipefd[2])`创建管道，返回两个文件描述符:

  - `pipefd[0]`:<span style="color: #0f7b6c;">读端</span>，用于从管道读取数据
  - `pipefd[1]`:<span style="color: #0f7b6c;">写端</span>，用于向管道写入数据
  内核数据结构:内核为每个管道分配一个<span style="color: #dfab01;">环形缓冲区</span>（即循环队列）和<span style="color: #e03e3e;">两个文件描述符</span>（读端和写端）

1. **进程间共享**
  继承文件描述符:父进程调用`pipe()`创建管道后，通过`fork()`创建子进程。由前面的创建进程的学习我们可以知道，子进程会复制父进程的地址空间，因此子进程继承父进程的文件描述符表，从而共享同一管道的读写端。如下图（左）所示

  ![](https://cos.izumichan16.cn/408note/OS/TKE3DZHvgVA3Y5Vo/1745821797884-8b0aa82b-976a-41dc-a65a-4d91d1e3b1ac-138909.png)

  首先区分一下全双工与半双工通信，在半双工通信中，通信双方可以在同一信道上轮流发送和接收数据，但是不能同时进行发送和接受数据。也就是说，某一时刻信道只能用于一个方向的传输，例如对讲机就是典型的半双工，当一个人按下通话键说话时，对面只能听不能同时说话；只有当另一方停止发送并释放信道， 才可以发送信息；而全双工允许通信双方在同一时刻同时发送和接受数据，例如打电话就是全双工。

  如图实现了父子两个进程使用一个管道完成半双工通信。此时，父进程可以通过<span style="color: #0f7b6c;">fd[1]</span>给子进程发消息，子进程通过<span style="color: #0f7b6c;">fd[0]</span>读。子进程也可以通过<span style="color: #0f7b6c;">fd[1]</span>给父进程发消息，父进程用<span style="color: #0f7b6c;">fd[0]</span>读。

  ![](https://cos.izumichan16.cn/408note/OS/TKE3DZHvgVA3Y5Vo/1745822840401-618c31b1-94ab-45dd-a3dc-522ba0599ef7-327398.png)

  > 💡 

  > 例如在上图中，父进程将想要发送给子进程的数据写入管道之后，必须等子进程将数据全部读取完毕（注意从管道读数据是<span style="color: #dfab01;">一次性操作</span>，读完就失效），之后父进程才能执行读数据操作。如果不这样，父进程会读取自己写入的数据使其失效，从而使通信出错。因此父进程和子进程通过管道进行信息传递是<span style="color: #6940a5;">半双工</span>的，在同一时间段内只能<span style="color: #dfab01;">单向传输</span>数据。
  >
  >
  因此为了方便，一般在Linux中，父进程关闭写端（`close(pipefd[1])`），子进程关闭读端（`close(pipefd[0])`），形成单向数据流（父写子读或子写父读）。

  <span style="color: #e03e3e;">**若需要双向通信（全双工），需创建两个管道。**</span>

  ![](https://cos.izumichan16.cn/408note/OS/TKE3DZHvgVA3Y5Vo/1745820291344-aef6a1e0-788e-4495-8da3-e177b21fce4a-671034.png)

1. **数据读写机制**
  <span style="color: #0f7b6c;">写入操作</span>（write）:数据从<span style="color: #0b6e99;">用户空间</span>拷贝到<span style="color: #0b6e99;">内核缓冲区</span>。若缓冲区满，写操作<span style="color: #d9730d;">阻塞</span>，直到有空间。

  <span style="color: #0f7b6c;">读取操作</span>（read）:数据从<span style="color: #0b6e99;">内核缓冲区</span>拷贝到<span style="color: #0b6e99;">用户空间</span>。若缓冲区空，读操作<span style="color: #d9730d;">阻塞</span>，直到有数据。

  <span style="color: #0f7b6c;">原子性</span>:小于<span style="color: #dfab01;">PIPE_BUF</span>（通常4096字节）的写入保证原子性，即多个进程同时写时，数据不会交叉混合。

1. **生命周期**
  <span style="color: #0f7b6c;">依赖进程</span>:管道随进程的终止而销毁。当所有引用管道的文件描述符被关闭后，内核回收缓冲区资源。

  <span style="color: #0f7b6c;">自动销毁</span>:即使某些进程未正确关闭描述符，当所有进程终止时，内核仍会清理管道。

以上便是匿名管道的核心工作原理。

源码片段与机制（保留精华要点）:

```c
struct pipe_inode_info {
    struct mutex mutex;          // 互斥
    wait_queue_head_t rd_wait;   // 读等待队列
    wait_queue_head_t wr_wait;   // 写等待队列
    unsigned int head, tail;     // 环形缓冲指针
    unsigned int readers, writers; // 引用计数
    // ...
};
```

- mutex 保护缓冲区，读写互斥
- 等待队列在空/满时<span style="color: #d9730d;">阻塞并唤醒</span>
---

上面介绍的<span style="color: #0f7b6c;">匿名管道</span>只能在有<span style="color: #0f7b6c;">亲缘关系</span>的进程之间通信，而<span style="color: #0f7b6c;">命名管道</span>则可以在<span style="color: #0f7b6c;">无亲缘关系</span>的进程之间通信，不过那个不重要，这里不做过多介绍。

> 💡 <span style="color: #e03e3e;">通过上面介绍的管道的原理，我们可以总结以下特点（考点）:</span>

> 1. 管道通信双方可以按照<span style="color: #0f7b6c;">生产者-消费者模型</span>进行通信，管道中写入的数据一旦读出就会从管道消失（可以理解为从队列中出队）。
>
> 1. 管道是一种<span style="color: #0f7b6c;">特殊的文件</span>，是在<span style="color: #dfab01;">内核</span>中的<span style="color: #dfab01;">环形数据缓冲区</span>（数据结构为<span style="color: #dfab01;">循环队列</span>）。
>
> 1. 管道只能读<span style="color: #0f7b6c;">head</span>(读指针)指向的数据，只能在<span style="color: #0f7b6c;">tail</span>（写指针）指向的区域写入数据（队尾写入，队头读出），不支持 `lseek` 之类的文件定位操作。
>
> 1. 读<span style="color: #d9730d;">空管道</span>，进程<span style="color: #d9730d;">阻塞</span>；写<span style="color: #d9730d;">满管道</span>，进程<span style="color: #d9730d;">阻塞</span>。
>
> 1. 同一时刻，管道仅支持<span style="color: #6940a5;">半双工通信</span>，若要实现<span style="color: #6940a5;">全双工通信</span>，需要在进程之间建立<span style="color: #e03e3e;">两个管道</span>。
>
> 1. 对管道的读写操作需要<span style="color: #dfab01;">互斥</span>进行，当有一个进程对管道进行读/写时，其他想要读/写的进程会被阻塞（加入 `rd_wait` 队列并休眠）。
>
管道之所以被称为"特殊的文件"，是因为它在操作方式上类似于文件，需要通过<span style="color: #0f7b6c;">文件描述符</span>和<span style="color: #0f7b6c;">系统调用</span>进行读写（可以像操作普通文件一样使用`read()`、`write()`、`open()`等）；但是它与文件又有以下不同之处:

- 管道存储在<span style="color: #dfab01;">内存</span>之中，而普通文件通常存放在<span style="color: #dfab01;">磁盘</span>之中。
- 普通文件可以支持多个进程同时读，而管道的读写操作都需要<span style="color: #dfab01;">互斥</span>，同一时刻管道只允许一个进程读管道或者写管道。
- 管道中的数据读完就<span style="color: #dfab01;">失效</span>了，而普通文件读操作不会对它产生影响。

### 2.1.5.4 信号（<span style="color: #0b6e99;">2025 年大纲新增</span>）

<span style="color: #6940a5;">概念</span>:<span style="color: #d9730d;">异步</span>、<span style="color: #0f7b6c;">轻量</span>的事件通知机制，内核或进程向目标进程发出事件；不用于传输大数据。

<span style="color: #6940a5;">来源</span>

- 硬件异常:如除零 → <span style="color: #dfab01;">SIGFPE</span>，非法访问 → <span style="color: #dfab01;">SIGSEGV</span>
- 软件事件:`kill`，`raise`，`alarm/setitimer`，子进程退出 → <span style="color: #dfab01;">SIGCHLD</span>
- 终端输入:Ctrl+C → <span style="color: #dfab01;">SIGINT</span>
<span style="color: #d9730d;">处理方式</span>

- 默认动作、捕捉（自定义 handler）、忽略
- <span style="color: #dfab01;">SIGKILL、SIGSTOP 不可捕捉/忽略</span>
<span style="color: #808080;">流程</span>:产生 → 投递 → 按进程设置处理 → 返回原执行点（或终止）

常见信号示例:

- SIGINT 终端中断
- SIGTERM 友好终止
- SIGKILL 强制终止（<span style="color: #dfab01;">不可屏蔽</span>）
- SIGCHLD 子进程状态变化
- SIGALRM 定时器到期
注:经典语义下，同类信号<span style="color: #dfab01;">不排队</span>（实时信号除外）。

### 2.1.6.2 **线程的上下文切换**

- 区别定位:<span style="color: #6940a5;">线程是调度基本单位</span>，<span style="color: #6940a5;">进程是资源拥有单位</span>。

- 多线程进程:共享地址空间与全局资源；各线程仍有<span style="color: #ad1a72;">私有数据（栈、寄存器）需在切换时保存</span>。
- 切换要点:
  - 不同进程的线程切换 ≈ 进程上下文切换（包含<span style="color: #dfab01;">地址空间/页表</span>切换）
  - 同一进程内线程切换:<span style="color: #0f7b6c;">无需切换页表</span>，仅切换寄存器、栈等私有上下文，开销更小。

### 2.1.6.3 **线程与进程的比较**

线程和进程之间的另一个主要区别在于栈，在简单的传统进程地址空间模型(单线程进程)中只有一个栈，通常位于地址空间的底部；然而，在多线程的进程中，每个线程独立运行，因此每个线程都有一个栈，假设有一个多线程的进程它有两个线程，结果地址空间看起来不同。

![](https://cos.izumichan16.cn/408note/OS/TKE3DZHvgVA3Y5Vo/1734100965020-4ec36706-f6d9-433a-b585-8be7a0c424bf-969830.jpeg)

从图中我们可以看到，两个栈跨越了进程的地址空间。因此，所有位于栈上的变量、参数、返回值和其他栈上的数据，都会被放置在<span style="color: #6940a5;">线程本地存储</span>的位置，即相关线程的栈。

由于每个线程都有自己的栈，因此线程局部变量是<span style="color: #6940a5;">线程私有</span>的，其他线程不应该访问。线程之间共享数据需要放在<span style="color: #dfab01;">堆(heap)</span>或其他全局可访问的位置。

由于线程之间共享地址空间，理论上同一进程的不同线程可以修改别的线程的栈内数据，但同一进程的线程属于同一用户，通常程序员会在编程时避免多个线程之间修改栈数据的行为。

线程相比进程能减少开销，体现在:

- <span style="color: #0f7b6c;">创建速度更快</span>:线程创建时不需要分配内存管理、文件管理等资源信息，而是共享进程已有的资源。
- <span style="color: #0f7b6c;">终止速度更快</span>:线程释放的资源相比进程少很多。
- <span style="color: #0f7b6c;">切换开销更小</span>:同一进程内的线程切换比进程切换快，因为线程共享相同的地址空间（<span style="color: #0b6e99;">虚拟内存共享</span>），意味着同一进程的线程共用同一页表，切换时<span style="color: #0f7b6c;">无需切换页表</span>。而进程间切换需要切换页表，开销较大。
- <span style="color: #0f7b6c;">通信效率更高</span>:<span style="color: #e03e3e;">由于同一进程的各线程共享内存和文件资源，线程间数据传递不需要经过内核，数据交互效率更高。</span>
综上，无论在时间效率还是空间效率方面，线程都优于进程。

### 2.1.6.6 **线程的实现方式**

1) **用户级线程（ULT）**

![](https://cos.izumichan16.cn/408note/OS/TKE3DZHvgVA3Y5Vo/1745860276197-ed138caf-d15c-41e3-89fe-f0374f3117c3-951515.png)

**用户级线程的特征**

- 不依赖于<span style="color: #6940a5;">操作系统的内核</span>
  - 内核<span style="color: #e03e3e;">不了解</span>用户线程的存在
  - 可用于<span style="color: #0b6e99;">不支持线程</span>的多进程操作系统
- 在<span style="color: #0f7b6c;">用户空间</span>实现的线程机制
  - 每个进程有私有的<span style="color: #6940a5;">线程控制块（TCB）</span>列表，用于跟踪记录各线程状态信息（PC、栈指针、寄存器等）
  - TCB由<span style="color: #0b6e99;">线程库函数</span>维护
- 同一进程内的线程<span style="color: #0f7b6c;">操作效率高</span>
  - 用户级线程的管理和调度完全在用户空间进行，线程切换由线程库函数完成，<span style="color: #e03e3e;">无需用户态到内核态的切换</span>，避免系统调用开销，使创建、销毁和切换操作比内核级线程更快
- 允许每个进程拥有<span style="color: #0b6e99;">自己的线程调度算法</span>
  - 用户可根据程序需求自定义调度策略，如实时系统可采用优先级调度，计算密集型任务可使用时间片轮转
**用户级线程的缺点:**

- 一个线程阻塞会导致<span style="color: #e03e3e;">整个进程（包括所有线程）阻塞</span>，因为内核不了解用户线程的存在
- <span style="color: #e03e3e;">不利于多处理器利用</span>:操作系统无法将不同线程调度到不同处理器上运行，无法发挥多处理器的并行处理能力
- <span style="color: #e03e3e;">线程抢占困难</span>:运行中的线程必须主动交出CPU使用权，其他线程才能执行，因为用户态线程无法打断当前运行线程
- <span style="color: #e03e3e;">时间片分配劣势</span>:由于时间片分配给整个进程，多线程执行时每个线程获得的时间片较少，执行相对较慢
- <span style="color: #e03e3e;">编程复杂性增加</span>:程序员需要显式管理线程的生命周期和调度
- <span style="color: #e03e3e;">公平性</span>:它们无法充分利用操作系统内核的调度器，可能会出现资源争用和不公平的问题

2) **内核级线程（KLT）**

![](https://cos.izumichan16.cn/408note/OS/TKE3DZHvgVA3Y5Vo/1745861318973-3542a096-be57-449b-8444-7793c473450e-230696.png)

内核级线程，或者称为内核线程，是由操作系统内核来管理和调度的线程。内核线程的创建、同步和调度等操作都是由内核来完成的，因此，内核线程可以<span style="color: #e03e3e;">直接利用操作系统提供的调度算法、优先级管理等机制</span>。内核空间为每一个内核级线程设置一个线程控制块，内核根据该控制块感知某线程的存在，并对其加以控制。

内核级线程的特征:

- <span style="color: #6940a5;">由内核维护PCB和TCB</span>
- <span style="color: #6940a5;">线程执行系统调用而被阻塞不影响其他线程</span>
- <span style="color: #6940a5;">线程的创建、终止和切换开销相对较大</span>
  - 因为线程的管理和调度是由内核完成的，所以创建、销毁和切换线程等操作需要通过<span style="color: #e03e3e;">系统调用</span>来进行。这意味着这些操作需要在<span style="color: #0f7b6c;">用户态和内核态之间进行切换</span>，因此比用户级线程的相应操作更为耗时
- <span style="color: #6940a5;">支持多处理器并行</span>
  - 因为内核了解并控制所有的内核级线程，所以它可以将不同的线程调度到多个处理器上运行，从而<span style="color: #0b6e99;">充分利用多处理器的并行处理能力</span>
- <span style="color: #6940a5;">以线程为单位进行CPU时间分配</span>
  - 多线程的进程可获得更多CPU时间

### 2.1.6.8 **多线程模型**

# 2.2 处理机调度

## 2.2.1 调度的概念

<span style="color: #6940a5;">**调度的层次**</span>:

调度策略在操作系统中起着非常关键的作用，主要可以分为三类:<span style="color: #6940a5;">高级调度</span>（也被称为作业调度）、<span style="color: #6940a5;">中级调度</span>（也被称为内存调度）以及<span style="color: #6940a5;">低级调度</span>（也被称为进程调度或CPU调度）。

<details><summary>**三层调度详解**</summary>

- <span style="color: #6940a5;">**高级调度（作业调度）**</span>:这是最高级别的调度。其主要任务是控制<span style="color: #0f7b6c;">"作业池"</span>（即用户提交的一系列作业）中等待执行的进程数量。当一个新作业（即程序）提交给系统执行时，作业调度器决定是否接受这个作业，并决定何时将其从作业池移入内存，进行执行。这种调度<span style="color: #0f7b6c;">**主要在多道批处理系统中使用**</span>。**每个作业只调入一次，调出一次**。**作业调入时会建立PCB，调出时才撤销PCB**。
> 💡 最后这句话是在解释高级调度（作业调度）的特点。

> 当说"每个作业只调入一次，调出一次"时，意思是:
>
>
> - 在批处理系统中，一个作业（程序）从提交到完成的整个生命周期中，它只会被调入内存一次，然后执行直到完成，最后被调出
>
> - 与低级调度不同，低级调度（进程调度）中的进程可能会被多次调度进出CPU
>
> 关于"作业调入时会建立PCB，调出时才撤销PCB":
>
>
> - 当作业被高级调度器接受并调入内存时，系统会为其创建进程控制块（PCB），此时作业转变为进程
>
> - 只有当整个作业完全执行结束，被调出系统时，其PCB才会被撤销
>
> 这与中级调度和低级调度不同:
>
>
> - 中级调度可能会多次将进程在内存和外存之间交换（不会撤销PCB）
>
> - 低级调度则频繁地在就绪队列和CPU之间调度进程（更不会撤销PCB）
>
- <span style="color: #6940a5;">**中级调度（内存调度）**</span>:中级调度器负责把暂时不运行的进程调度到硬盘上（即换出），此时进程的状态为<span style="color: #6940a5;">**挂起态**</span>，以便为新的、即将运行的进程释放内存。需要运行的进程则从硬盘换入内存，这个过程被称为<span style="color: #6940a5;">**换入/换出（Swapping）**</span>。
- <span style="color: #6940a5;">**低级调度（进程调度或CPU调度）**</span>:这是最低级别的调度。其主要任务是选择内存中的一个进程，分配给CPU进行执行。
</details>

![](https://cos.izumichan16.cn/408note/OS/TKE3DZHvgVA3Y5Vo/1746344689781-b07223eb-03ad-4099-8e80-5eb497c77ac0-999652.png)

<span style="color: #d9730d;">**三层调度的联系、对比**</span>

---

> 💡 <span style="color: #6940a5;">易混点纠正:三层调度如何串联</span>

> - 作业不必然由“很多进程”协作完成。被接纳的作业至少创建一个进程，具体是否再派生出多个进程或多线程取决于实现与负载。
>
> - 分层顺序要清晰:
>   1) 高级调度（作业调度）:从作业池接纳作业→创建进程（建 PCB）→进程入就绪队列。
>
>   2) 中级调度（内存/交换）:运行期间按内存压力与活跃度反复在“就绪/阻塞”与“就绪挂起/阻塞挂起”之间换入/换出。
>
>   3) 低级调度（CPU调度）:仅在“内存中的就绪进程”之间分配 CPU。
>
>
> - PCB撤销时机:作业完成、最终调出系统时撤销 PCB；中级调度的换入/换出不会撤销 PCB（只是挂起或激活）。
>
> - 多作业并存时:
>   - 高级调度控制接纳节奏与多道程序度。
>   - 中级调度决定谁留在内存、谁暂挂外存。
>   - 低级调度在“当前在内存”的就绪进程间轮转或抢占。
>
## 2.2.2 调度的实现（调度器/调度程序scheduler）

<span style="color: #6940a5;">调度程序</span>（Scheduler）是操作系统中负责管理进程执行的关键组件。它的主要任务是根据特定的<span style="color: #0f7b6c;">调度算法</span>决定<span style="color: #0b6e99;">就绪队列</span>中的哪个进程应该获得CPU资源。调度程序通常包括三个主要部分:<span style="color: #d9730d;">排队器</span>（Queuing），<span style="color: #d9730d;">分派器</span>（Dispatcher），和<span style="color: #d9730d;">上下文切换器</span>（Context Switcher）。

- <span style="color: #d9730d;">**排队器**</span>**（Queuing）**:负责管理进程队列，根据进程的<span style="color: #0f7b6c;">优先级</span>、<span style="color: #0f7b6c;">到达时间</span>等因素对进程进行排序。排队器将进程分为不同的队列，如<span style="color: #0b6e99;">就绪队列</span>、<span style="color: #0b6e99;">等待队列</span>、<span style="color: #0b6e99;">阻塞队列</span>等。就绪队列中的进程已准备好运行，等待分派器将它们分配给CPU。等待队列和阻塞队列中的进程则因为I/O操作或其他资源需求而暂时无法执行。
  > 排队器会根据<span style="color: #0f7b6c;">调度算法</span>（如<span style="color: #6940a5;">先来先服务</span>、<span style="color: #6940a5;">短作业优先</span>、<span style="color: #6940a5;">优先级调度</span>等）对进程进行排序，以便分派器能够根据这些排序决策分配CPU资源。

- <span style="color: #d9730d;">**分派器**</span>**（Dispatcher）**:执行完调度程序根据调度算法从就绪队列中选出一个进程之后，将处理机资源分配给它。
- <span style="color: #d9730d;">**上下文切换器**</span>**（Context Switcher）**:将当前进程的<span style="color: #6940a5;">内核上下文</span>保存到它的<span style="color: #0b6e99;">PCB</span>中，然后从刚被分配到处理机的进程的PCB中取出上下文，之后便切换到了新进程，可以继续执行；
## 2.2.3 调度的时机与调度方式（抢占式/非抢占式）

### <span style="color: #6940a5;">非抢占式调度</span>

- **定义**:一个进程除非运行结束或者自己主动放弃CPU，否则不会被其它进程抢占CPU。
- **调度时机**:
  - 进程运行结束
  - 进程由于发起I/O等主动阻塞，主动放弃处理机使用权
> 若不考虑进程执行`yield`系统调用主动释放处理机资源，那么非抢占式调度只会出现运行态到退出态或阻塞态的转变，不可能会发生运行态到就绪态的转变。

- **特点**:
  - 调度不太频繁，CPU利用率一般更高（没有运行态与就绪态的切换开销）
  - 实时性比较差，<span style="color: #0f7b6c;">**一般用于批处理操作系统**</span>，<span style="color: #e03e3e;">**不能用于大部分实时操作系统和分时操作系统**</span>
  - 系统开销小，整体吞吐量更大
### <span style="color: #6940a5;">抢占式调度</span>

- **定义**:进程在执行过程中，可能<span style="color: #0f7b6c;">**因为时间片用完或者有更高优先级进程进入就绪态而被抢占CPU**</span>。
- **调度时机**:
  - 当前进程主动放弃CPU（运行结束或者进入阻塞态）
  - 当前进程时间片用完或有更高优先级的进程进入就绪态
- **特点**:
  - 频繁调度，实时性强
  - 可以防止一个进程长时间独占处理器的恶意行为
  - 可以优先处理更紧急的进程，也可实现让各进程按时间片轮流执行的功能(通过时钟中断)
  - <span style="color: #0f7b6c;">**等待时间和响应时间更短，用户体验好，适用于分时操作系统、实时操作系统**</span>
### <span style="color: #d9730d;">抢占式调度的具体实现方式</span>

在进程的PCB中，为进程设置一个<span style="color: #6940a5;">**标志位**</span>，例如linux中`PCB`里的<span style="color: #6940a5;">`**TIF_NEED_RESCHED**`</span><span style="color: #6940a5;">**（记作**</span><span style="color: #6940a5;">`**NEED_RESCHED**`</span><span style="color: #6940a5;">**）**</span>标志位，其含义为"<span style="color: #0f7b6c;">**需要重新调度**</span>"，当某个进程的 `TIF_NEED_RESCHED` 标志被设置时，表示内核需要尽快触发调度器`scheduler`，重新选择下一个要运行的任务。

> <span style="color: #808080;">中断处理返回的宏观流程</span>

> 1. **中断服务程序（ISR）主体执行完毕**:这是中断处理的业务逻辑部分，比如处理一个磁盘读写完成的信号。
>
> 1. **准备退出中断 (ret_from_intr)**:当中断服务程序的主体完成后，会跳转到一个通用的、体系结构相关的退出路径。在Linux中，这个入口点通常被称为`ret_from_intr`或类似的名字。
>
> 1. **检查 need_schedul 标志并决定是否调度**
>
> 1. **执行调度或返回原进程**:
>   - **如果需要调度**:则执行调度程序（`schedule()`），选择下一个要运行的进程，并进行上下文切换。
>   - **如果不需要调度**:则直接准备返回到被中断的进程。
>
> 1. **恢复现场和屏蔽字**。
>
> 1. **执行 ire (或 eret 等) 指令，真正从硬件上返回**。
>

<details><summary>**什么时间点不能进行调度？**</summary>

- <span style="color: #e03e3e;">**当前进程处于中断处理过程中**</span>（中断处理通常涉及到操作系统的核心功能和关键资源，是系统工作的一部分，逻辑上不属于某一进程，不应被剥夺处理机资源）
- 进程<span style="color: #e03e3e;">**在访问操作系统内核临界区中**</span>（注意在用户级别的临界区中可以进行进程调度）
- 禁用中断（屏蔽中断过程中）
- 原语执行过程中（如加锁、解锁、中断现场保护、恢复等原子操作。原子操作不可中断一气呵成，连中断都要屏蔽，更不应该进行进程调度与切换）
</details>

D正确。在中断/异常/系统调用的返回路径，会检查当前进程的 `**NEED_RESCHED**` 标志，若有效则触发调度。

### <span style="color: #dfab01;">临界区的不同调度策略</span>

在操作系统中，无论是在内核级别还是用户级别，临界区的基本概念都是相同的:它是一段访问共享资源或数据的代码，这段代码必须被互斥地执行。这是为了防止并发访问导致的数据不一致和其他并发问题。

然而，<span style="color: #6940a5;">**内核临界区**</span>和<span style="color: #6940a5;">**用户级别的临界区**</span>在一些方面有所不同:

### <span style="color: #0b6e99;">闲逛进程 🌟</span>

<span style="color: #6940a5;">**闲逛进程**</span>（Idle Process），又称为空闲进程或空闲任务，是操作系统中一种特殊的进程，用于在系统中没有其他进程需要运行时占据CPU资源。闲逛进程的主要目的是确保CPU始终有任务可执行，从而避免CPU处于空闲状态。

<span style="color: #d9730d;">**闲逛进程的特点**</span>:

1. <span style="color: #0f7b6c;">**优先级最低**</span>:闲逛进程的优先级通常设置为最低，这意味着只有在没有其他进程需要运行时，闲逛进程才会被调度执行。一旦有其他进程需要CPU资源，闲逛进程会立即让出CPU，让其他进程执行。
1. <span style="color: #0f7b6c;">**持续运行**</span>:闲逛进程通常会持续运行，直到有其他进程需要CPU资源。在某些操作系统中，闲逛进程可能会执行一些简单的任务，如清理内存或执行系统维护操作。但在大多数情况下，闲逛进程仅执行一个空循环，不执行任何实际操作。
1. <span style="color: #0f7b6c;">**只运行在内核态下**</span>
1. <span style="color: #0f7b6c;">**资源占用最小**</span>:不需要CPU以外的资源，不会阻塞

## 2.2.4 调度算法的评价指标（调度准则）

### <span style="color: #6940a5;">核心性能指标</span>

<span style="color: #0f7b6c;">**CPU 利用率**</span>:衡量 CPU 忙碌程度

- 公式:<span style="color: #0f7b6c;">CPU 利用率</span> = \frac{\text{CPU 有效工作时间}}{\text{总时间}}
- 目标:使 CPU 尽可能忙碌，避免空闲
<span style="color: #0f7b6c;">**系统吞吐量**</span>:单位时间内完成的作业数量

- 公式:<span style="color: #0f7b6c;">系统吞吐量</span> = \frac{\text{总共完成的作业数}}{\text{总共花费时间}}
- 长作业占用较长 CPU 资源，降低吞吐量；短作业提升系统吞吐量
### <span style="color: #6940a5;">时间相关指标</span>

<span style="color: #0f7b6c;">**作业周转时间**</span>:从提交到完成的总时间段

- 定义:<span style="color: #0f7b6c;">周转时间</span> = 作业完成时间 - 作业提交时间
- 包含:进程运行 + 阻塞时间 + 等待时间
- 用户更关心自己单个作业的周转时间
<span style="color: #0f7b6c;">**平均周转时间**</span>:系统整体表现指标

- 公式:<span style="color: #0f7b6c;">平均周转时间</span> = \frac{\text{各作业周转时间之和}}{\text{作业数}}
- 操作系统更关心所有作业的平均值
<span style="color: #0f7b6c;">**带权周转时间**</span>:相对效率指标

- 公式:<span style="color: #0f7b6c;">带权周转时间</span> = \frac{\text{作业周转时间}}{\text{作业实际运行时间}}
- 特点:必然 ≥ 1，越小越好
- 意义:实际运行时间相同时，周转时间短的用户满意度更高
<span style="color: #0f7b6c;">**平均带权周转时间**</span>:系统相对效率

- 公式:<span style="color: #0f7b6c;">平均带权周转时间</span> = \frac{\text{各作业带权周转时间之和}}{\text{作业数}}
### <span style="color: #6940a5;">调度算法专用指标</span>

<span style="color: #0f7b6c;">**等待时间**</span>:就绪队列中的等待时间

- 定义:进程处于就绪态的时间之和
- CPU 调度算法只影响等待时间，不影响运行和 I/O 时间
<span style="color: #0f7b6c;">**响应时间**</span>:用户体验关键指标

- 定义:从用户提交请求到系统<span style="color: #0f7b6c;">第一次产生响应</span>所花费的时间
- 在交互式系统中是衡量调度算法好坏的<span style="color: #0f7b6c;">主要标准</span>
> 对于作业在后备队列（也被称为作业池）中等待的时间，通常被称为等待进入内存的时间，或者进入就绪队列的等待时间。这个时间通常被视为另一个指标，因为进程在后备队列中等待是因为当前内存资源不足，无法将更多的进程载入内存。在这种情况下，进程还未达到可以被执行的就绪状态。所以，<span style="color: #e03e3e;">通常说的等待时间是指进程已经进入就绪队列，但是由于CPU正在执行其他进程，还未轮到该进程执行的时间。</span>

### 先来先服务调度算法

**先来先服务（**`First-Come, First-Served`**，**<span style="color: #0b6e99;">**FCFS**</span>**）调度算法**是一种最简单的调度算法，属于<span style="color: #e03e3e;">**不可剥夺（非抢占式）算法**</span>，它既可用于作业调度，也可用于进程调度。

在**作业调度**中，该算法每次从<span style="color: #6940a5;">后备队列</span>中选择最先进入该队列的作业，将它们调入内存、分配必要资源、创建进程并放入就绪队列。

在**进程调度**中，该算法按照进程<span style="color: #0f7b6c;">到达的先后顺序</span>分配处理器，直到**进程执行完毕或被阻塞(例如请求I/O)**。在FCFS算法中，进程的等待时间取决于它前面进程的执行时间和到达时间。

**FCFS**算法的优点是<span style="color: #0b6e99;">简单易实现</span>，<span style="color: #0f7b6c;">**公平**</span>，<span style="color: #0b6e99;">**适用于长作业和低交互型进程**</span>，<span style="color: #0f7b6c;">**不会导致饥饿**</span>。

缺点是:

1. <span style="color: #e03e3e;">短作业排在长作业后面时需等待很长时间</span>，带权周转时间大，用户体验差。因此对长作业有利，对短作业不利（相较于SJF和高响应比算法）。
1. <span style="color: #e03e3e;">资源利用率低</span>:当CPU密集型进程占用处理器时，I/O设备可能闲置，而I/O密集型进程则被迫等待。
**为什么说FCFS算法有利于CPU繁忙型作业，不利于I/O繁忙型作业？**

> FCFS调度算法对<span style="color: #0b6e99;">长作业有利</span>，因为它按照作业<span style="color: #0f7b6c;">到达顺序</span>进行调度，不考虑作业长度。<span style="color: #0b6e99;">CPU繁忙型作业</span>需要大量CPU时间计算，很少请求I/O操作，在FCFS下能获得<span style="color: #0f7b6c;">连续的执行时间</span>，避免频繁中断和上下文切换带来的效率损失。而<span style="color: #e03e3e;">I/O繁忙型作业</span>频繁请求I/O操作，每次操作完成后必须重新排队等待调度。因此，CPU繁忙型作业更接近长作业概念，能充分利用分配的时间；而I/O繁忙型作业在短暂使用处理器后就因I/O操作而被阻塞，完成I/O后又排到队尾等待，导致<span style="color: #e03e3e;">等待时间过长</span>。

### 短作业优先(SJF)调度算法

**短作业优先（**`SJF，Shortest Job First`**）调度算法**是一种基于<span style="color: #0b6e99;">作业执行时间</span>的<span style="color: #e03e3e;">**非抢占式调度算法**</span>。其核心思想是**优先调度**<span style="color: #0f7b6c;">**执行时间最短**</span>**的作业，以**<span style="color: #0b6e99;">**最小化平均等待时间和平均周转时间**</span>。

该算法既适用于作业调度也适用于进程调度。短作业优先(SJF)是从<span style="color: #6940a5;">后备队列</span>中选择一个或若干估计运行时间最短的作业，将它们调入内存运行；**短进程优先(SPF, process)**是从<span style="color: #6940a5;">就绪队列</span>中**选择一个**<span style="color: #0f7b6c;">**估计运行时间最短**</span>**的进程将处理机分配给它**，使之立即执行，直到完成或因某事件阻塞时，才释放处理机。(注意，更为恰当的表示是<span style="color: #0b6e99;">**最短下次CPU执行**</span>(shortest-next-CPU-burst)算法，因为调度取决于进程的下次CPU执行的长度，而非其总长度)。

**优点:**能<span style="color: #0f7b6c;">最小化平均等待时间和平均周转时间</span>，因为优先调度执行时间最短的作业。这减少了作业的等待时间和完成时间，提高了系统性能。

**缺点**:

- 首先，需要<span style="color: #e03e3e;">预先知道每个作业的执行时间</span>，但实际情况下，这些时间通常是未知的。作业/进程的执行时间通常由用户提供，可能不准确，导致无法实现真正的短作业优先。
- 其次，SJF算法可能导致<span style="color: #e03e3e;">长作业等待时间过长</span>，因为短作业总是优先执行，这可能导致<span style="color: #e03e3e;">长作业饥饿</span>。
- 最后，该算法<span style="color: #e03e3e;">完全不考虑作业的紧迫程度</span>，无法保证紧急任务得到及时处理。
该调度算法也有<span style="color: #0b6e99;">**抢占式版本**</span>，即**最短剩余时间优先（**`SRTN，Shortest Remaining Time Next`**）算法**，这是一种**基于**<span style="color: #0f7b6c;">**作业剩余执行时间**</span>**的抢占式调度算法**。在SRTN算法中，**当**<span style="color: #0b6e99;">**新作业到达系统时**</span>**（即每当有进程加入就绪队列时），**操作系统会比较该作业的剩余执行时间与当前执行作业的剩余时间。如果新作业的剩余执行时间更短，操作系统会<span style="color: #e03e3e;">暂停当前作业</span>，将CPU分配给新作业。若两个作业的剩余执行时间相同，则可使用先来先服务（FCFS）算法决定先后顺序。

`SRTN`算法的优点在于它可以<span style="color: #0f7b6c;">最小化平均等待时间和平均周转时间</span>，因为它优先调度剩余执行时间最短的作业，从而减少作业的等待时间和完成时间，提高系统响应速度和吞吐量。

**408考试注意的细节:**

- 若题目未特殊说明，所提到的"短作业/进程优先算法" <span style="color: #e03e3e;">**默认是非抢占式的**</span>
- 在有前提条件"<span style="color: #0b6e99;">所有进程可同时运行</span>"或"<span style="color: #0b6e99;">所有进程几乎同时到达</span>"的情况下，我们可以说采用SJF的调度算法的平均等待时间、平均周转时间最少。若未加该前提条件，则应该说"<span style="color: #0f7b6c;">**抢占式的短作业/进程调度算法(SRTN)的平均等待时间、平均周转时间最少**</span>**。**
- 如果选择题中遇到"SJF的平均等待时间、平均周转时间最少"的选项，最好先判断别的选项是否有明显错误，若无更合适选项，那也应该选择该选项。
### 高响应比优先(HRRN）调度算法

`FCFS`算法在每次调度时选择<span style="color: #0b6e99;">等待时间最长</span>的作业/进程服务，但由于不考虑运行时间，对<span style="color: #e03e3e;">短作业不友好</span>；

`SJF`算法只考虑<span style="color: #0f7b6c;">执行时间</span>而完全忽略等待时间，导致对<span style="color: #e03e3e;">长作业不友好</span>，甚至可能引发<span style="color: #e03e3e;">饥饿现象</span>。

**高响应比优先调度算法（Highest Response Ratio Next，HRRN）**是一种基于<span style="color: #0b6e99;">响应比</span>的<span style="color: #0f7b6c;">非抢占式</span>调度算法，它<span style="color: #0b6e99;">平衡</span>了上述两种算法的缺点，**同时考虑每个作业的**<span style="color: #0b6e99;">**等待时间**</span>**和**<span style="color: #0f7b6c;">**估计运行时间**</span>。

该算法应用于作业/进程调度，每次调度时计算各作业/进程的<span style="color: #0b6e99;">响应比</span>，为<span style="color: #0f7b6c;">响应比最高</span>的作业/进程提供服务；

响应比 = \frac{等待时间+计算时间}{计算时间}

作为<span style="color: #0f7b6c;">**非抢占式**</span>算法，**只有当前运行的作业/进程**<span style="color: #e03e3e;">**主动放弃处理机**</span>**（正常/异常完成，或主动阻塞）时，才需要进行调度并计算响应比；**

优缺点:

- 该算法<span style="color: #0b6e99;">综合考虑</span>等待时间和运行时间。当等待时间相同时，<span style="color: #0f7b6c;">服务时间短的优先</span>（体现SJF优点）；当服务时间相同时，<span style="color: #0b6e99;">等待时间长的优先</span>（体现FCFS优点）；
- 对长作业而言，随着等待时间增长，其响应比逐渐增大，从而<span style="color: #0f7b6c;">**避免了长作业饥饿问题**</span>；
- 然而，HRRN算法也存在局限性。最主要的是它需要<span style="color: #e03e3e;">预先知道</span>每个作业的执行时间，但在实际应用中，这些时间通常<span style="color: #e03e3e;">无法准确获知</span>。

以上三种算法主要关心对用户的<span style="color: #0f7b6c;">公平性</span>、<span style="color: #0b6e99;">平均周转时间</span>、<span style="color: #0b6e99;">平均等待时间</span>等评价系统整体性能的指标，但不关心"<span style="color: #e03e3e;">响应时间</span>"，也不区分任务的<span style="color: #e03e3e;">紧急程度</span>，因此对用户而言<span style="color: #e03e3e;">交互性很差</span>。这三种算法**一般适用于早期的**<span style="color: #0f7b6c;">**批处理系统**</span>。

当然FCFS算法经常与其他算法结合使用。另外**我们**<span style="color: #e03e3e;">**无法事先准确知道**</span>**一个进程/作业的运行时间(要求服务时间)，只能**<span style="color: #0b6e99;">**近似预测**</span>**(如使用以前CPU执行长度的指数平均值)，因此高响应比优先调度算法是「**<span style="color: #e03e3e;">**理想型**</span>**」调度算法，现实中**<span style="color: #e03e3e;">**难以实现**</span>。

### 时间片轮转(RR，Round-Robin)调度算法

时间片轮转调度算法（Round Robin）是**一种基于**<span style="color: #0b6e99;">**时间片**</span>**的**<span style="color: #0f7b6c;">**抢占式**</span>**调度算法**。每个进程被分配一个固定的时间片（20ms~50ms），当时间片用完后，操作系统会将该进程挂起，并将CPU分配给下一个进程。如果进程在时间片结束前完成任务，它会被从就绪队列中移除；否则会被重新加入到就绪队列的末尾，等待下一次调度。

该调度算法**用于**<span style="color: #0b6e99;">**进程调度**</span>，只有作业放入内存建立了相应的进程后，才能被分配处理机时间片。

属于<span style="color: #0f7b6c;">**抢占式算法**</span>，若进程未能在时间片内运行完，将被强行剥夺处理机使用权，由<span style="color: #0b6e99;">**时钟装置**</span>**发出**<span style="color: #e03e3e;">**时钟中断**</span>**来通知CPU时间片已到**。

**优点**:<span style="color: #0f7b6c;">公平</span>、<span style="color: #0f7b6c;">响应快</span>、**适用于**<span style="color: #0b6e99;">**分时操作系统**</span>，确保每个进程都能获得一定的CPU时间，避免了长时间等待，<span style="color: #0f7b6c;">**不会导致饥饿**</span>。

**缺点**:高频率的进程切换导致<span style="color: #e03e3e;">较大开销</span>，且<span style="color: #e03e3e;">不区分任务的紧急程度</span>。

**时间片设置太大或太小会导致什么问题？**

在该算法中，<span style="color: #0b6e99;">时间片大小</span>对系统性能影响很大。

若**时间片**<span style="color: #0b6e99;">**足够大**</span>，以至于所有进程都可以在一个时间片内执行完毕，则时间片轮转调度算法就**退化为**<span style="color: #0f7b6c;">**先来先服务调度算法**</span>。

若**时间片**<span style="color: #e03e3e;">**很小**</span>，则处理机将在进程间过于频繁地切换，使**处理机的**<span style="color: #e03e3e;">**开销增大**</span>，真正用于运行用户进程的时间将减少。

因此时间片的大小应选择适当。一般来说，设计时间片时要让切换进程的开销占比不超过1%，根据经验，80%的CPU执行应该小于时间片。

**时间片的长短通常由以下因素决定:**<span style="color: #0b6e99;">**系统的响应时间**</span>**、**<span style="color: #0b6e99;">**就绪队列的进程数目**</span>**和**<span style="color: #0b6e99;">**系统的处理能力**</span>**。**

注意:

- 若进程在<span style="color: #0f7b6c;">时间片内提前完成</span>，则进程本身自动释放CPU，会发生调度
- 如果当前进程的CPU执行时间<span style="color: #e03e3e;">大于一个时间片</span>，定时器会<span style="color: #e03e3e;">中断</span>操作系统，然后进行<span style="color: #0b6e99;">上下文切换</span>，将进程加入到<span style="color: #0b6e99;">就绪队列队尾</span>，CPU会选择就绪队列的下一个进程
- **在做题时，若某一时刻进程P1下处理机，同一时刻进程P2到达，那么默认**<span style="color: #0b6e99;">**新到达的进程先进入就绪队列**</span>
<span style="color: #e03e3e;">**时钟中断**</span>是计算机系统中的一种重要中断类型，主要用于计时和控制时间相关的操作。它由<span style="color: #0b6e99;">系统时钟</span>（通常是硬件定时器）周期性发出，中断当前执行的程序，转而执行特定的中断处理程序。时钟中断在操作系统中的作用至关重要，详细介绍如下。

<span style="color: #0b6e99;">**时钟中断的工作原理**</span>

1. <span style="color: #0b6e99;">**硬件定时器**</span>:计算机系统中有专门的硬件定时器，根据设定的时间间隔周期性产生时钟中断。
1. <span style="color: #0b6e99;">**中断信号**</span>:当定时器达到设定的时间间隔时，向CPU发送中断信号。
1. <span style="color: #0b6e99;">**中断处理**</span>:CPU收到时钟中断信号后，暂停当前执行的任务，保存当前CPU状态，然后转到中断向量表中对应的中断处理程序。
1. <span style="color: #0b6e99;">**中断服务程序**</span>**（ISR - Interrupt Service Routine）**:时钟中断的ISR由操作系统提供，负责处理各种时间相关的任务。
<span style="color: #0f7b6c;">**时钟中断的主要功能**</span>

1. <span style="color: #0f7b6c;">**更新系统时间**</span>:
  - 时钟中断的主要任务之一是更新系统时钟。每次时钟中断发生时，ISR会更新系统维护的时间变量，使系统时间准确反映当前时间。
1. <span style="color: #0f7b6c;">**时间片管理和进程调度**</span>:
  - 在多任务操作系统中，时钟中断用于时间片管理。每个进程分配一个时间片，时钟中断会检查当前进程的时间片是否用完。若用完，操作系统会触发进程调度，将CPU分配给其他进程。
<span style="color: #0b6e99;">**时钟中断的实现细节**</span>

1. <span style="color: #0b6e99;">**硬件初始化**</span>:
  - 在系统启动时，**操作系统会初始化硬件定时器，设定**<span style="color: #0f7b6c;">**时钟中断的频率**</span>。例如，设置定时器每10毫秒产生一次中断。
1. <span style="color: #0b6e99;">**中断向量表**</span>:
  - 中断向量表是包含各类中断入口地址的数据结构。时钟中断对应的ISR地址保存在这里，当中断发生时，CPU会跳转到该地址执行ISR。
1. <span style="color: #0b6e99;">**ISR的实现**</span>:
  - **时钟中断的ISR实现包括**<span style="color: #0f7b6c;">**更新系统时间**</span>**、**<span style="color: #0f7b6c;">**处理进程调度**</span>**、**<span style="color: #0f7b6c;">**执行定时任务**</span>**等**。ISR通常是<span style="color: #0b6e99;">**操作系统内核**</span>的一部分，需要高效快速执行，以减少中断处理时间对系统性能的影响。

【2024-30】假设某系统使用时间片轮转调度算法进行 CPU 调度，时间片大小为 5 ms，系统共有 10 个进程，初始时均处于就绪队列，执行结束前仅处于执行态或就绪态。若队尾的进程 P 所需 CPU 时间最短，时间为 25 ms。在不考虑系统开销的情况下，则进程 P 的周转时间为

A. 200 ms

B. 205 ms

C. 250 ms

D. 295 ms

<details><summary>答案</summary>

本题选C。

在时间片轮转 (Round Robin，RR) 调度算法中，进程轮流执行一个固定的时间片。如果一个进程在时间片结束时还没有完成，它将被放到就绪队列的末尾，等待下一轮调度。

根据题目条件，时间片大小为 5 ms，进程 P 所需 CPU 时间为 25 ms，需要 25 ms / 5 ms = 5 个时间片才能完成其执行，即需要 5 轮才能完成。

又因为系统共有 10 个进程，初始时均处于就绪队列，每轮每个进程占用一个时间片，每轮总时间 10 × 5 ms = 50 ms，因为进程 P 所需 CPU 时间最短，所以进程 P 第一个执行完毕，即在 P 执行完毕前，别的进程还有时间片待分配，又进程 P 位于队尾，所以每轮进程 P 最后一个执行，也就是 P 所在轮占用时间片结束时，这个轮次结束。根据之前的分析，该过程总共需要 5 轮，总计 5 × 50 ms = 250 ms。

进程P的完成时间为250ms，到达时时间为0ms，因此进程 P 的周转时间 = 完成时间 - 到达时间 = 250 ms - 0 ms = 250 ms。

</details>

### 优先级调度算法

随着计算机的发展，特别是实时操作系统的出现，越来越多的应用场景需要根据任务紧急程度来决定处理顺序。每个进程/作业都有各自的<span style="color: #0b6e99;">优先级</span>，调度时系统会选择<span style="color: #0b6e99;">优先级最高</span>的作业/进程。这种方法可用于作业、进程或I/O调度。

根据新的更高优先级进程能否抢占正在执行的进程，可将其分为两种:

- <span style="color: #0f7b6c;">**非抢占式优先级调度算法**</span>:只在进程主动释放处理机时进行调度。若在执行过程中有更高优先级的进程到来，只需将其加入到就绪队列的队头即可。
- <span style="color: #0f7b6c;">**抢占式优先级调度算法**</span>:在就绪队列发生变化时检查是否需要发起抢占。若有更高优先级进程进入，则立即暂停当前运行的进程，将处理机分配给新进程。
> 补充:就绪队列未必只有一个，可以按照不同优先级来组织。另外可以把优先级更高的进程排在就绪队列更靠近队头的位置。

根据进程创建后其优先级是否可以改变，可以将进程优先级分为以下两种:

- <span style="color: #6940a5;">**静态优先级**</span>:创建进程后确定，之后一直不变。其主要依据有进程类型、进程对资源的要求、用户要求等。
- <span style="color: #6940a5;">**动态优先级**</span>:创建进程后有一个初始值，之后会根据情况动态调整。调整优先级的主要依据有进程占用CPU时间的长短、就绪进程等待CPU时间的长短等。
**优点**:用优先级区分任务的紧急程度和重要程度，适用于实时操作系统；可灵活调整对各种作业/进程的偏好程度。

**缺点**:若源源不断地有高优先级进程到来，**则可能导致**<span style="color: #e03e3e;">**饥饿**</span>。

**如何合理地设置各类进程的优先级:**

- 响应时间原则:<span style="color: #0b6e99;">系统进程</span>优先级高于<span style="color: #0b6e99;">用户进程</span>（系统进程作为系统管理者理应拥有更高的优先级）。
- <span style="color: #0b6e99;">**交互型进程**</span>** > **<span style="color: #0b6e99;">**非交互型进程**</span>**（或前台进程 > 后台进程）**
- 系统资源利用率原则:<span style="color: #0b6e99;">**I/O繁忙型进程**</span>** > **<span style="color: #0b6e99;">**计算型进程**</span>**（CPU繁忙型进程）**
> I/O设备和CPU可以并行运行，并且。（I/O繁忙型进程只要执行很短的CPU时间就转去处理I/O，这时CPU就可以让其他进程上来处理，这样不仅提升了并行处理的时间，还可以让I/O设备尽快投入工作）此外，I/O繁忙型进程通常与用户交互密切相关，例如读取文件、处理网络请求等。提高这类进程的优先级可以使它们更快地响应用户请求，从而提高系统的响应速度和用户体验。

**如果采用动态优先级，什么时候进行调整:**

> 可以从追求公平、提升资源利用率等角度考虑:如果某进程在就绪队列中等待了很长时间，则可以适当<span style="color: #0f7b6c;">提升其优先级</span>；如果某进程占用处理机运行了很长时间，则可以适当<span style="color: #e03e3e;">降低其优先级</span>；如果发现一个进程频繁地进行I/O操作，则可适当<span style="color: #0f7b6c;">提升其优先级</span>。

【2016-46】（6分）某进程调度程序采用基于优先数 (priority) 的调度策略，即选择优先数最小的进程运行，进程创建时由用户指定一个nice作为静态优先数。为了动态调整优先数，引入运行时间cpuTime和等待时间waitTime，初值均为0。进程处于执行态时，cpuTime定时加1，且waitTime置0；进程处于就绪态时，cpuTime置0，waitTime定时加1。请回答下列问题。

1. 若调度程序只将nice的值作为进程的优先数，即priority=nice，则可能会出现饥饿现象，为什么？
1. 使用nice、cpuTime和waitTime设计一种动态优先数计算方法，以避免产生饥饿现象，并说明waitTime的作用。
<details><summary>答案</summary>

(1) nice为静态优先数，若采用nice作为进程优先数，对于就绪队列中某一个尚未运行的nice值较大的进程，若有比该进程nice值小的进程源源不断进入就绪队列，则该进程将一直无法运行，从而导致饥饿现象。

注:在操作系统中，nice 值并不是表示优先级，而是表示优先级的修正数值，它与优先级 (priority) 的关系是这样的:priority(new) = priority(old) + nice。内核中，priority 的范围是 0~139，值越低，优先级越高，其中前面的 0~99 范围是提供给实时任务使用的，而 nice 值是映射到 100~139，这个范围是提供给普通任务用的，因此 nice 值调整的是普通任务的优先级。

![](https://cdn.nlark.com/yuque/0/2025/png/42876865/1746541779774-c51741d4-d1f5-4344-bda9-f66dcc906308.png)

nice 值越小，优先数就越小，任务的优先级就越高。

(2) 为了避免产生饥饿现象，需要将静态优先数调整为动态优先数，引入运行时间cpuTime和等待时间waitTime，根据高响应比优先调度算法，响应比=(等待时间＋要求服务时间)/要求服务时间，waitTime视为等待时间，cpuTime视为要求服务时间。

- cpuTime越大，响应比越小，优先级越低，优先数越大，采用乘法权重，设权值为k1 > 0，可以增加k1 · cpuTime。
- waitTime越大，响应比越大，优先级越高，优先数越小，采用乘法权重，设权值为k2 > 0，可以减少k2 · waitTime。
综上所述，优先数 = nice + k1 · cpuTime - k2 · waitTime，其中k1表示cpuTime的权重，k2表示waitTime的权重，k1、k2均为大于0的常数。

waitTime的使用保证若waitTime越大，则优先数越小，从而避免出现饥饿现象。

</details>

### 多级队列调度算法

> 💡 前面所述的各种调度算法通常只设置一个就绪队列，即调度算法是固定且单一的，无法满足系统中不同用户对进程调度策略的不同要求。在多处理机中这种单一调度策略实现机制的缺点更加突出。

在进程容易分成不同组的情况下，可以有另一类调度算法。

例如，进程通常分为<span style="color: #0b6e99;">前台进程</span>(或交互进程) 和 <span style="color: #0b6e99;">后台进程</span>(或批处理进程)， 这两种类型的进程具有不同的响应时间要求，进而也有不同的调度需要。另外与后台进程相比，前台进程可能要有更高的优先级(外部定义)。

<span style="color: #e03e3e;">多级队列调度算法</span>将就绪队列分成多个单独队列(**在系统中设置多个就绪队列**，将不同类型或性质的进程**固定分配到不同的就绪队列)**，根据进程属性，如内存大小、进程优先级、进程类型等，**一个进程**<span style="color: #e03e3e;">**永久分配**</span>**到一个队列。每个队列有自己的调度算法。**

在<span style="color: #0f7b6c;">多处理机系统</span>中，可以很方便地为每一个处理机设置一个单独的就绪队列，每个处理机可实施各自不同的调度策略，这样就能根据用户需求将多个线程分配到一个或多个处理机上运行。

此外，**队列之间应有调度，通常采用**<span style="color: #6940a5;">**固定优先级抢占调度**</span>**，**例如前台队列可以比后台队列具有绝对的优先。

来看个实例，这里有五个队列，按优先级从高到低分别是系统进程、交互进程、交互编辑进程、批处理进程、学生进程，每个队列与更底层队列相比具有绝对的优先。例如只有系统进程、交互进程、交互编辑进程都为空时，批处理队列内的进程才可以运行。如果在一个批处理队列内的进程运行时来了一个交互进程进入就绪队列，那么该批处理进程就会被<span style="color: #d9730d;">抢占</span>。

另外一种可能是在队列之间<span style="color: #0b6e99;">划分时间片</span>。每个队列都有一定比例的CPU时间可用于调度队列内的进程。例如对于前台—后台队列的例子，前台队列可以有80%的CPU时间，用于在进程之间进行<span style="color: #0f7b6c;">RR调度</span>，而后台队列可以有20%的CPU时间，用于按<span style="color: #0f7b6c;">FCFS算法</span>来调度进程。

### 多级反馈队列调度算法

在使用上面所说的<span style="color: #0b6e99;">**多级队列调度算法**</span>时，进程在进入系统时被<span style="color: #e03e3e;">**永久地**</span>分配到某个队列，虽然调度开销低，但是不够灵活。相反，<span style="color: #6940a5;">**多级反馈队列调度**</span>算法<span style="color: #0f7b6c;">**允许进程在队列之间迁移**</span>。多级反馈队列调度算法（Multilevel Feedback Queue Scheduling）是一种<span style="color: #0b6e99;">**动态优先级**</span>的进程调度算法，它<span style="color: #d9730d;">**结合了优先级调度和时间片轮转调度**</span>的特点，以适应不同类型的进程需求。该算法将进程分为多个队列，每个队列具有不同的优先级和时间片大小。

![](https://cos.izumichan16.cn/408note/OS/TKE3DZHvgVA3Y5Vo/1748003637077-f0f87be8-82df-4474-ae76-49c9a8622482-934027.png)

<span style="color: #0b6e99;">以下是多级反馈队列调度算法的主要特点:</span>

- <span style="color: #6940a5;">**多级队列:**</span>进程被分配到不同优先级的队列中。通常情况下，新到达的进程被放入最高优先级的队列。每个队列具有不同的时间片大小，优先级越高的队列，时间片越短
- <span style="color: #6940a5;">**时间片轮转:**</span>在每个队列中，进程按照时间片轮转和FCFS的方式进行调度。这样可以确保每个进程都能获得一定的CPU时间，并且避免长时间占用CPU的进程导致其他进程无法运行
- <span style="color: #6940a5;">**反馈机制:**</span>如果一个进程在当前队列中运行的时间超过了时间片大小，那么它将被降级到下一个优先级的队列中。这样可以确保高优先级的进程能够尽快获得CPU资源，从而提高系统的响应速度。同时，如果一个进程在当前队列中完成了其任务而未用完时间片，它可以在下次调度时保持在当前队列
- <span style="color: #6940a5;">**一定程度上避免饥饿:**</span>通过多级队列和反馈机制，可以避免低优先级进程长时间得不到调度的问题。即使一个进程被降级到最低优先级的队列，它仍然有机会获得CPU资源，从而避免<span style="color: #e03e3e;">饥饿现象</span>的发生。此外，在较低优先级队列中等待时间过长的进程会被移到更高优先级队列，这种形式的<span style="color: #0f7b6c;">老化</span>阻止饥饿的发生（极端情况下仍有可能发生饥饿）
多级反馈队列调度算法的<span style="color: #0b6e99;">**优点**</span>在于它可以适应不同类型的进程需求，如<span style="color: #d9730d;">I/O密集型</span>和<span style="color: #d9730d;">CPU密集型</span>进程(例如可以将因I/O阻塞的进程重新放回原队列，这样I/O型进程就可以保持较高优先级）。它可以确保高优先级的进程能够快速响应，同时避免低优先级进程饥饿。

![](https://cos.izumichan16.cn/408note/OS/TKE3DZHvgVA3Y5Vo/1734100965045-35dfb32a-5661-4c14-89b2-798708031516-501351.png)

例如，考虑一个多级反馈队列的调度程序，它有3个队列，从0到2；调度程序首先执行队列0内的所有进程。只有当队列0为空时，它才能执行队列1内的进程。类似地，只有队列0和队列1都为空时，队列2里的进程才能被执行。另外到达队列0或队列1的进程会<span style="color: #e03e3e;">**抢占**</span>队列2的进程，**原来在队列2运行的进程放回队列2队尾**(被抢占处理机的进程重新放回原队列队尾)。

每个进程在进入就绪队列后都会被添加到队列0的队尾，队列0里的每个进程都有<span style="color: #0b6e99;">8ms的时间片</span>；如果一个进程不能在这8ms内完成，那么它会被移到队列1的队尾。如果队列0为空，队列1头部的进程会得到<span style="color: #0b6e99;">16ms的时间片</span>，如果它不能完成将会被抢占，并添加到队列2的队尾。只有当队列0和队列1都为空时，队列2里的进程才会按照<span style="color: #0f7b6c;">FCFS</span>和<span style="color: #0f7b6c;">时间片轮转</span>来运行。若队列2里的进程在时间片内没运行完继续插入到队列2队尾。

这种调度算法将给那些CPU执行时间不超过8ms的进程最高优先级。这类进程可以很快得到CPU，完成CPU执行，并且处理下个I/O执行。所需时间超过8ms但小与24ms的进程也会很快得到服务，但是他们的优先级会低一些。长进程会自动沉入队列2。

通常，<span style="color: #6940a5;">**多级反馈队列调度算法可由以下参数来定义:**</span>

- <span style="color: #0b6e99;">就绪队列数量</span>
- <span style="color: #0b6e99;">每个队列的调度算法</span>
- <span style="color: #0b6e99;">就绪队列的优先级</span>
- <span style="color: #0b6e99;">用以确定何时升级到更高优先级的方法</span>
- <span style="color: #0b6e99;">用以确定何时降级到更低优先级的方法</span>
- <span style="color: #0b6e99;">用于确定进程在需要服务时将会进入哪个队列的方法</span>(指多级反馈队列调度算法如何根据进程的特征和需求将其分配到合适的队列)

饥饿现象是指一个进程或任务由于得不到执行的机会而无法完成的情况。调度算法的设计应该避免饥饿现象的发生，确保公平地分配处理器时间给各个进程或任务。

A正确。时间片轮转调度算法是一种循环调度算法，在每个时间片内，每个进程或任务都有机会执行一段时间。因为时间片是有限的，所以没有一个进程会长时间占用处理器，从而避免饥饿现象的发生。

B错误。静态优先数调度算法根据每个进程或任务的静态优先级进行调度。属于优先级调度算法，饥饿现象可能发生在优先级较低的进程，只要有源源不断的优先级比该进程高的进程在其执行前到来，则该进程将一直被推迟，可能导致饥饿现象。

C错误。非抢占式短作业优先调度算法将优先执行估计运行时间短的作业。属于短作业优先调度算法。饥饿现象可能发生在运行时间较长的作业，只要有源源不断的运行时间比该作业短的作业在其执行前到来，则该作业将一直被推迟，可能导致饥饿现象。

D错误。抢占式短作业优先调度算法中，运行时间相对较短的作业可以抢占正在执行的剩余运行时间相对较长的作业。属于短作业优先调度算法。饥饿现象可能发生在运行时间较长的作业，只要有源源不断的运行时间比该作业短的作业在其执行前到来，则该作业将一直被推迟，可能导致饥饿现象。

</details>

【2017-23】假设4个作业到达系统的时刻和运行时间如下表所示。

系统在t=2时开始作业调度。若分别采用先来先服务和短作业优先调度算法，则选中的作业分别是（ ）。

A. J2、J3

B. J1、J4

C. J2、J4

D. J1、J3

<details><summary>答案</summary>

本题选D。

系统在t=2时开始作业调度，此时已经到达的作业有J1、J2和J3。

先来先服务调度算法优先选择到达时刻早的作业，J1、J2和J3中J1到达时刻最早。若采用先来先服务调度算法，则选中J1。

短作业优先调度算法优先选择运行时间短的作业，J1、J2和J3中J3的运行时间最短。若采用短作业优先调度算法，则选中J3。
