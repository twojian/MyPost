## 6.2 动态主机配置协议`DHCP`

### 6.2.1 `DHCP`**的作用**

常用于给主机动态地分配地分配 IP *地址*，*提供了即插即用的联网机制*，*允许一台计算机加入新的网络和获取* IP 地址而不用手工参与。

> 局域网内主机开机启动 DHCP ，然后 DHCP 服务器为局域网中各主机配置参数: IP 地址、子网掩码、默认网关的 IP 地址、 DNS 服务器的 IP 地址

### 6.2.2 `DHCP`**的工作过程**

1. `DHCP`报文的封装应用层中的`DHCP`客户端**报文**在运输层加上 UDP 首部（包括源端口号68和目的端口号67）被封装成  UDP  *用户数据报*，*然后在网际层加上* IP  首部被封装成  IP  数据报**，再根据所使用的网络接口，加上**帧头**封装成相应的数据链路层的**帧（例如以太网帧）进行发送。
1. **基本工作过程**

> 1. **DHCP 发现（Discover）报文**
>   - 源 IP 地址:0.0.0.0（主机尚未分配到 IP 地址，将 IP 设为全 0，本地网络上的所有主机都可以收到该报文）。
>   - 目的 IP 地址:255.255.255.255（主机并不知道网络中有哪几个 DHCP 服务器，也不知道它们的 IP 地址，因此使用广播）。
>
> 1. **报文内容与接收者**
>   - DHCP 报文段内封装有事务 ID 和 DHCP 客户端的 MAC 地址等信息。
>   - 只有在应用层**始终运行着 DHCP 服务器进程**的 DHCP 服务器才会接收该报文并作出响应；其他主机即使接收到也会丢弃。
>
> 1. **服务器处理发现报文**
>   - DHCP 服务器接收到发现报文后，会根据客户端的 MAC 地址查自己的数据库:
>     - 若有针对它的配置信息，则使用该信息配置 DHCP 提供报文。
>     - 若没有，则采用默认配置信息来构建提供报文。
>   - 注意:在 DHCP 服务器挑选待租用给主机的 IP 地址后，会使用 ARP 来确保所选 IP 未被网络中其他主机占用。
>
> 1. **DHCP 提供（OFFER）报文的发送与处理**
>   - 源 IP 地址:服务器自身 IP 地址。
>   - 目的 IP 地址:仍为广播地址（客户端尚无 IP）。
>   - 网络中所有设备都会收到该 IP 数据报；层层解封至 DHCP 提供报文后，**只有在应用层运行着 DHCP 客户进程**的主机会接收并处理；再根据报文的事务 ID 确认是否为自己请求的报文，若是则接收，否则丢弃。
>
> 1. **多条 OFFER 的选择**
>   - DHCP 客户在发出请求后可能会收到多条 DHCP 提供报文（OFFER），一般情况下会选择**先接收到的那个**。
>
> 1. **OFFER 报文常见配置信息**
>   - 包含:IP 地址、子网掩码、地址租期、默认网关、DNS 服务器的 IP 地址等。
>
> 1. **DHCP 请求（REQUEST）报文**
>   - 客户端收到 OFFER 后，向 DHCP 服务器发送 DHCP REQUEST:
>     - 封装该报文的 IP 数据报**源 IP 地址仍为 0.0.0.0**（客户端刚从多个 OFFER 中选定一个服务器，需先征得其同意，之后才能正式使用该 IP）。
>     - **目的 IP 地址仍为广播**，这样无需逐一告知网络中的每个 DHCP 服务器自己是否选择了它。
>   - 各 DHCP 服务器在收到该报文后，会根据事务 ID、DHCP 客户端的 MAC 地址、接收租约中的 IP 地址以及提供该租约的 DHCP 服务器的 IP 地址，判断自己是否被选中。
>
> 1. **DHCP ACK 与地址冲突检测**
>   - DHCP 服务器同意请求后，向客户端发送 DHCP 确认报文（DHCP ACK），**目的地址仍为广播地址**。
>   - 客户端收到确认报文后即可使用租用的 IP 地址。
>   - 注意:在使用该 IP 之前，主机仍会使用 ARP 检测该 IP 是否已被其他主机使用。若被占用，DHCP 客户端会向服务器发送 DHCP DECLINE（谢绝）报文来拒绝该租约，并重新发送 DHCP 发现报文。
>
> 1. **租约续约机制**
>   - 当 IP 地址的租约期过去**一半**时，DHCP 客户端发送请求报文用于续约。服务器收到该报文后，有三种可能:
>     - **同意续约**:发送 DHCP ACK 确认报文，客户端得到新的租期；
>     - **不同意续约**:发送 DHCP NACK 否认报文，客户端立即停止使用该 IP 并立即“寻找下家”（发送 DHCP 发现报文；真干脆）；
>     - **未作出响应（冷暴力）**:在租期过了 **87.5%** 后，客户端必须再次发送续约请求并等待响应；若仍无响应（搁这 PUA 呢），租期到期后客户端**立即停止使用**并寻找下家。
>
> 1. **提前终止租约**
>   - DHCP 客户端可以随时提前终止租约期:若不想用了，直接向 DHCP 服务器发送 DHCP RELEASE（释放）报文即可。
>   - 封装该报文的 IP 数据报**源 IP 为 0.0.0.0，目的 IP 地址为 255.255.255.255**
>
### 6.2.3 `DHCP`的中继代理

如下左图中由于广播报文不会被路由器转发，会被丢弃，所以不能获取配置参数。我们不愿意在每一个网络上都设置一个`DHCP`服务器，因为这样会使得`DHCP`服务器数量太多。因此现在一般是使每一个网络中至少有一个`DHCP`中继代理( relay agent ),它配置了`DHCP`服务器的IP地址，当中继代理收到主机以广播形式发送的`DHCP`发现报文后，就以单播形式向`DHCP`服务器转发此报文，并等待回答。

## 6.3 域名系统（`DNS`）

【作用】:将便于人们记忆的主机名转换为便于机器处理的  IP  地址

> 注意，域名 /IP/MAC  与主机都不具有一一映射的关系，1台主机可能对应着多个不同的域名 /IP/MAC 。

【**因特网的域名结构**】:

- 因特网采用层次树状结构的域名结构。
- 域名的结构由若干个分量组成，各分量之间用“点”隔开，分别代表不同级别的域名。
> … .三级域名.二级域名.顶级域名

> 例如 cqut.edu.cn  , cqu (三级域名)，  edu (*二级*)、 cn  (顶级域名) 、根（隐藏）
>
>
![](https://cos.izumichan16.cn/408note/CN/pZwFKsWKuPREJejV/1734101001339-c621f699-f3ad-45a2-b502-e6beba37aa8d-550027.png)

【**域名服务器**】:域名和`IP`地址的映射关系必须保存在域名服务器中，供所有其他应用查询。显然不能将所有信息都储存在一台域名服务器中。DNS使用**分布在各地的域名服务器**来实现域名到IP地址的转换。自上而下分别是**根域名服务器、顶级域名服务器、权限域名服务器**

**分类**:

1. **根域名服务器**
  - 根域名服务器是最高层次的域名服务器。
  - 管辖顶级域  cn/com/hk/uk/us/net  等，每个根域名服务器都知道所有的顶级域名服务器的域名及其IP地址。
  - **任何本地域名服务器对任何域名进行解析，只要自己无法解析，就请求根域名服务器**（若缓存中存有部分待解析的域名，则可以跳过根域名服务器。例如本地缓存存有 .com  ，在查询 www.baidu.com  时可以直接请求 .com  顶级域名服务器）
  - **根域名服务器通常并不直接对域名进行解析，而是返回该域名所属顶级域名的顶级域名服务器的 ** IP  地址。
1. **顶级域名服务器**:
  - 负责管理在该顶级域名服务器注册的所有二级域名
  - 当收到`DNS`查询请求时就给出相应的回答，可能是给出 IP *地址*，*也可能是指出下一级权限域名服务器的* IP 地址。
1. **权限域名服务器**:
  - 权限域名服务器负责管理某个区的域名。
  - **每一个主机的域名都必须在某个权限域名服务器处注册登记**。因此权限域名服务器知道其管辖的域名与`IP`地址的映射关系。
  - **另外，权限域名服务器还知道其下级域名服务器的地址。**
1. **本地域名服务器**
  - **本地域名服务器不属于上述的域名服务器的等级结构**
  - 当一个主机发出`DNS`请求报文时，**这个报文就首先被送往该主机的本地域名服务器。**
  - **本地域名服务器起着代理的作用，会将该报文转发到上述的域名服务器的等级结构中。**
  - 每一个因特网服务提供者ISP，一个大学，甚至一个大学里的学院，都可以拥有一个本地域名服务器，它有时也称为默认域名服务器。
  - 本地域名服务器离用户较近，一般不超过几个路由器的距离，也有可能就在同一个局域网中。**本地域名服务器的**`IP`**地址需要直接配置在需要域名解析的主机中。**
**因特网的域名解析过程**

> 为了提高DNS的查询效率，并减轻根域名服务器的负荷和减少因特网上的DNS查询报文数量，在各级域名服务器中广泛地使用了高速缓存。高速缓存用来存放最近查询过的域名以及从何处获得域名映射信息的记录(由于域名到IP地址的映射关系并不是永久不变，为保持高速缓存中的内容正确，域名服务器应为每项内容设置计时器并删除超过合理时间的项,例如，每个项目只存放两天)不但在本地域名服务器中需要高速缓存，在用户主机中也很需要。许多用户主机在启动时从本地域名服务器下载域名和IP地址的全部数据库，维护存放自己最近使用的域名的高速缓存，并且只在从缓存中找不到域名时才向域名服务器查询。同理，主机也需要保持高速缓存中内容的正确性。⭐️⭐️本地域名服务器完成域名解析时，最多的请求查询次数（迭代次数）为域名的段数（除去 www、dns  等） + 1（这是根域名服务器的一次查询）例如: www.baidu.com  最多两段+1 = 3次查询  dns.abc.com  最多两段+1 = 3次查询如图，代查询 www.abc.xyz.com

## 6.4 文件传输协议（`FTP`）

1. 文件传输协议（`File Transfer Protocol,FTP`）的**作用**:
- 提供**交互式**的访问，允许客户指明文件的类型与格式（如指明是否使用ASCII码），并**允许文件具有存取权限**（如访问文件的用户必须经过授权，并输入有效的口令）
- `FTP`屏蔽了各计算机系统的细节，因而适合于在异构网络中任意计算机之间传送文件。
1. FTP采用**客户/服务器**的工作方式，使用**TCP**可靠的传输服务。一个FTP服务器进程可同时为多个客户进程提供服务:
  - **主进程(单个)**:用于接收新的请求，对应着控制连接 `21port.`
  - **从属进程(多个)**:用于处理单个请求的数据连接。
1. FTP工作时使用两个并行的TCP连接
> 【注】:

> 1. 端口号20、21都是服务器端口号，客户端的端口号由客户端系统自行分配；
>
> 1. 由于`FTP`使用一个分离的”控制连接“， 所以也称FTP的控制信息是带外（`out-of-band`）传输的
>
```plain text
- 控制连接（端口号21）:用于传输控制信息（连接请求、传送请求等），不传输数据信息，由于在传输数据的时候也可以通过控制连接发生控制命令（例如终止传输），所以控制连接在整个会话期间一直保持打开状态。
- 数据连接:用来连接客户端与服务端的数据传送过程，完成文件传输。在每次文件传输时才建立，传输结束就关闭。数据传输有两种模式:
```

## 6.5 电子邮件

### 6.5.1 电子邮件系统的组成

电子邮件系统采用**客户/服务器**方式

- **用户代理**:用户与电子邮件系统的接口，即电子邮件客户端软件；
- **邮件服务器**:电子邮件系统的基础设施，用于发送和接收邮件，同时还要维护用户的邮箱。（同时充当 C  和 S ）
- **协议**:包括**邮件发送**协议（ SMTP 、 HTTP ）*和邮件接收*(*读取*)*协议*（ POP3 、 IMAP ）等
![](https://cos.izumichan16.cn/408note/CN/pZwFKsWKuPREJejV/1734101001324-d73c57da-4c67-4e16-b4d1-aa72b66e46ef-643917.png)

> 注意:

> 1.  SMTP *为*“ *推*” *服务*，*即由发送方将邮件*“ *推*” *给接收方*； POP3 为“拉”服务，即由接收方从发送方“拉”出邮件；
>
> 1. 以上所有连接都是基于 TCP ，*所有服务都是基于* C/S 
>
> 1.  SMTP 地址出错:不能发送邮件；  POP3 地址出错:不能接收邮件；  https  地址出错，既不能发也不能收；  mail 地址出错，发错人或者发不出（查无此人）
>
【电子邮件的收发过程】:

1. 发信人通过**用户代理**（即写信的界面例如QQ邮箱软件）来撰写邮件；
1. 用户代理通过 SMTP 发邮件发送给**发送方的邮件服务器**；
1. **发送方的邮件服务器**将邮件放入邮件缓存队列中等待发送；
1. **发送方的邮件服务器**发现缓存中有待发送的邮件，就向**接收方的邮件服务器**建立 TCP 连接；
1.  TCP *连接建立后*，*发送方的邮件服务器远程向接收方的邮件服务器发送邮件*，*当所有邮件发送完毕后断开* TCP 连接；
1. **接收方的邮件服务器**接收到邮件后，将邮件存入**收件人的用户邮箱**中等待收信人在方便的时候读取；
1. 收信人在打算收信时，通过用户代理使用 POP3 *或者* IMAP 将自己的邮件从**接收方的邮件服务器**中取回。

## 6.6 万维网（`WWW`）
