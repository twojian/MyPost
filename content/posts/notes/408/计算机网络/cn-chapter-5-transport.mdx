# 第五章 传输层

## 5.1 传输层的功能

传输层是面向通信部分的最高层，用户功能中最低层

- 端到端的通信，即提供了不同主机上的进程之间的逻辑通信。

> “逻辑通信”的意思是:从应用层来看，只要把应用层报文交给下面的运输层，运输层就可以把这报文传送到对方的运输层(哪怕双方相距很远，例如几千公里)，好像这种通信就是沿水平方向直接传送数据。但事实上这两个运输层之间并没有一条水平方向的物理连接。“逻辑通信”的意思是“好像是这样通信，但事实上并非真的这样通信”。网络层为主机之间提供逻辑通信。

- 复用和分用

> 注意：网络层也有复用和分用，复用指发送方不同协议的数据可以封装成IP数据报发送出去，分用是接收发在剥去首部后可以把数据交付给相应的协议。


>
>   SAP服务访问点是计算机网络中相邻层实体之间进行通信的逻辑接口**SAP服务访问点**:各层 SAP 的表示形式是对应层第一个单词的第-个字母加上“SAP”
>
>   - 物理层服务访问点 PSAP (Physical layer Service Access Point)：网络通信中设备的具体物理接口；
>   - 数据链路服层务访问点 DLSAP (Data Link Control layer Service Access Point）：物理接口的 MAC 地址；
>   - 网络层服务访问点 NSAP (Network layer Service Access Point)：各物理接口上配置的网络地址(如IP地址，但在OSI/RM 中网络地址不一定是 IP 地址，要视具体的网络层协议而定，如还可以是 IPX 地址）；
>   - 传输层服务访问点 TSAP (Transport layer Service Access Point）：具体网络应用进程通信所用的传输层端口；
>   - 会话层服务访问点 SLSAP (Session layer Service Access Point）：具体网络应用会话进程；
>   - 表示层服务访问点 PLSAP (Presentation layer Service Access Point）：具体网络应用进程中的用户标识。
>


> - 复用：在发送方不同的应用进程都可以使用同一个运输层协议传（TCP/UDP）送数据(当然需要加上适当的首部)
>   - 分用：指接收方的运输层在剥去报文的首部后能够把这些数据正确交付目的应用进程

- 流量控制
- 差错控制

## 5.2 UDP

- UDP的特点（和TCP对比）

| 传输层功能 | UDP | TCP |
| --- | --- | --- |
| 复用和分用 | √ | √ |
| 逻辑通信 | 不可靠无连接、支持一对一、一对多、多对一 | 可靠面向连接 |
| 发送长度 | 面向报文，应用层给多长的报文就发多长的报文，一次发送一个报文 | 面向字节流 |
| 校验和 | 可检测也可不检测，对伪首部+首部+数据进行校验、出错丢弃或向上层报告这是一个错误的报文段 | 必须检测，方法同UDP |
| 流量控制 | 无 | 有 |
| 拥塞控制 | 无 | 有 |
| 状态 | 无连接状态 | 需维护接收/发送缓存、拥塞控制参数和序号、确认号等参数 |

  - 源端口（2B）
  - 目的端口（2B）
  - 长度（2B）：首部+数据长度，单位字节。最小是8B
  - 检验和（2B）：

  - 校验和的校验范围：12B伪首部+8B首部+数据部分（+补充为偶数字节数的全0字节）
  - 发送方校验和计算步骤
    1. 每16bit（2B）为一个字进行16位求和
    2. 求和后最高位有进位，把进位的数在最低位再加上（回卷）
    3. 对求得的结果取反

  - 注意：全0校验和表示不进行UDP校验。伪首部和全0字节不发送。

## 5.3 TCP

- TCP的特点 $ 套接字socket =(IP地址:端口号) $ 每一条 TCP 连接唯一地被通信两端的两个端点(即两个套接字)所确定。即:$ TCP连接::= $ $\{socket1,socket2\}$ $=$ $\{(IP1:port1;),(IP2:port2)\}$
  ![](https://cos.izumichan16.cn/408note/CN/L0V7kgr2-aZA-oNL/1734100999514-61f6d130-6dd2-4fd7-8b34-88f5001c69be-601676.png)
- TCP报文段的首部格式（首部前20B固定，最长60B）
  ![](https://cos.izumichan16.cn/408note/CN/L0V7kgr2-aZA-oNL/1734100999483-260b8823-7c51-49ef-b147-1df5dc0d8d0f-938562.png)


> 1. 源端口/目的端口（各2B）
> 2. 序号（4B）：表示本报文段数据的第一个字节的序号，最大序号是$2^{32}-1$，下一个序号又回到0.
> 3. 确认号ack（4B）：当确认位ACK=1时，确认号才有意义。表示期待接收到的下一个报文段的第一个数据字节的序号。
>
>      > 若确认号为N，则表明：到序号N-1为止的所有数据都已正确收到。
> 4. 数据偏移（4bit）：与IP数据报偏移量不同，这里是指**数据部分第一个字节距离首部起始位置的距离，也即TCP报文首部的长度**。以4B为单位，占4bit，最大值15，所以首部最长60B。
> 5. 保留（6bit）：日后使用。
> 6. 6bit控制位
>
>      - 紧急位(**"插队位"**)URG：配合紧急指针使用，URG=1时紧急指针有效；
>      - 确认位ACK：**连接建立后始终为1**；
>      - 推送位PSH：置1表示不必等接收缓存满了再交付，而是尽快交付（很少使用）；
>      - 复位位RST：置1表示连接出现重大错误，需要重连。也可用来拒绝非法报文段；
>      - 同步位SYN：连接请求(**ACK=0**,SYN=1)，连接请求确认报文(ACK=1,SYN=1)；
>      - 终止位FIN：置1时表示发送数据完毕，要释放连接。
> 7. 窗口（2B）：接收窗口大小，以字节为单位
> 8. 检验和字段（2B）：伪首部和UDP几乎一样，17改为6，UDP长度改为TCP长度。计算步骤一致
> 9. 紧急指针（2B）：URG=1才有意义，表示**有多少字节的紧急数据**（紧急数据在报文数据部分最前面），即使窗口为0紧急数据也能发送
> 10. 选项：最大40B，比如MSS的长度选项：每一个TCP报文段中的**数据字段的最大长度**，不包括TCP首部。MSS和窗口值无关。
> 11. 填充：为了确保整个首部是4B的整数倍


> 正常情况下，TCP发送报文的长度规则：
>
>   ①缓存中存放的数据到达MSS字节时，就组装成一个TCP报文发送出去。
>
>   ②由应用进程指明要求发送报文段，即TCP支持的PUSH（推送）操作
>
>   ③发送方的一个计时器期限到了，即使没达到MSS也发送出去。
>
>   ④若接收窗口没有MSS大小，应等待接收窗口达到MSS一半或者MSS，两者任一时机再发送。
>
>   Nagle算法：对于一个TCP连接，第一个字节立马发送出去，然后继续缓存要发送的数据，收到上一个字节的确认再发送已缓存的数据。每轮等到上一个报文段的数据全部确认后再发送已缓存好的下一个报文段。

- TCP的连接/释放
  - TCP三次握手
    ![](https://cos.izumichan16.cn/408note/CN/L0V7kgr2-aZA-oNL/1734100999493-3fe110a2-4ce5-4ef3-8464-9411a87efcdf-858835.png)

    1. 客户进程A向服务器B发送一个连接请求报文段：SYN=1，seq=x，ACK=0。**SYN报文不能携带数据，并且要消耗一个序号**，客户进程进入SYN-SENT状态。
    2. 服务器B收到请求连接后，如同意建立连接，则向A发送确认：SYN=1，ACK=1，ack=x+1，seq=y。也消耗一个序号。服务器B进入SYN\_RCVD状态。
    3. 客户进程A收到B的确认后，还需要给B确认：ACK=1，ack=y+1，自己序号seq=x+1。第三次握手可以携带数据，携带数据则消耗序号，不携带则不消耗，在不携带情况下，下一个数据报文段的序号仍是seq=x+1。此时连接已建立，A进入ESTABLISHED状态
  - TCP四次挥手

> 最长报文段寿命MSL（Maximum Segment Lifetime）：报文段在网络中的最长生存时间，由操作系统决定，通常为几十秒至几分钟。
>
>     作用：
>
>     ① 确保最后一个确认报文段能到达B。若A直接进入CLOSED状态，确认丢失时B会重传FIN+ACK报文段，而A已关闭导致B无法释放。正确做法是等待2MSL，若收到重复FIN+ACK，则重发确认并重新计时。
>
>     ② 确保旧连接的报文段完全消失。若A收到FIN+ACK后立即释放并建立新连接，旧连接的延迟报文可能影响新连接。等待2MSL可确保旧报文段在网络中消失，避免干扰。

    ![](https://cos.izumichan16.cn/408note/CN/L0V7kgr2-aZA-oNL/1734100999541-a80a29dd-f5b4-4fb3-8f08-5093471af420-678606.png)

    1. 通信双方都可释放连接。假设客户进程A释放连接，A发出连接释放报文段并停止发送数据：FIN=1，seq=u。FIN报文段不携带数据但消耗一个序号。A进入FIN-WAIT-1状态。
    2. 服务器B收到连接释放报文段后发出确认：ack=u+1，seq=v，ACK=1。B进入CLOSE-WAIT状态，A收到此报文后进入FIN-WAIT-2状态。
    3. 服务器B传送完剩余数据后，发出连接释放报文段：FIN=1，ack=u+1，seq=w，ACK=1。B进入LAST-ACK状态。

> 若B没有数据要传送，第二、三次挥手可合并。从A发出FIN到双方进入CLOSED状态，A最短1RTT+2MSL，B最短1.5RTT

    4. 客户进程A对B的连接释放报文段进行确认：ACK=1，seq=u+1，ack=w+1，然后进入TIME-WAIT阶段，必须经过2MSL后，A才进入CLOSED状态。

- TCP可靠性的工作原理
  - 超时重传：每发送完一个分组时设置一个超时计时器。如果在超时之前收到了确认就撤销计时。否则就认为分组丢失了，因而要重传前面发送过的分组。
    - 发送方在发送完一个分组后，必须暂时保留自己已发送的副本（在发送超时重传时使用），收到相应的确认后清除暂时保留的副本。
    - 分组和确认都应该进行编号，这样才能收到确认的是哪个分组。若收到两个重复的分组，那么一定是发生了超时，丢弃较晚接收的分组**并回送确认**。

- TCP的流量控制：让发送方发送速率不要太快，接收发来得及接收，由滑动窗口实现。
  - 滑动窗口
    ![](https://cos.izumichan16.cn/408note/CN/L0V7kgr2-aZA-oNL/1734100999510-0ed12a63-3790-4e47-8cfe-ca6abda2303b-511759.png)

    - 发送缓存：应用层想要发送的数据。缓存空间有限并且循环使用，逻辑上是一个圆。其中包含两个部分：①发送方的应用程序传送给发送方TCP准备发送的数据。②TCP已发送出但未收到确认的数据。
    - 发送窗口：发送窗口里的序号表示允许发送的序号。包含：①已经发送了的但是还未收到确认的②允许发送但是还未发送的。
      - 发送窗口左端点在收到新的确认后往右移动，没收到确认则不动。
      - 发送窗口右端点通常是不断往右移动，因为收到了新的确认。但是也可能不动，因为接收发的接收窗口变小了，导致不动。但是TCP标准不赞成往左移动，因为窗口里的数据大部分已经发送出去，现在又要收缩窗口，不让发送这些数据，这样就会产生一些错误。
    - 接收缓存：即将交给应用层的数据。包含：①按序到达的、但尚未交付应用进程的数据②未按序到达的
    - 接收窗口：用来接收即将到达的数据，按序达到的数据，发送确认后接收窗口往右移动，但是不能超过接收缓存的范围。


> 发送窗口的序号集是发送缓存序号集的子集。
>
>     接收窗口的序号集是接收缓存序号集的子集。

- TCP的拥塞控制

>
>   研究前提：
>
>   ①数据是单方向传送，接收方只传送确认报文
>
>   ②接收发总是有足够大接收缓存，因而发送窗口大小由网络的拥塞程度（拥塞窗口）来决定。
>
>   拥塞窗口（cwnd）：取决于网络的拥塞程度，动态变化。所有的拥塞控制算法本质上都是控制每对TCP传输中发送方的cwnd。
>
>   实际的发送窗口=min\{rwnd，cwnd\}；rwnd为接收方的接收窗口。
>

  ![](https://cos.izumichan16.cn/408note/CN/L0V7kgr2-aZA-oNL/1734100999493-f419ec14-3284-4ec2-b0aa-663093d15222-220619.png)

![](https://cos.izumichan16.cn/408note/CN/L0V7kgr2-aZA-oNL/1734100999469-473113fb-c941-4916-a43d-31419ef2556e-447745.png)

- 慢开始算法：每收到1个报文段确认，拥塞窗口cwnd增加1。每经过1个RTT，cwnd翻倍（指数增长）。"慢"是指cwnd初始值为1，而非增长速率慢。

> 为防止cwnd过大引起网络拥塞，需设置慢开始门限ssthresh：
当cwnd \&lt; ssthresh时，使用慢开始算法。
当cwnd > ssthresh时，使用拥塞避免算法。
当cwnd = ssthresh时，两种算法均可。

- 超时：判断为网络拥塞，ssthresh = cwnd/2，cwnd = 1，进入慢开始阶段。
- 快恢复：快重传后不启动慢开始，而是ssthresh = cwnd/2，cwnd = ssthresh，直接执行拥塞避免算法。
- 流量控制和拥塞控制的区别

> 拥塞控制与流量控制关系密切，但存在差别。
>
> **拥塞控制**是防止过多数据注入网络，避免路由器或链路过载。是**全局性**过程，涉及**所有主机、路由器**及影响网络性能的因素。
>
> **流量控制**是点对点通信量控制，是**端到端**问题（接收端控制发送端），目的是抑制发送速率以便接收端处理。
