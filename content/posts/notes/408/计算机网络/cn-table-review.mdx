## 物理层

**表 2-1  频分复用、时分复用和码分复用的主要对比**

| **对比项** | **频分复用（FDM）** | **时分复用（TDM）** | **码分复用（CDM）** |
| --- | --- | --- | --- |
| **基本原理** | 将信道的总频带划分成多个互不重叠的子频带，每个子频带传输一路信号 | 将时间划分成一段段等长的时隙，每一路信号在其相应时隙内独占信道的全部资源进行通信 | 通过唯一一码片序列区分各路信号，各路信号共享同一频段和时间 |
| **信道使用方式** | 按频率 | 按时间 | 按码片序列 |
| **主要优点** | 无须同步，适合模拟信号传输 | 高效利用信道带宽；适合数字信号传输 | 抗干扰强；多路信号共享同一信道同时传输 |
| **主要缺点** | 存在频带浪费（每个子频带之间要有隔离频带）；易受频率干扰 | 需要严格的时间同步；存在时隙分配开销 | 需要使用扩频技术产生码片序列；编码/解码复杂度高 |
| **典型应用** | 广播电台，传统有线电视，模拟电话系统 | 光纤通信（如 SDH），数字电话（如 PCM） | 军事通信，3G 移动通信 |

## 网络层

**表 4-1 虚电路服务与数据报服务的对比**

| **对比方面** | **虚电路服务** | **数据报服务** |
| --- | --- | --- |
| 思路 | 可靠通信应当由网络自身来保证 | 可靠通信应当由用户主机来保证 |
| 连接 | 必须建立网络层连接 | 不需要建立网络层连接 |
| 目的地址 | 仅在连接建立阶段使用，之后每个分组使用短的虚电路号 | 每个分组都必须携带完整的目的地址 |
| 分组转发 | 属于同一条虚电路的分组均按同一路由进行转发 | 每个分组可走不同的路由 |
| 节点故障 | 所有通过出故障节点的虚电路均不能工作 | 出故障的节点可能会丢失分组，一些路由可能会发生变化 |
| 分组顺序 | 总是按发送顺序到达目的主机 | 到达目的主机时不一定按发送顺序 |
| 服务质量 | 可以将通信资源提前分配给每个虚电路，因此容易实现 | 很难实现 |

**表 4-4 定长子网划分与变长子网划分的对比**

| **对比方面** | **采用定长子网掩码 FLSM 进行定长子网划分** | **采用变长子网掩码 VLSM 进行变长子网划分** |
| --- | --- | --- |
| 子网掩码 | 划分出的所有子网使用同一个子网掩码（所有子网的网络前缀长度都相同，即“定长”） | 划分出的所有子网可以使用不同的子网掩码（前缀长度不同，即“变长”） |
| 子网数量 | 只能划分出 2 的幂次方（如 2, 4, 8, …）个子网，每个子网包含的地址数量相同 | 可以划分出非 2 的幂次方（如 3, 5, 6, …）个子网，因此每个子网包含的地址数量可能不同 |
| 灵活性 | 低（只适用于划分相同规模子网的场景） | 高（适用于划分不同规模子网的场景） |
| 地址利用率 | 可能较低（因为各子网规模相同） | 高效利用地址（接近按需分配） |

## 传输层

**表 5-1 UDP 和 TCP 的主要区别**

| **对比项** | **用户数据报协议 UDP** | **传输控制协议 TCP** |
|---|---|---|
| 连接方式 | 无连接（直接发送数据，无须事先建立连接） | 面向连接（发送数据前须通过三次握手建立 TCP 连接） |
| 单播、多播和广播 | 支持单播、多播和广播 | 仅支持单播 |
| 可靠性 | 不可靠（对丢失、错误、去重等传输差错不进行处理） | 可靠（有确认和重传机制） |
| 流量控制 | 无 | 通过滑动窗口机制实现 |
| 拥塞控制 | 无 | 四种拥塞控制算法（慢开始、拥塞避免、快速传输和快速恢复） |
| 首部长度 | 8 字节（源端口 + 目的端口 + 长度 + 校验和） | 20 字节固定首部（源端口 + 目的端口 + 序号 + 确认号 + 数据偏移 + 保留 + 6 个标志位 + 窗口 + 校验和 + 紧急指针）+ 最多 40 字节扩展首部 |
| 封装单位 | 面向应用层报文（将应用进程交付下来的报文整体封装） | 面向字节流（将应用层报文拆分或合并后以 TCP 报文段形式发送） |
| 适用场景 | 实时应用（视频会议、在线游戏、直播等） | 可靠性要求高的应用（网页浏览、文件传输、电子邮件等） |

**表 5-3 GBN、SR 和 TCP 实现可靠传输的主要区别**

| **对比项** | **TCP** | **回退 N 帧（GBN）** | **选择重传（SR）** |
|---|---|---|---|
| 体系结构的层 | 传输层 | 数据链路层 | 数据链路层 |
| 序号对象 | 给每个字节编号 | 给每个数据包（帧）编号 | 给每个数据包（帧）编号 |
| 窗口类型 | 动态窗口（受流量控制和拥塞控制调节） | 固定窗口 | 固定窗口 |
| 确认机制 | 累积确认 + 可选选择确认（SACK） | 累积确认 | 独立确认（针对每个数据包单独确认） |
| 重传触发方式 | 计时器超时 + 收到 3 个重复确认（快速重传） | 重传计时器超时 | 重传计时器超时 |
| 重传范围 | 超时的 TCP 数据报文段 | 超时的数据包及其后续未确认的数据包 | 超时的数据包 |
| 接收方缓存机制 | 接收方缓存序号落入接收窗口的、按序/未按序到达的字节数据 | 接收方仅缓存序号落入接收窗口且按序到达的数据包 | 接收方缓存序号落入接收窗口的、按序/未按序到达的数据包 |

**表 5-4 TCP 使用的四种计时器的主要区别**

| **名称** | **主要功能** | **启动条件** | **超时处理** | **超时值** |
| --- | --- | --- | --- | --- |
| 重传计时器 | 检测数据报文段丢失，确保可靠传输 | 发送数据报文段后启动 | 重传触发超时的报文段 | 动态计算，每次测得往返时间 RTT 后按公式计算一次 |
| 时间等待计时器 | 确保被动关闭方能收到最后确认报文段后进入 CLOSED 状态 | 主动关闭方收到对方的 FIN 报文段并发送确认后，进入 TIME-WAIT 状态并启动 | 进入 CLOSED 状态 | 2MSL（MSL 为 30 秒\~2 分钟） |
| 保活计时器 | 检测 TCP 连接存活状态 | TCP 长时间空闲（默认 2 小时） | 发送探测报文段，确认对方是否在线 | 默认 2 小时，可配置 |
| 持续计时器 | 避免零窗口报文段引起的死锁 | 收到对方的零窗口报文段 | 发送探测报文查询对方接收窗口大小 | 一般为 5\~60 秒（指数退避） |
