| **停止-等待协议 (SW)** | 数据链路层/传输层 | **确认 (ACK)**分组 | 告知发送方数据已正确接收，实现可靠传输 |
|  |  | **否认 (NAK)**分组 | 告知发送方数据未正确接收(使用超时重传后可省略) |
| **回退N帧协议 (GBN)** | 数据链路层/传输层 | **确认 (ACK)**分组 | 累积确认，指示按序到达的最后一个分组 |

| CSMA协议 | 数据链路层 |  |  |
| **协议类型** | **信道空闲时** | **信道忙时** | **适用场景****/特点** |
| **1-坚持CSMA** | 立即发送 | 继续监听，直到空闲后立即发送 | 低负载、低延迟需求 发送最积极，但冲突概率较高 |
| **非-坚持CSMA** | 立即发送 | 停止监听，等待随机时间后重新监听 | 高负载、高延迟需求 减少冲突，但信道利用率可能降低 |
| **p-坚持CSMA** | 以概率 p 发送；以概率 (1-p) 推迟一个时隙后重新监听 | 持续监听，直至信道空闲 | 动态负载、可平衡优化 通过概率机制平衡延迟和冲突 |
|  |  |  |  |
| CSMA/CD 协议 | 数据链路层 | （竖着看） |  |
| **核心机制** | **关键参数** | **帧长要求** | **冲突处理** |
| **载波监听**发送前监听总线是否空闲 | **争用期 **$2\tau$= 512 比特发送时间 = 51.2 μs (10Mbps) | **最小帧长**: 64B 首部 14B + 尾部 4B → 数据载荷最小 46B | **截断二进制指数退避 **退避时间 = $r$ $r \in \{0,1,...,2^k-1\}$ |
| **冲突检测**发送过程中持续检测碰撞 | **单程时延**$\tau$端到端传播时延 | **最大帧长**: 1518B MTU 1500B + 首部 + 尾部 | **重传次数 ****$k$** $k = \min(\text{重传次数}, 10)$ 重传 16 次后放弃 |
| **半双工通信**适用于总线型网络 | **参数 a **$\displaystyle a = \frac{\tau}{\text{帧发送时延}}$ a 越小信道利用率越高 | **无效帧判定**收到 \&lt; 64B 的帧 → 碰撞导致的无效帧 | **填充机制**数据不足 46B 时 用全零字节填充 |
| **检测到空闲后发送**但总线不一定真正空闲 | **争用期内无碰撞**→ 确保本次发送成功 | **前导码**: 8B 7B 前同步码 + 1B 帧开始符 帧间间隔: 96 比特 | **检测到冲突**→ 立即停止发送→执行退避算法 |

|  |  | **允许发送 (CTS)**帧 | 对 RTS 的响应，用于信道预约，携带通信持续时间 |
|  |  | **确认 (ACK)**帧 | 实现可靠传输的停止-等待确认机制 |

|  |  | CTS（2024 年-36） | $SIFS + T_{DATA} + SIFS + T_{ACK}$ |
|  |  | 数据帧 | $T_{DATA} + SIFS + T_{ACK}$ |
|  |  | ACK | 0（通信结束） |

| **IEEE 802.1Q (VLAN)** | 数据链路层 | **VLAN 标签 (tag)**字段 (如**VID**) | 划分虚拟局域网，限制广播域 |
| **地址解析协议 (ARP)** | 网络层 (或数据链路层) | **ARP 请求分组** | 广播发送，查询 IP 地址对应的 MAC 地址 |
|  |  | **ARP 响应分组** | 单播发送，返回 IP 地址与 MAC 地址的映射关系 |
| **IP (IPv4/IPv6)** | 网络层 | **IPv4/IPv6 首部字段**(如TTL/跳数限制) | 控制数据报在网络中的寿命，防止无限循环 |
| **网际控制报文协议 (ICMP)** | 网络层 (协议号 `1`) |  |  |
|  | **ICMP 差错报告报文** | **目的不可达**报文 | 报告路由器或主机无法交付 IP 数据报的差错 |
|  |  | **源点抑制**报文 | 报告网络拥塞，要求源点减慢发送速率 |
|  |  | **时间超过**报文 | 报告 TTL 减为 0 或数据报分片未在规定时间内收齐 |
|  |  | **参数改变**报文 | 路由器/主机收到 IP 数据报后，发现首部中有不正确的字段值，丢弃该报文，并发送 |
|  |  | **改变路由 (重定向)**报文 | 指示主机使用更优的下一跳路由器 |
|  | **ICMP 询问报文** | **回送请求和回答**报文 | 测试主机或路由器之间的连通性 (如 PING) |
|  |  | **时间戳请求和回答**报文 | 用于时钟同步和测量时间 |
|  |  |  |  |
| **网际组管理协议 (IGMP)** | 网络层 (协议号 `2`) | **成员报告报文** | 主机声明加入多播组 |
|  |  | **成员查询报文** | 多播路由器周期性探询组内成员是否活跃 |
|  |  | **离开组报文** | 主机声明离开多播组 |
|  |  |  |  |
| **开放最短路径优先 (OSPF)** | 网络层 (协议号 `89`) | **问候 (Hello)**分组 | 发现和维护邻居路由器的可达性 |
|  |  | **数据库描述 (DBD)**分组 | 向邻居路由器提供链路状态数据库的摘要信息 |
|  |  | **链路状态请求 (LSR)**分组 | 向邻居路由器请求某些链路状态项目的详细信息 |
|  |  | **链路状态更新 (LSU)**分组 (封装 LSA) | 洪泛发送链路状态信息(包含 LSA) |
|  |  | **链路状态确认 (LSAck)**分组 | 对链路状态更新分组的确认 |
| **路由信息协议 (RIP)** | 应用层 (基于 `UDP:520`) | **路由更新报文** | 周期性交换路由表(距离向量)信息 |
| **边界网关协议 (BGP-4)** | 应用层 (基于 `TCP:179`) | **打开 (OPEN)**报文 | 与相邻 BGP 发言人建立关系，通信初始化 |
|  |  | **保活 (KEEPALIVE)**报文 | 周期性证实邻站的连通性 |
|  |  | **更新 (UPDATE)**报文 | 通告新路由信息或撤销旧路由 |
|  |  | **通知 (NOTIFICATION)**报文 | 发送检测到的差错，用于终止连接 |
|  |  |  |  |
| **对比项目** | **RIP** | **OSPF** | **BGP** |
| **协议类别** | 内部网关协议(IGP) | 内部网关协议(IGP) | 外部网关协议(EGP) |
| **采用算法** | 距离向量算法 | 基于链路状态使用Dijkstra 最短路径优先算法 | 路径向量算法 |
| **度量标准** | 跳数(所经过路由器的数量,最大为 15) | 路径成本(基于带宽、时延等) | 路径属性(AS 路径长度、策略等) |
| **更新方式** | 周期性更新(每 30 秒更新一次) | 触发更新+周期性更新(每 30 分钟维护链路状态) | 增量更新(仅在路由表变化时,默认 60 秒保活) |
| **收敛速度** | 慢(容易出现路由环路) | 快速 | 较慢 |
| **路由环路** | 容易产生环路(通过触发更新、水平分割等控制) | 不会产生环路 | 不会产生环路 |
| **规模** | 小规模AS内部 | 中大型AS内部 | AS之间 |
| **划分区域** | 不支持 | 支持(分为OSPF 骨干区域和非骨干区域) | 不支持 |
| **是否支持无类别路由** | RIPv1 为有类路由(不支持子网掩码传递),RIPv2 为无类路由 | 原生支持无类路由(VLSM和CIDR) | 原生支持无类路由(VLSM和CIDR) |
| **认证机制** | RIPv1 无认证机制,RIPv2 支持明文/MD5 认证 | 支持明文/MD5 认证 | 支持 MD5 认证(TCP 会话认证) |
| **资源消耗** | 较低(仅维护 RIP 距离) | 中等(维护链路状态数据库LSDB) | 高(维护大量路由表项和策略) |
| **PDU 封装** | RIP 报文封装在传输层UDP用户数据报中,UDP 端口号为**520**;报文经 IP 数据报传输,IP 协议字段值为**17**;RIP 组播地址为**224.0.0.9**(RIPv2)或广播地址**255.255.255.255**(RIPv1) | OSPF 报文封装在网络层IP数据报中,IP 协议字段值为**89**;多播地址为**224.0.0.5**或**224.0.0.6** | BGP 报文封装在传输层TCP段中,TCP 端口号为**179**;IP 协议字段值为**6**;使用单播地址传输 |
| **典型应用场景** | 小型网络或历史悠久的简单系统 | 企业级网络、ISP 等复杂环境 | 因特网中 AS 互连 |

| **传输控制协议 (TCP)** | 传输层 (协议号 `6`) | **同步位 (SYN)** | 用于连接请求和连接请求确认 |
|  |  | **确认位 (ACK)**/**确认号 (ack)** | 用于确认和累积确认，可靠性保障 |
|  |  | **终止位 (FIN)** | 用于释放连接 |
|  |  | **复位位 (RST)** | 表示连接出现重大错误，需重连或拒绝非法报文 |
|  |  | **紧急位 (URG)**/**紧急指针** | 配合使用，用于发送紧急数据 |
|  |  | **窗口**字段 | 用于流量控制，指示接收窗口大小 |
| **用户数据报协议 (UDP)** | 传输层 (协议号 `17`) | **检验和**字段 | 可选用于检测数据报在传输过程中是否出现差错 |
|  |  |  |  |
| **动态主机配置协议 (DHCP)** | 应用层 (基于 `UDP:67/68`) | **DHCP 发现 (Discover)**报文 | 客户端广播寻找DHCP 服务器 |
| 颜色 | DHCP 客户 | **DHCP 提供 (OFFER)**报文 | 服务器提供 IP 地址租约提议 |
|  | DHCP 服务器 | **DHCP 请求 (REQUEST)**报文 | 客户端请求选定的 IP 地址租约 |
|  |  | **DHCP 确认 (ACK)**报文 | 服务器同意并确认租约配置 |
|  |  | **DHCP 否认 (NACK)**报文 | DHCP 服务器发送，表示不同意续约 |
|  |  | **DHCP 谢绝 (DECLINE)**报文 | 客户端拒绝租约(通常是发现 IP 冲突) |
|  |  | **DHCP 释放 (RELEASE)**报文 | 客户端提前终止租约 |
| **文件传输协议 (FTP)** | 应用层 (基于 `TCP:21/20`) | **控制信息**/**命令** | 通过控制连接(21 端口)传输，用于交互式访问和权限验证 |
| **简单邮件传输协议 (SMTP)** | 应用层 (基于 `TCP:25`) | **命令和响应报文** | 发送方将邮件"推"给接收方服务器 |
| **邮局协议 (POP3) / IMAP** | 应用层 (基于 `TCP:110`) | **命令和响应报文** | 收信人从邮件服务器"拉"回邮件 |
| **域名系统 (DNS)** | 应用层 (基于 `UDP:53`) | **DNS 查询/请求报文** | 客户端或服务器请求将域名转换为 IP 地址 |
| FTP 与 HTTP 补充 |  |  |  |
| **协议** | **传输层协议与端口** | **连接方式与特点** | **特殊机制** |
