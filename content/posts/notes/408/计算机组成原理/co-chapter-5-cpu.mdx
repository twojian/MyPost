## CPU 时序与控制方式整理

### 1. CPU 控制器的作用与输入

- 控制器产生操作控制信号，决定 CPU 内部单总线的使用。
- CPU 时钟是最基本的输入源，决定控制信号产生的时机与持续时间。

### 2. CPU 三级时序

三级时序用于对操作控制信号进行定时控制，包含：

1. 状态周期：完成一个基本操作的时间单元。
- 例：取指周期、计算周期、执行周期。
2. 节拍定位：状态周期划分出的若干操作阶段。
- 例：PC → MAR 的传送操作。
3. 节拍脉冲：节拍定位内的同步信号，用于触发具体微操作。

### 3. 举例说明

- 在指令周期中：
- 取指周期：取出指令。
- 计算周期：计算操作数有效地址。
- 执行周期：完成指令执行。
- 每个状态周期又进一步细分为若干节拍定位，每个节拍定位包含一个节拍脉冲。
- 比喻：
- 状态周期 = 乐章 / 一件要完成的事。
- 节拍定位 = 乐章中的小节 / 完成事情的几个步骤。
- 节拍脉冲 = 最基本的节拍 / 每个步骤的触发点。

### 4. 定长与变长指令周期

- 定长指令周期：所有指令的周期相同，简单但对大量简单指令会浪费时间。
- 变长指令周期：
- 各指令根据实际需要分配状态周期。
- 各状态周期根据需要分配节拍单位。
- 例：
- SW、BEQ 指令：包含 3 个状态周期。
- ADD、ADDI 指令：包含 2 个状态周期。
- 各状态周期内节拍数量也可能不同（如取指周期有 4 个节拍，执行周期可能只有 3 个）。
- 区分概念：
- 定长/变长指令系统：针对指令长度。
- 定长/变长指令周期：针对执行时间。

### 5. 传统多级时序控制方式

1\.  同步控制方式

- 以统一时钟为标准，各部件在固定时间间隔内完成操作。
- 优点：设计简单。
- 缺点：慢速部件会拖累整体效率。

2\. 异步控制方式

- 无统一 CPU 时钟，也没有固定的状态周期和节拍单位。
- 控制器发送操作信号后，需等待功能部件的应答信号才能进行下一步。
- 例：CPU 访问内存时，利用内存 ready 引脚作为读写周期结束的标志。
- 特点：
- 提高了系统速度（快速部件不再等待慢速部件）。
- 实现结构较复杂。

3\. 联合控制方式

- 综合同步与异步：
- 对大多数固定时间操作采用同步控制。
- 对少量时间难以确定的操作采用异步控制。

## 时序发生器

1. 三级时序的回顾
- 早期计算机采用状态周期、节拍电位和节拍脉冲三级时序，对操作控制信号进行定时控制。
- 本节课介绍产生这三级时序的硬件——时序发生器的工作原理和设计方法。
2. 时序发生器的组成
- 晶体振荡器作为脉冲源。
- 经时序整形与分频后得到节拍脉冲信号。
- 节拍脉冲信号作为输入，经过时序发生器，产生状态周期信号和节拍电位信号。
- 定长指令周期：状态周期信号和节拍电位信号仅与节拍脉冲相关。
- 变长指令周期：状态周期信号和节拍电位信号还可能与指令译码信号、反馈信息信号相关。

3. 控制信号
- 时序发生器还应具有启动、停止、复位等控制信号。
- 确保节拍电位从第一个节拍开始，到最后一个节拍结束，保证状态周期完整。
4. 时序发生器的实现方法
- 本质上是一个同步时序电路，可用摩尔型有限状态机（FSM）设计。
- 计数器是同步时序电路的典型例子。
5. 设计实例（定长指令周期的三级时序）
- 将取指、计算、执行三个周期，各自的四个节拍电位作为不同状态：
- S0：取指周期，节拍电位1有效
- S1：取指周期，节拍电位2有效
- S2：取指周期，节拍电位3有效
- S3：取指周期，节拍电位4有效
- S4：计算周期，节拍电位1有效
- S5：计算周期，节拍电位2有效
- S6：计算周期，节拍电位3有效
- S7：计算周期，节拍电位4有效
- S8：执行周期，节拍电位1有效
- S9：执行周期，节拍电位2有效
- S10：执行周期，节拍电位3有效
- S11：执行周期，节拍电位4有效
- 状态依次循环，由节拍脉冲下降沿触发。
- 输出信号（状态周期信号、节拍电位信号）只取决于当前状态。
6. 摩尔型FSM特点
- 状态转换由时钟沿触发（此处为节拍脉冲下降沿）。
- 输出信号仅依赖于现态，与输入无关。
7. 变长指令周期的设计（MIPS32例子）
- 在取指周期最后一个状态 S3：
- 如果是 LW/SW/BEQ 指令 → 转到 S4（计算周期开始）。
- 如果是 ADD/ADDI 指令 → 转到 S6（执行周期开始）。
- 说明在变长指令周期中，状态转换与指令译码信号相关。
8. 状态编码与状态转换表

- 
9个状态需4比特编码（16种组合，取12种）。

- 
将状态编号标记在转换图旁边。

- 
状态转换表：记录现态、输出信号、次态。

- 
从表中可看出：

- 状态寄存器保存现态。
- 组合逻辑电路输入=现态，输出=状态周期信号和节拍电位信号。
- FSM的输入：现态、反馈信息、指令译码信号。

9. 逻辑表达式设计
- 状态寄存器输出的比特依次为 b3 b2 b1 b0。
- 举例：执行周期信号 MEX 仅在 S6、S7、S8 有效 → 写出逻辑表达式。
- 节拍电位 T3 仅在 S2 和 S8 有效 → 写出逻辑表达式。
- 按此方法可写出所有输出信号逻辑表达式，设计组合逻辑电路。
10. 设计流程总结
1. 划分三级时序中的各状态周期和节拍电位 → 画出时序图。
2. 根据时序图构建摩尔型FSM。
3. 根据状态转换图写出状态转换表。
4. 根据状态转换表构建时序发生器。

11. 有限状态机在其他课程中的应用
- 出现在：数字逻辑设计、计算机组成原理、操作系统、计算机网络、编译原理。
- 网络课程中：PPP协议的状态转换图；TCP三次握手、四次挥手也是状态机过程。
- 408考研中也会考查（如2021年第38题）。

## 硬布线控制器（1）：概述

### 硬布线控制器的作用

- 硬布线控制器是控制器的一种，用于产生操作控制信号。
- CPU 内部的控制器通过产生操作控制信号，来控制数据通路中的相关部件执行相应操作。

### 区分不同信号

- 不要将 三级时序发生器产生的状态周期信号和节拍电位信号与控制器产生的操作控制信号混淆。
- 状态周期信号和节拍电位信号是硬布线控制器中组合逻辑单元的输入，用于产生指令执行所需的所有控制信号序列。

### 硬布线控制器的组成

- 三级时序发生器是硬布线控制器的组成部分。
- 硬布线控制器组合逻辑单元是控制器的核心：
- 输入：指令译码信号、反馈信息信号、状态周期信号、节拍电位信号。
- 输出：指令执行所需的所有控制信号序列。

### 组合逻辑单元的实现

- 可采用 组合逻辑电路、可编程逻辑阵列 PLA 或 ROM 实现。
- 每个控制信号 = 不同的指令译码信号、状态周期信号、节拍电位信号、反馈信息信号构成的逻辑与操作的和（典型积之和范式）。
- 状态周期信号和节拍电位信号限定了各操作控制信号的产生时间与持续时间。

### 硬布线控制器的特点

- 根据指令集中的各指令在不同状态周期、不同节拍电位、不同反馈条件，产生不同的操作控制信号。
- 通过时序发生器对操作控制信号进行定时控制：
- 确保信号的产生与维持时间。
- 协调各部件间的正确操作，从而实现指令功能。
- 硬布线控制器也称 组合逻辑控制器，由逻辑门电路和触发器构成。
- 内部结构复杂，但速度较快。
- 精简指令集处理器（RISC）广泛采用硬布线控制器。

## 硬布线控制器（2）：一般设计流程

### 设计步骤

1. 分析指令的数据通路
- 对指令集中每条指令执行时的数据通路进行分析。
- 得出执行操作流程和每一步操作所需的控制信号。
2. 操作控制信号定时
- 将每条指令的每个微操作划分到相应状态周期的具体节拍电位信号上。
- 对操作控制信号进行定时控制。
3. 构造时序发生器
- 按控制信号的同步控制方式（定长/变长指令周期），构造相应的时序发生器。
4. 写出逻辑表达式
- 分析每个控制信号在不同指令、不同状态周期、不同节拍电位下是否有效。
- 写出每个控制信号的逻辑表达式。
5. 实现逻辑表达式
- 使用逻辑门、PLA 或 ROM 实现每个控制信号的逻辑表达式功能。

### 逻辑表达式举例

- 控制信号 $x_{in}$：
- 所有指令在取指周期的节拍电位T1 → $M_{IF}$ ∧ T1（逻辑与）。
- LW、SW、BEQ 在计算周期的节拍电位T1 → $M_{CAL}$ ∧ T1。
- BEQ、ADDI、ADD 在执行周期的节拍电位T1 → $M_{EX}$ ∧ T1 ∧ (BEQ ∨ ADDI ∨ ADD)。

- 控制信号 z\_out：
- $Z_{out} = M_{IF} ∧T_3 + M_{EX}∧T_1(lw+sw)+M_{EX}∧T_3(beq+addi+add)$
- 控制信号 $PC_{in}$：
- $PC_{in} = M_{IF} ∧T_3+M_{EX}∧T_3∧beq∧PSW.ZF$
- 在执行周期（MEX）、节拍电位3（T3）、且 BEQ 指令满足条件时 → MEX ∧ T3 ∧ BEQ ∧ (PSW.ZF)。
- 其中 PSW.ZF 属于反馈信息信号。

### 总结

- 每个控制信号的逻辑表达式均符合积之和范式。
- 输入信号包括：指令译码信号、状态周期信号、节拍电位信号、反馈信息信号。
- 完成前四个步骤后，可进入第五步，用逻辑器件实现硬布线控制器组合逻辑单元。

## 现代时序硬布线控制器：总体说明

### 基本思路

- 现代时序硬布线控制器不再采用多级时序体制：对操作控制信号的定时直接采用基本时钟信号，不再使用由基本时钟信号派生的节拍脉冲信号、节拍电位信号、状态周期信号。
- 按需分配时钟周期：给指令集中的每一条指令的执行过程，按需分配相应数量的时钟周期，以提高程序执行效率。

### 与传统三级时序的对比

- 传统三级时序硬布线控制器包含的、用于产生状态周期信号和节拍电位信号的时序发生器相应组合逻辑电路不再需要。
- 将状态寄存器输出的现态直接作为硬布线控制器组合逻辑单元的输入，用于产生相应的操作控制信号。
- 由此得到现代时序硬布线控制器的组成框图；核心问题转为：如何设计有限状态机组合逻辑、如何设计硬布线控制器组合逻辑单元。

## 现代时序硬布线控制器的一般设计流程（对比说明）

### 步骤一（相同）

- 对指令集中每一条指令执行时的数据通路进行分析，得出每一条指令的执行操作流程和每一步操作所需的控制信号。

### 步骤二（不同）

- 将每一条指令的每一个微操作划分到具体的时钟周期，即对操作控制信号进行定时控制。
- 不同点源于：现代时序中状态周期信号、节拍电位信号已经不存在。

### 步骤三（不同）

- 以时钟周期为单位，画出指令执行的状态转换图，得出状态转换表，构造相应的有限状态机（FSM）。

### 步骤四（不同）

- 统计每一个控制信号产生的所有状态条件，进而写出每一个控制信号的逻辑表达式。

### 步骤五（相同）

- 采用逻辑门、可编程逻辑阵列 PLA 或 只读存储器 ROM来实现每一个控制信号的逻辑表达式的功能。

## 现代时序设计示例（基于 CPU 内部单总线 + MIPS32 五条典型指令）

### 前置与约定

- 继续沿用“基于 CPU 内部单总线的数据通路”和 MIPS32 中的五条典型指令（LW、SW、BEQ、ADDI、ADD）作为示例。

## 各条指令的状态与转换要点

### LW 指令

- 给出“每个时钟周期对应的状态”及“各状态下需要有效的控制信号”。
- 到达状态 S8 后，S8 为当前状态；在该状态的时钟周期结束（时钟下降沿）时，切换到次态 S0，此时 S0 成为现态。
- 由此画出 LW 的状态转换图。

### SW 指令

- 取指过程相同：对每条指令，S0～S3 相同，且各状态下的取指控制信号相同。
- 给出计算操作数有效地址及指令执行过程中，“每个时钟周期对应的状态”与“各状态下需要有效的控制信号”。
- 到达状态 S13 后，S13 为当前状态；在该状态的时钟周期结束（时钟下降沿）时，切换到次态 S0，此时 S0 成为现态。
- 由于取指的 S0～S3 通用，因此从S3开始补全 SW 的其他状态，画出状态转换图。

### BEQ 指令（含条件分支）

- 取指过程相同：S0～S3 与相应控制信号相同。
- 给出计算操作数有效地址及指令执行过程中，“每个时钟周期对应的状态”与“各状态下需要有效的控制信号”。
- 到达状态 S18 后，S18 为当前状态；在该状态的时钟周期结束（时钟下降沿）时，切换到次态 S0，S0 成为现态。
- 条件说明：对 BEQ 指令，上述“包含指令执行过程（执行跳转）”的状态转换还取决于程序状态字寄存器 PSW 的 ZF 标志位：
- PSW.ZF = 1：包含指令执行过程（执行跳转）。
- PSW.ZF = 0：不包含指令执行过程，从“计算有效地址”的最后一个状态 S15 直接切换到 S0（取指首状态）。
- 分别给出 PSW.ZF = 1 与 PSW.ZF = 0 两种情况下的状态转换图；从S3开始补全 BEQ 的其他状态。

### ADDI 指令

- 取指过程相同：S0～S3 与相应控制信号相同。
- 无“计算操作数有效地址”过程。
- 给出指令执行过程中“每个时钟周期对应的状态”与“各状态下需要有效的控制信号”。
- 到达状态 S21 后，S21 为当前状态；在该状态的时钟周期结束（时钟下降沿）时，切换到次态 S0，S0 成为现态。
- 从S3开始补全 ADDI 的其他状态，画出状态转换图。

### ADD 指令

- 取指过程相同：S0～S3 与相应控制信号相同。
- 无“计算操作数有效地址”过程。
- 给出指令执行过程中“每个时钟周期对应的状态”与“各状态下需要有效的控制信号”。
- 到达状态 S24 后，S24 为当前状态；在该状态的时钟周期结束（时钟下降沿）时，切换到次态 S0，S0 成为现态。
- 从S3开始补全 ADD 的其他状态，画出状态转换图。

### 完整 FSM

- 汇总 LW、SW、BEQ、ADDI、ADD 的状态转换，得到本例中完整的状态转换图（有限状态机的图形化表示）。

- 5 比特共有 2\^5 = 32 个组合（五个 0 \~ 五个 1）；
- 从中选取 25 个不同的组合，分别分配给 S0 ～ S24。

## 由状态表到电路实现

### 现态→次态逻辑

- 从状态转换表中得出现态与次态之间的逻辑关系，设计有限状态机组合逻辑电路。

### 现态→输出（操作控制信号）逻辑

- 根据状态转换表中每一个现态与其相应输出（操作控制信号）的关系，写出每一个操作控制信号与现态之间的逻辑表达式。
- 上述工作与之前“时序发生器”一课中的方法一致。

### 物理实现

- 采用逻辑门、可编程逻辑阵列（PLA）或只读存储器（ROM）来实现每一个控制信号的逻辑表达式，进而实现硬布线控制器组合逻辑单元与整个硬布线控制器。

## 特性与应用取舍

### 性能与复杂度

- 硬布线控制器执行速度较快，但其内部结构相对复杂，设计和修改较为困难，尤其难以适应复杂指令集处理器（CISC）的需求。

### 典型应用

- 精简指令集处理器（RISC）——例如 ARM——普遍采用硬布线控制器。

- 为追求更高的设计灵活性与可维护性，微程序控制器应运而生。

## 微程序控制器（总论与系列梳理）

### 引入与核心动机

- 硬布线控制器执行速度较快，但内部结构相对复杂，设计和修改较为困难，尤其难以适应复杂指令集处理器的需求；目前精简指令集处理器（例如 ARM）普遍采用硬布线控制器。
- 为追求更高的设计灵活性与可维护性，微程序控制器应运而生。本系列课系统介绍微程序控制器的基本概念、组成、下一个微地址的形成方法、微指令与微程序设计、操作控制字段表示法，以及水平型/垂直型微指令等内容。

## 微程序控制器的基本概念

### 核心思想

- 模仿程序设计方式：将每条指令执行所需要的相关控制信号按某种规则编码成微指令；使用这些微指令为每条指令编写微程序，以实现指令功能。
- 微程序由若干微指令构成；各指令的微程序全部存放在 CPU 内部的控制存储器（ROM）中（称为控制存储器）。
- 相较于硬布线控制器采用硬件时序对控制信号进行定时控制，微程序控制器采用软件时序对控制信号进行定时 控制，简化了复杂的控制逻辑，提高了设计的灵活性和可维护性。

### 例：以 MIPS32 的 LW 指令说明

- 按时钟周期列出操作与所需控制信号；将每一时钟周期的控制信号按规则编码为一条微指令；这些微指令组成 LW 的微程序。
- 控制存储器中按微地址存放各微程序。

### 微命令与微操作

- 
控制部件向执行部件发送的各种控制信号称为微命令；执行部件收到微命令后执行的操作称为微操作。

- 
例：$PC_{OUT}、IR_{IN}、MAR_{IN} $等为微命令；IR 收到 $IR_{IN}$ 即执行“把单总线数据写入 IR”的微操作。

- 
相容性微操作：可同时执行/同一机器周期内并行执行（如 $PC_{IN}$、$MAR_{IN}$、$IR_{IN}$ 等）；

互斥性微操作：同一机器周期内不可并行（如主存读$Mem_R$/写微命令$Mem_W$、单总线输出类微命令$XXX_{out}$、运算器控制微命令ADD、SUB、+4）。

- 
只有相容的微命令才能出现在同一条微指令中。

- 
现在时序取消“机器周期”概念，互斥/相容的时间粒度以一个时钟周期为单位。

### 微指令与微程序

- 在一个机器周期（现代时序下对应一个时钟周期）内，一组相容性微命令构成一条微指令；它们各自产生微操作控制信号，完成一条指令的部分功能。

- 微指令基本格式：由操作控制字段与顺序控制字段两部分组成。
- 操作控制字段：若干微命令位，置 1 表示产生相应微操作控制信号；
- 顺序控制字段：含判别测试字段与下址字段。
- 判别测试字段：指出需要测试的外部条件（是否依据指令译码进行分支、进位是否为零、运算结果是否为零、是否为当前微程序最后一条等）；
- 下址字段：存放下一条微指令的微地址；是否按此取下一条微指令取决于判别测试字段的测试结果（条件成立则修改微地址以分支）。

- 取指微程序通常设计为公共微程序：从控制存储器 0 号单元开始，系统上电自动执行；取出指令后依据指令译码（判别测试位 $P_0$）进行微程序分支，跳转到相应指令的微程序入口地址 。取指的最后一条微指令的 $P_0=1$，表示不检查其他状态条件，直接按译码分支跳转。

### 微指令周期

- 微指令周期（微周期）：从控制存储器取出并执行一条微指令所需时间。串行执行方式下可设计为与一个机器周期相同；在现代时序中，微指令周期=一个 CPU 时钟周期。一条指令的微程序包含多少条微指令，就安排相应数量的时钟周期。
- 区分指令周期与微指令周期。

### 408 真题要点

- 硬布线控制器直接用组合逻辑/状态机生成控制信号，无控制存储器访问时延，速度更快；微程序控制器需访问控制存储器，增加时延。
- 硬布线修改/扩展需改硬件，成本高；微程序通过修改微程序代码即可，灵活性高。

## 微程序控制器的组成

### 三大组成部分

- 控制存储器：存放各指令的微程序；字长=微指令字长；容量由全部微指令数量决定；每次读出一条微指令。
- 微地址寄存器$μAR$：提供读取微指令的微地址；上电初始化为 0，使取指微程序从 0 号单元开始执行；按时钟脉冲更新（三级时序：状态周期最后一个节拍结束触发；现代时序：当前时钟周期结束触发；若上升沿有效，则更新在下降沿触发）。

- 地址转移逻辑：依据指令译码、外部状态条件、判别测试字段、下址字段等产生下一个微地址输入到微地址寄存器$μAR$。

> - 为了方便描述问题，图中 给出的是微指令的格式， 而不是用于暂存从控制存储器中取出的微指令的微指令寄存器μlR。
> - μIR 是微程序控制器的组成部分，汇编程序员不可见。

---

- 
控制存储器通常用 ROM；在部分现代 CPU 中也可能用 RAM/EPROM/Flash 以支持微程序更新（如修复安全漏洞）。

- 
主存（RAM/ROM）与控制存储器用途区别：主存位于 CPU 外部存放指令/数据；控制存储器位于 CPU 内部存放微指令。

- 
汇编语言程序员可见的有：

- 
通用寄存器（组）：用于存储数据、地址、中间计算结果

- 
程序计数器PC：存放下一条待执行指令的地址

- 
堆栈指针SP：指向栈顶地址

- 
基址寄存器（如x86中的BX）：存放主存寻址基址

- 
状态寄存器（FLAGS/PSW）：存储运算状态（如进位/零标志等）

- 
汇编语言程序员不可见的有：

- 
指令寄存器IR：存放当前正在译码的机器指令

- 
存储器地址寄存器MAR：存放要访问的主存地址

- 
存储器数据寄存器MDR：存放从/向主存读取/写入的数据

- 
微地址寄存器μAR：存放当前微地址，以便从控制存储器指定微地址处读取微指令

- 
微程序寄存器μPC：存放下一条微指令的微地址，本节课框图中未给出，可看作包含在地址转移逻辑中

- 
微指令寄存器μIR：存放当前执行的微指令

## 下一个微地址的形成（地址转移逻辑）

### 两种方法

- 下址字段法（断定法）
- 微指令包含下址字段；当判别测试字段条件不满足时，直接按下址字段给出下一条微指令的微地址；否则按判别结果修改地址（微程序分支）。
- 各指令微程序的最后一条微指令的下址字段通常指向取指微程序入口地址，以便指令执行完毕后重新进入取指阶段。
- 计数器法
- 采用类似 PC 自动加一思想，微地址=当前微地址+1；微指令不含下址字段，缩短微指令、降低控制存储器容量需求。
- 为保证回到取指入口，在判别测试字段中增加微程序结束判别测试位 $P_{end}$。当 $P_{end}$=1 且无其他测试条件成立（如无中断），地址转移逻辑将取指入口地址（控制存储器 0 号单元）送入微地址寄存器μAR。
- 要求每条指令的微程序在控制存储器中连续存放（顺序访问）；下址字段法无此要求。

### 下址字段法的地址转移逻辑实现

- 组成：微程序入口查找组合逻辑、多路选择器、条件判别测试组合逻辑。
- 多路选择器输出的下一个微地址包括：某个微程序的入口地址、当前微程序内的分支地址、当前微指令的下址字段给出的地址。
- 判别条件来自微指令的判别测试字段与外部状态条件信号：
- P0=1：下一条微指令地址取微程序入口查找逻辑的输出（即新指令的微程序入口地址）；
- P1…Pk：检测被置 1 的相应外部状态条件反馈信号，条件满足则在当前微程序内按约定分支跳转；
- P0…Pk 全 0：下一条地址由下址字段给出（即顺序执行）。
- 判别测试→多路选择器控制信号的对应关系可列表并由组合逻辑实现。
- 各指令与其微程序入口地址为固定映射，可据此实现微程序入口查找组合逻辑。
- 若仅含 P0，多路选择器可简化为两路，选择端直接来自 P0。

---

### 计数器法的地址转移逻辑实现与扩展

- 默认下一条地址为微地址寄存器+1（顺序地址），送入多路选择器；
- 判别测试字段含微程序结束位 $P_{end}$ 以返回取指入口；
- 当指令数多、判别条件多时：
- 微程序入口查找逻辑与条件判别测试逻辑可用 ROM 实现：
- 把指令译码结果编码为 ROM 地址，直接读出微程序入口地址；
- 把条件测试结果编码为 ROM 地址，直接读出微程序内分支地址；
- 多路选择器仅需固定四个输入（顺序、入口、分支、特殊/保留等）。

## 微指令设计（格式与字段）

### 操作控制点与微命令位

- 以CPU 内部单总线为例，细分 IR→总线的输出为两条控制点：IR(IMM)→总线（I）与IR(BranchAddr)→总线（A）；合计22 个微操作控制点。
- 下址字段法的微指令格式：
- 操作控制字段包含22 个微命令位；
- 判别测试字段至少含 P0（指令译码测试位） 与 P1（外部状态条件测试位）；
- P0=1：下一条地址为微程序入口地址；
- P1=1：检测外部状态条件（本例为 PSW.ZF，用于 BEQ 执行周期的最后一步）；
- 判别测试字段为全 0 时，按下址字段顺序执行。
- 例：下址字段 5 位 ⇒ 可寻址 2⁵=32 条微指令。

### 计数器法的微指令格式

- 顺序控制字段不含下址字段，仅含判别测试字段；
- 需添加微程序结束判别测试位 $P_{end}$：$P_{end}$ = 1 且无其他条件满足时返回取指入口。

## 微程序设计（把 FSM 映射到控制存储器）

### 映射原则

- 控制信号持续时间为一个时钟周期，每个周期对应一个状态；周期结束（时钟下降沿）状态切换；控制信号只与当前状态相关。
- 状态转换图中的每个状态$S_x$ ↔ 一条微指令；状态编号值（本例 S0…S24，需 5 比特）可直接作为微指令在控制存储器CS中的地址（微地址）；每一个状态 S\_x 需要给出的为操作控制信号应该映射到相应微指令的操作控制字段中的微命令位。

### 
取指微指令 

- 取指微程序：S0～S3 四条微指令，最后一条的 P0=1（下址字段无效），进入“按译码分支”的取指后续流程。

### 各指令微程序（下址字段法）

- LW：有效地址计算 S4～S5，执行 S6～S8；最后一条下址字段跳回取指入口（S0）。

- SW：有效地址计算 S9～S10，执行 S11～S13；最后一条跳回S0。

- BEQ：有效地址计算 S14～S15；若 PSW.ZF=1，应将 P1（$P_{PSW.ZF}$）位对应的微程序内的分支目标地址送入到微地址寄存器μAR；若 PSW.ZF=0（下址字段有效），直接回 S0。其中 S15 的微指令需 P1=1 以测试 PSW.ZF；为 0 则按下址字段取公共取指第一条；为 1 则按 P1 对应的分支目标地址更新微地址。

- ADDI：仅执行 S19～S21；最后一条回 S0。

- ADD：仅执行 S22～S24；最后一条回 S0。

### 计数器法思路

- 使用无下址字段的微指令格式，并在判别测试字段中设置 Pn；各指令微程序末条 Pn=1 返回取指入口；给出 LW、BEQ 的微程序，其余（SW、ADDI、ADD）同理设计。

## 操作控制字段的三种表示法

### 直接表示法（位-微命令一一对应）

- 每个二进制位定义为一个微命令位；取值 1 ⇒ 产生该微操作控制信号，取值 0 ⇒ 不产生。
- 优点：简单、并行能力强、速度快。
- 缺点：微命令数量大（可至上百），微指令过长、控制存储器容量需求大。

### 编码表示法（字段译码法）

- 
将用于操作控制的微命令位编码为若干互斥字段；每字段内微命令互斥，通过译码器（如 3-8 译码器）只激活其中一个有效微操作；各字段输出经时间同步后控制数据通路。

- 
判别测试字段通常也可采用编码表示法（外部状态条件多为互斥）。

- 
必须预留一个译码输出状态表示“本微指令不使用该字段中的任何微命令”。

- 例题要点：
- 字段一/二均为 3 位经 3-8 译码 ⇒ 8 种输出，预留 1 种 ⇒ 7 种可表示微命令；
- 判别测试字段 4 位经 4-16 译码 ⇒ 16 种输出，其中 4 种用于外部条件、预留 1 种 ⇒ 余 11 种；

- 单条微指令最多同时激活的微命令数 = 采用编码的字段个数（每字段至多 1 个）（包括判别测试字段编码）；
- 下址字段 6 位 ⇒ 可寻址 2⁶=64 条微指令；若微指令总长 16 位 ⇒ 控制存储器容量为 64×16 位。
- 优点：微指令短、控制存储器小；缺点：译码与同步环节略降速度。

### 混合表示法

- 将直接表示法与编码表示法结合，在指令长度、并行性、执行速度、灵活性间综合权衡；适合现代处理器“热点并行直接、其余编码”的折中。

---

## 水平型与垂直型微指令

### 水平型微指令

- 一个微周期内可同时给出多个微命令。
- 当操作控制字段采用直接表示法 ⇒ 全水平型；采用编码表示法 ⇒ 编码水平型；采用混合表示法 ⇒ 混合水平型。
- 高并行性，但微指令结构较复杂、长度较长。

### 垂直型微指令

- 设计思想接近机器指令编码；一条垂直型微指令包含微操作码字段与微地址码字段。
- 结构简单规整、长度短，编写微程序相对容易；但通常仅控制 1～2 个微操作，并行性弱，微程序较长，效率低。
- 由于性能问题，垂直型微指令基本被淘汰；现代处理器多采用混合型（以水平型为主，局部垂直型优化），兼顾性能与灵活性。

- 对比维度：设计思想、编码方式、并行性、控制存储器空间、可读性与编程难度、典型应用（如 CISC、FPU、早期 GPU、DSP vs. MCU、RISC 异常处理、简单 I/O 控制器）。

## 微程序控制器：设计流程总结

### 步骤总览

1. 分析数据通路：对指令集中每条指令执行时的数据通路进行分析，得到执行操作流程与每步所需控制信号。
2. 操作定时：将每条指令的每个微操作划分到相应状态周期的具体节拍信号（传统）或具体时钟周期（现代）上，完成定时控制。
3. FSM 构建：以时钟周期为单位画出状态转换图，得到状态转换表，构造相应有限状态机FSM。
4. 微指令格式设计：选择水平型/垂直型；微命令编码方法选择直接表示法/编码表示法/混合表示法；明确判别测试字段（P0、P1、…、Pn）与下址字段（若采用）。
5. 编写微程序：依据 FSM，为指令集每条指令编写微程序；按 FSM 将全部微程序排列并存放到控制存储器。
6. 实现控制器：根据全部微程序在控制存储器中的组织，构建地址转移逻辑、微地址寄存器、控制存储器之间的通路，完成微程序控制器实现。

### 与硬布线控制器的对比（回顾）

- 执行速度：硬布线更快；微程序需访存。
- 设计复杂性：微程序器硬件更规整；复杂性转移到软件（微程序）。
- 可修改与扩充：微程序控制器通过更新微程序即可扩展（如 ROM/RAM/EPROM/Flash 方案）。
- 应用场景：硬布线适合 RISC/高性能固定流程；微程序适合复杂功能、可维护扩展的需求。

| **对比项目** | **CISC** | **RISC** |
| --- | --- | --- |
| 指令系统 | 复杂、庞大 | 简单、精简 |
| 指令数目 | 一般大于 200 条 | 一般少于 100 条 |
| 指令字长 | 不固定 | 固定 |
| 可访存指令 | 不加限制 | 只有 LOAD/STORE 指令 |
| 各种指令执行时间 | 相差较大 | 绝大多数在一个周期内完成 |
| 各种指令使用频度 | 相差很大 | 都比较常用 |
| 通用寄存器数量 | 较少 | 较多 |
| 目标代码 | 难以用优化编译生成高效的目标代码程序 | 采用优化的编译程序，生成代码较为高效 |
| 控制方式 | 绝大多数为微程序控制 | 绝大多数为组合逻辑控制 |
| 指令流水线 | 可以通过一定方式实现 | 必须实现 |

| 对比项目 | 硬布线控制器 | 微程序控制器 |
| --- | --- | --- |
| 设计思想 | 微操作控制信号直接由硬件逻辑电路（组合逻辑+时序逻辑）给出 | 微操作控制信号用微程序实现，微程序存放在控制存储器CS中。现代微程序控制器均采用可写的CS，以便修改、扩展指令功能，甚至修复处理器存在的出厂“bug”。 |
| 执行速度 | 快 | 慢（需要频繁访问控制存储器CS读取微指令） |
| 设计复杂性 | 高（尤其是指令集复杂时，电路设计非常复杂） | 较低（将复杂性转移到了编写微指令程序） |
| 可修改/扩充 | 困难 | 容易 |
| 应用场景 | RISC处理器（如ARM） | CISC处理器（如x86） |

专有名词与符号（不省略要点）

### 关键信号与位

- 微命令/微操作、PCOUT、IRIN、MARIN、PCIN 等；
- PSW.ZF（程序状态字寄存器零标志位，外部状态条件反馈信号）；
- 判别测试字段位：P0（指令译码测试位）、P1（外部状态测试位，例：PSW.ZF）、Pn（微程序结束判别测试位）。

### 微指令字段

- 操作控制字段、判别测试字段、下址字段；
- 直接表示法、编码表示法（字段译码法，3-8、4-16 等译码器）、混合表示法。

### 存储与部件

- 控制存储器（ROM/RAM/EPROM/Flash）、微地址寄存器、地址转移逻辑（微程序入口查找组合逻辑、条件判别测试组合逻辑、多路选择器）。

### 方法与流程

- 下址字段法（断定法）、计数器法（微地址+1）；
- 取指微程序（控制存储器 0 号单元起）、微指令周期=CPU 时钟周期（现代时序）；
- 状态编码：本例 S0～S24 需 5 比特（共 25 个状态）。

## 指令示例（FSM/微程序映射要点）

### 共有取指（S0～S3）

- 最后一条取指微指令 P0=1，按译码分支到对应指令微程序入口。

### 各指令（下址字段法）

- LW：S4～S5（有效地址计算），S6～S8（执行）；末条回 S0。
- SW：S9～S10（有效地址计算），S11～S13（执行）；末条回 S0。
- BEQ：S14～S15（有效地址计算）；若 PSW.ZF=1 ⇒ S16～S18（执行跳转）；否则直接回 S0；S15 的微指令 P1=1 以测试 ZF 并据此分支。
- ADDI：S19～S21（执行）；末条回 S0。
- ADD：S22～S24（执行）；末条回 S0。

### 计数器法提示

- 无下址字段；末条 Pn=1 返回取指入口；其余同理完成。

# 多处理器

## 5.6.1 计算机体系结构

### 一、单指令流单数据流（SISD）

- 特性
- 各指令只能并发，不能并行
- 每条指令处理一两个数据
- 不是数据级并行技术
- 硬件组成
- 一个处理器、一个主存储器
- 实现指令流水线需要多个功能性部件，采用多模块交叉存储器

### 二、单指令流多数据流（SIMD）

- 特性
- 各指令只能并发，不能并行
- 每条指令可以同时处理多个具有相同特征的数据，如for循环数组计算等
- 是数据级并行技术
- 硬件组成
- 一个控制部件（CU）
- 多个执行单元（如ALU）：不同执行单元同时执行一条指令，处理不同数据
- 多个局部存储器
- 一个主存储器

### 三、多指令流单数据流（MISD）

实际并不存在

### 四、多指令流多数据流（MIMD）

- 特性
- 指令可以并行
- 是线程级并行技术
- 进一步分类
- 多处理器系统
- 各处理器之间可以访问同一个主存
- 可以通过主存相互传递数据
- 多计算机系统
- 不能直接访问对方的主存
- 通过消息传递来共享数据

### 五、向量处理器

- 特性
- 是SIMD的变种
- 处理的数据为向量
- 擅长向量计算、大型浮点运算等
- 硬件组成
- 多个处理单元、多组向量寄存器
- 主存采用多端口同时读取的多模块交叉存储器
- 多个处理器、一个主存储器
- 需要大容量、集中式的主存储器

## 5.6.2 多核处理器

即共享内存多处理器（SMP）

- 所有核（处理器）共享一个主存
- 可以通过指令直接访问对方的地址空间

UMA和NUMA是两种多处理器系统中的内存访问架构:

UMA (Uniform Memory Access，统一内存访问):

- 多处理器访问统一内存
- 运算扩展性差
- 存在cache一致性问题

NUMA (Non-Uniform Memory Access，非统一内存访问):

- 优先给CPU分配最接近的内存
- 运算扩展性强

这两种架构是在共享内存多处理器(SMP)系统中采用的不同内存组织方式。

## 5.6.3 硬件多线程

- 处理器中存在多个IR、功能部件、寄存器组，则可以支持硬件多线程
- 线程切换时不用再花费开销保存和恢复现场

|  | 细粒度线程 | 粗粒度线程 | 同时多线程(SMT) |
| --- | --- | --- | --- |
| 指令发射 | 每个时钟周期轮流发射不同线程的指令 | 连续发射同一线程的指令 | 一个时钟周期内发送多条指令 |
| 线程切换频率 | 一个时钟周期切换一次 | 仅在流水线阻塞时切换 |  |
| 线程切换代价 | 低 | 高，需要重载流水线 |  |
| 并行性 | 指令级并行线程间不并行 | 指令级并行线程间不并行 | 指令级并行线程级并行 |

超线程就是SMT技术
