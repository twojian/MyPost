## 异常与中断的基本概念

在之前的课程中，我们学习了 CPU 内部控制器的功能，其中一项重要任务就是处理 CPU 内部异常和外部中断请求。从本节课开始，我们进入异常与中断的学习。本节课主要介绍它们的基本概念。

### 异常的分类

异常（又称内部中断）是由 CPU 内部引起的异常事件，可以分为三类：故障、自陷、终止。

### 故障

故障一般由指令执行过程中出现的问题导致，例如：

- 除数为零
- 整数溢出、浮点溢出
- 数据未对齐
- 缺页故障
- 段故障
- 未定义指令
- 越权指令
- 存储保护违例

故障又分为可恢复和不可恢复两类：

- 可恢复故障：例如缺页故障。发生时操作系统进行页面调度修复，然后从故障指令处继续执行（断点在当前指令）。
- 不可恢复故障：例如未定义指令、越权指令等，操作系统会终止当前进程。

### 自陷

自陷是程序员通过插入特定指令主动触发的异常，目的是实现用户态到内核态的安全切换，从而使操作系统执行特权操作，如系统调用和调试处理。

特点：

- 由自陷指令触发，无断点概念。
- 执行自陷指令时无条件或有条件调用内核程序，执行完毕后返回到自陷指令的下一条指令继续执行。
- 在单步调试模式下，CPU 的陷阱标志位（TF）被置位，每条普通指令执行完毕后都会触发一次调试自陷异常，交还控制权给调试器。

### 终止

终止是指 CPU 无法继续执行的硬件故障。这类异常随机发生，与具体指令无关。例如：

- 总线错误
- 机器校验错误
- 异常处理中再次出现异常的“双错”

其中，机器校验错误是 CPU 检测到与自身或相关硬件（内存、总线、控制器）发生的不可纠正的致命性错误时触发的最高优先级异常。例如 Windows 系统蓝屏就是由此类硬件故障引起的。出现这种情况时，程序只能终止，由异常处理程序重启系统。

### 外部中断的基本概念

外部中断是外部设备向 CPU 发出的请求，例如按键、鼠标单击等。其流程为：

- CPU 在一条指令结束后检查是否有中断请求。
- 如果有，则暂停当前程序，转去执行外设对应的中断服务程序。
- 处理完毕后返回断点，继续执行原程序。

外部中断由外部设备随机触发，与具体指令无关。

### 异常与中断的定义差异

不同体系结构对异常和中断的定义和分类有所不同，例如 x86、MIPS、ARM 架构都有各自的处理方式。对于未接触过相关嵌入式系统的同学，只需了解即可。

## 异常与中断的处理过程

在上一节课中，我们学习了异常与中断的基本概念。本节课主要介绍它们的处理过程。尽管不同计算机体系结构对异常和中断的定义存在差异，但处理方式基本一致。为了简化表述，除必要情况外，我们将异常与中断统称为中断。

### 中断响应周期

当中断事件发生时，CPU 会收到中断请求并进入中断响应周期：

- 正常情况：CPU 在当前指令执行结束后才进入中断响应周期。
- 特殊情况：若指令本身引发故障异常（如缺页异常），则必须立即进入中断响应周期。

CPU 在中断响应周期的主要任务包括：

1. 关中断
2. 保存断点
3. 中断识别

### 关中断

关中断是指暂时禁止新的中断请求进入。这样做的目的在于保护现场，保证中断服务程序能够完整执行并最终返回断点。

- 单级中断：仅在中断返回时重新开中断。
- 多级嵌套中断：完成现场保护后，可以通过指令开中断，允许更高优先级中断打断当前中断服务程序。

> 中断嵌套
> 
> 在支持中断优先级的系统中，当较低优先级中断服务程序执行过程中重新开启中断时，如果出现更高优先级中断请求，CPU 将：
> 
> 1. 暂停当前（低优先级）中断服务程序并保存上下文。
> 2. 立即响应并处理高优先级中断。
> 3. 高优先级中断处理完毕后，返回继续执行被暂停的低优先级中断服务程序。
> 4. 最终再返回主程序。

### 保存断点

保存断点的作用是确保中断服务结束后能够回到正确的程序位置继续执行。

- 对于已成功执行的指令，应保存 下一条指令地址（有可能不是顺序指令地址）。
- 对于执行失败的指令（如缺页故障、段错误），应保存 当前指令的 PC 值，以便在异常修复后重新执行该指令。

不同架构对断点保存的实现方式有所不同：

- x86 架构：硬件会自动将断点压入内存堆栈，利用栈的 LIFO 特性支持多级嵌套。
- MIPS 架构：硬件仅将断点保存到异常指令寄存器 EPC，需要软件在中断服务程序中将 EPC 内容保存到内存（如内核栈），否则新中断会覆盖 EPC，导致无法正确返回。

### 中断识别

中断识别是指 CPU 确定中断来源，识别具体发生的中断，并将相应中断服务程序入口地址送入程序计数器（PC）。至此，中断响应周期的任务完成。

需要注意：

- 中断响应周期内的操作由硬件实现，不可被打断。
- 响应结束后，CPU 从 PC 中取出中断服务程序的第一条指令并开始执行，直到中断返回。

### 硬件与软件协同

整个中断处理过程由 硬件和软件协同完成：

- 硬件负责：关中断、保存断点、中断识别等响应周期任务。
- 软件负责：执行中断服务程序并最终完成返回。

本节课介绍了中断处理的基本流程。下一节课将进一步学习中断处理相关的硬件机制，再下一节课则介绍中断服务程序的具体内容。

## 为 CPU 增加中断处理功能：数据通路改造

### 改造对象与简化说明

- 仍以基于 CPU 内部单总线的数据通路为例；为突出中断相关部件并便于画图，ALU、PSW、寄存器组等部件在示意图中隐去。

### 新增与改接部件

- 异常指令地址寄存器 EPC挂接到内部单总线：用于保存断点（可能是异常指令地址的 PC 值，也可能是下一条指令地址）；之所以挂接总线，是因为需要与 PC 进行保存断点/返回断点的数据交换；同样需要输入/输出控制信号（如其他挂总线寄存器）。
- 中断使能位寄存器 IE：
- IE=1 开中断、IE=0 关中断；
- STI 使 IE 置一，CLI 使 IE 清零。
- 中断控制逻辑：负责中断识别与优先级处理。本例假设 CPU 支持 4 个外部中断源 SA、SB、SC、SD：
- 任一/多个源中断时，产生中断请求信号，并输出优先级最高的中断号；
- 中断请求与 IE 共同接入与门：与门输出连到控制器的中断输入端，从而实现“开/关中断”的硬件门控（IE 置一相当于“打开与门”，中断请求可达控制器）。
- 中断入口选择多路选择器：选择四路固定地址（四个中断服务程序入口地址）；选择控制端接中断号。
- 说明：为便于理解而采用 MUX；实际实现常通过中断向量表访问存储器获取入口地址（I/O 系统章节详述）。

### 动作示例（SA 与 SD 同时中断）

- IE 已开中断后，SA、SD产生中断；中断控制逻辑输出“请求=1”与“中断号=SA”；与门放行，请求送达控制器；控制器据此启动中断响应：关中断、保存断点、转入相应中断服务程序。

## 硬布线控制器改造

### 三级时序硬布线控制器：在 FSM 中加入“中断响应周期”

- 基于“变长指令周期”的三级时序 FSM，加入包含两个节拍电位的中断响应周期：
- S9（中断响应周期·节拍1）：
- CLI 使 IE 清零（实现关中断，与门被“关闭”）；
- PCOUT→总线→EPCIN：将 PC 的内容写入 EPC（保存断点）。

- S10（中断响应周期·节拍2）：
- MUX(中断号) 选出“当前中断服务程序入口地址”；
- 入口地址→总线→PCIN：将入口地址写入 PC。

- 随后进入取指周期的第一个节拍，开始执行中断服务程序（此时 PC=所选中断服务程序入口）。
- 中断返回指令（eret, MIPS32）纳入 FSM：
- 该指令无操作数，没有计算周期，取指结束即入执行；
- 在执行周期的最后一个节拍（S8）完成：
- 清除当前中断请求信号（控制中断控制逻辑）；
- STI 使 IE 置一（开中断，与门“打开”）；
- EPC→总线→PCIN（返回断点——写回先前保存在 EPC 的 PC 值）。

- 由此得到支持中断的变长指令周期 FSM；据此继续写出状态转换表 → 构建时序发生器 → 构建支持中断的三级时序硬布线控制器（方法同此前课程，不再赘述）。
- 点评：传统三级时序时序划分固定，耗时较少的简单指令（例如中断返回）也被分配到3 个节拍电位（相当于 3 个时钟周期）。

### 现代时序硬布线控制器：在状态图中按需加入“中断状态”

- 以现代时序（按基本时钟、不再使用节拍脉冲/节拍电位/状态周期信号；按需分配时钟周期）的状态图为基底：
- 新增两个状态（各对应1 个时钟周期）：用于中断响应（关中断、保存断点、进入中断服务程序）。
- 新增一个状态（对应1 个时钟周期）：用于中断返回（返回断点、开中断）。

- 结论：现代时序可将中断返回这类耗时短的简单指令仅分配1 个时钟周期，效率优于固定三级时序。
- 同样需据此写出状态转换表 → 构建支持中断的现代时序硬布线控制器（方法同前述课程）。

## 微程序控制器改造

### 微指令格式的扩充与顺序控制修改

- 以计数器法微指令格式为例：
- 在操作控制字段中新增 6 个与中断相关的微命令位（对应上节课已使用的中断相关微操作控制信号：用于关中断、保存断点、装载中断入口地址、返回断点、开中断、清除当前中断请求等）。
- 无论下址字段法还是计数器法，都必须在顺序控制字段中新增微指令结束判别测试位 Pend：用于指明“当前微指令为所在微程序的最后一条”，并按中断测试条件分支。

### 新增微程序片段

- 
依据“支持中断的三级时序状态图”对应的动作：

- 新增两条“中断响应”微指令（实现：关中断、保存断点、进入中断服务程序）。
- 新增一条“中断返回”微指令（实现：返回断点、开中断，并清除当前中断请求）。

- 
之后为指令集重新编写各条指令的微程序（插入/衔接上述中断微程序），以实现完整功能。

### 地址转移逻辑的改造与工作方式

- 原理框图修改要点：
- 在地址转移逻辑中，给多路选择器新增一个“中断响应微程序入口地址”输入端，以取出存放在控制存储器中的‘中断响应微程序’（由两条微指令构成）；
- 控制存储器中还存放有中断返回指令 “RET” 的微程序（由一条微指令构成）。
- 多路选择器选择逻辑示意：
- 选择“下址字段给出的地址”：表示当前微程序最后一条微指令结束，且没有中断请求；
- 选择“中断响应微程序入口地址”：表示当前微程序最后一条微指令结束，存在中断请求，且无其他判别测试条件成立。
- 为配合新增输入端与选择条件，需对条件判别测试组合逻辑进行相应修改，最终实现支持中断的微程序控制器。

## 关键术语与信号（不省略）

### 部件与寄存器

- EPC（异常指令地址寄存器）、PC（程序计数器）、IE（中断使能位寄存器）、中断控制逻辑、（中断号）多路选择器。

### 控制/微命令与信号

- STI（开中断）、CLI（关中断）、PCOUT、EPCIN、PCIN、（清除当前中断请求的控制信号）、（中断入口地址输出相关控制）。
- 中断请求信号、中断号、与门（IE 与中断请求的门控）。
- ERET（中断返回指令，MIPS32）。

### 状态与时序

- 三级时序 FSM 中新增/使用状态：S9（关中断+保存断点）、S10（装载中断入口地址→PC），S8（执行周期最后一拍：ERET 的返回断点、开中断、清除当前中断请求）。
- 现代时序：新增两个“中断响应”状态、一个“中断返回”状态（均各占1 个时钟周期）。

## 中断服务程序的基本步骤

### 四个核心步骤

1. 保护现场
- 目的是确保被中断的程序在中断服务结束后能正确继续执行。
- 需要将中断服务程序中可能被改写的寄存器（如 PSW 寄存器、通用寄存器、以及多级嵌套中断时的 EPC 寄存器）压栈保存到内存堆栈。
- 注意：这里的"现场"与函数调用中的寄存器保存不同。函数调用由调用者保存，而中断服务程序没有调用者，因此必须由中断服务程序自身负责保存可能被破坏的寄存器。
2. 中断服务
- 针对具体中断源完成必要的操作。
- 例：网卡收到新数据帧的硬件中断 →
- 从网卡缓冲区快速提取数据帧；
- 执行循环冗余校验；
- 将数据帧转入内存安全区；
- 解析数据帧首部；
- 设置"待处理数据帧"标志位；
- 唤醒后台网络协议栈线程；
- 通知调度器有网络任务待处理。
- 遵循 二八原则：中断服务程序只做 20% 的必要工作，将 80% 的复杂工作交给后台完成。
- 原因：若在中断服务中处理过多工作，会导致新的中断不能及时响应，用户体验卡顿。
3. 恢复现场
- 按照与压栈相反的顺序，将寄存器出栈恢复。
- 确保恢复后被中断的程序能继续正确执行。
4. 中断返回
- 使用指令返回断点，继续原程序。
- 例：在 MIPS32 中使用 ERET 指令返回断点。
- 同时重新开中断（恢复 IE=1），允许新的中断被响应。

## 与中断响应周期的衔接

- 在进入中断服务程序前，经过 中断响应周期：
- 第一个节拍电位：关中断、保存断点；
- 第二个节拍电位：进入中断服务程序。
- 在中断服务程序最后，通过 中断返回指令完成：返回断点、开中断。

---

## 多级嵌套中断的补充

- 保护现场后应立即开中断，以允许更高优先级的中断继续打断当前服务程序。
- 恢复现场前应关中断，以保证现场恢复的完整性。
- 单级中断：若同时出现多个中断请求，按照 中断优先级顺序处理。
- 嵌套中断：遵循 优先级抢占原则，高优先级中断可以打断低优先级中断的服务程序。
